# 设置页开发规则

本文件约束 `src/features/settings/` 内的实现。通过前端根规则，它也适用于因设置页需求而修改的目录外业务组件，例如 `src/components/PersonalContext/SettingsPanel.tsx`。仅对本次新增或修改的代码应用规则，不顺带迁移无关旧代码。

## 组件和配置契约

- 新增或修改设置模块前，阅读 `components/SettingRow.tsx`、`components/SettingRow.css`、`components/SettingsSection.tsx`、`components/SettingsSection.css`，并查看一个交互形式相同的现有模块。以这些共享组件为设置页的视觉契约。
- 对设置页中的普通布尔、选择、文本配置，即使字段尚未注册，也须先接入相应的前端 Settings 契约，再按 `registry/types.ts` 的 `switch`、`select` 或 `input` 项定义，通过 `components/SettingItemRenderer.tsx` 渲染。普通设置通过字段契约、声明式设置项和中英文文案完成，不新增专用设置组件或重复实现读取、保存和状态管理；不要通过不注册字段或使用 `component: 'custom'` 来绕开。
- 缺少数据源适配或可复用联动能力时，补充 Settings 公共契约、数据源或服务层；缺少通用渲染能力时，扩展共享渲染器，不能因此改用 `custom`。持久化、校验和运行时副作用在渲染器之外处理；业务决策仍由对应业务模块负责，不在共享渲染器中按业务字段添加分支。接入声明式配置时须保留原有校验、保存、联动及运行时行为。
- `custom` 只用于声明式设置项无法表达的复杂业务数据或交互，与普通设置拆为独立设置项，需要时通过 `subItems` 组合。不得把可独立声明的普通设置包进 `custom`，也不得因包含复杂业务交互而将整个设置项改成 `custom`。
- 自定义渲染器中的普通“标题/说明/控件”行使用 `SettingRow` 的 `title`、`description`、`children`、`subSettings`，不要重造行结构，也不要把字号、间距、边框和响应式规则复制进模块样式。

## 页面布局和样式

- 页面标题、内容内边距及页面滚动由 `SettingsPageLayout` 负责。嵌入面板不要另加页面标题、页面级内边距、固定或全页高度、页面滚动容器；业务列表确有需要时可以拥有有界的内部滚动。
- 通过模块定义让 `SettingsSection` 负责分组。自定义组件已有自己的卡片或列表边界时，使用 `separatedRows: true`，避免重复外框；普通设置行不要再套装饰卡片。
- 复用现有共享控件与语义主题变量。不要为单个模块覆盖共享设置行的字体、尺寸或颜色。模型列表、授权面板等业务布局可以采用不同结构，但应保持设置页的字体、间距、对齐、颜色、边框、圆角和控件样式一致。只有其他调用方也需要同样变化时才修改共享组件。

## 完成前验证

- 新增或修改的用户可见文案及无障碍名称按前端根规则补全中英文语言资源。
- 在浏览器中与已有设置模块比较：检查标题与内容对齐、设置行字体、分组与边框、窄屏布局；受影响时检查展开/收起状态，涉及主题时检查明暗两种外观。说明未能验证的状态。
- 运行 `npm run build` 和 `git diff --check`；构建通过不能代替页面视觉验证。
