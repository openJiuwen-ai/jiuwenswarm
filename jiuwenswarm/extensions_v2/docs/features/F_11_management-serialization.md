## 1. 当前规则

| 操作 | 并发处理 |
| --- | --- |
| 初始化、卸载、停机 | 由 `ExtensionManager` 的 `asyncio.Lock` 串行执行。 |
| 启动加载、安装、重载 | 直接调用 Core。等待依赖时不持有门面锁，因此不会阻塞其它管理请求和停机。 |
| 查询 | 不占门面锁，也不会触发安装、重载或回滚。 |

Core 在报告中记录正在执行的包操作和等待的依赖。相同包的重复操作返回忙碌；不同包可以并行准备。
报告读写和安装目录提交使用进程锁，依赖等待与扩展代码执行不持有该锁。

退出通知在门面锁外发送，可以继续执行查询或新的管理请求。已开始的操作被取消时，报告会保留结果未知状态，
调用方需要先查询当前状态，再决定是否清理。

## 2. 验证

`tests/unit_tests/extensions_v2/management/test_management_serialization.py` 覆盖依赖等待期间的其它请求、取消、失败后的后续操作、通知重入、重复初始化和初始化取消。跨进程互斥与依赖测试由 Core 覆盖，整体结果见 F_32。
