# Flash Skill 检索模块

本模块只接入 Flash mode。第一轮保留原有系统规则与普通工具，额外附加技能检索说明；全量技能名称和描述改为按需提供。检索采用两轮模型流程：生成 query 和关键词，本地 BM25 返回最多 5 个候选，再由主模型判断候选并加载技能。只有候选返回后才精简工具列表；检索失败或候选不适用时恢复原生流程。

模型负责理解需求与选择技能，代码负责排序、权限过滤、候选票据和原生加载衔接。不自动选择第一名，不调用额外的重排模型，也不下载 Embedding 或 Cross-Encoder 权重。模型生成 query 仍可能出错，不能承诺任意输入都准确召回。

## 启用与卸载

在用户配置现有的 `flash` 节点下设置：

```yaml
flash:
  enabled: true
  skill_selection:
    enabled: true
    candidate_k: 5
    query_timeout_s: 10.0
    catalog_check_interval_s: 5.0
```

`flash.enabled` 控制工作对话是否进入 Flash；`skill_selection.enabled` 只控制检索模块，默认关闭。启用检索后采用两轮流程，无需设置轮数或预取开关。配置重载或重启后生效，代码更新需要重启服务。

一轮预取代码及 `prefetch`、`prefetch_timeout_s` 配置项已删除。旧用户配置中残留的这两个字段会被忽略，启动配置清理时移除，不会启用旧流程或关闭检索。原生流程的超时、繁忙、失败及候选不适用回退保持不变。

关闭时设置 `skill_selection.enabled: false`。完整卸载时，停止服务后删除本 `skill_selection` 目录并重启即可；Flash 宿主使用可选导入，模块缺失时保留原生技能流程。无需删除已安装技能或修改其他 Agent。历史工具结果仍是对话记录，不随开关删除。

配置模板 `resources/config.yaml` 必须保留相应字段声明，否则应用启动清理和配置合并会忽略未声明字段。示例见 `config.example.yaml`。

## 两轮流程

1. 候选返回前，保留原始用户消息、对话上下文、原有系统规则以及 Flash 当前可见的普通工具，额外提供 `search_installed_skills` 与检索说明。模型遵循原有规则判断任务；检索时生成 query，保留动作、对象、交付格式、平台及否定条件，配以少量中英文功能词。不使用原话截断、首尾截取或固定关键词表代替模型理解。
2. 检索工具在已安装且当前允许使用的技能中排序。query 建议 30–120 字，keywords 建议 3–8 个；这是提示建议，不会强行裁掉复杂需求。最多返回 5 个候选及当前请求的 `search_id`，此时尚未加载技能。
3. 拿到候选后，第二轮才把工具列表缩小为 `search_installed_skills`。模型对照原始要求判断候选，调用 `action="load"` 并传入 `search_id`、`skill_name`；候选不足或不适合时调用 `action="fallback"`，不反复改写 query。两轮规则提示和检索工具自身的 schema 保持稳定，但完整工具列表不同，缓存收益需实际测量。
4. 加载 Rail 校验票据、当前权限、配置、目录范围和源文件指纹，再将调用转换为原生 `skill_tool`。原有授权、凭证和活跃技能状态处理继续执行，权限中断交给 Agent 原有流程。
5. 加载成功后恢复执行工具，继续隐藏全量技能目录。加载只表示指令可用，任务是否完成仍取决于后续执行和交付结果。

检索模块为 Office 文档处理与交付补充技能优先指引：Excel 表格、Word 报告或会议纪要、办公文档转换等任务，优先检索并加载合适技能，再处理文件。任务简单、数据少或模型能自行编写脚本，都不作为跳过检索的理由，生成文件前的环境检查也遵循这一顺序。用户明确要求不用技能时遵从，本任务已加载适用技能时不重复检索。该引导通过系统提示和检索工具描述提供，第一轮普通工具仍保留，未增加关键词分类器或强制拦截；模型遵循情况需实际验证。

正常路径隐藏原生 `skills` 段落中的全量目录条目，并将“用 read_file 阅读 SKILL.md”等旧入口指引改为遵循检索补充说明。选择相关技能、加载后再执行的要求继续保留，其他系统段落及普通资料读取规则不变。用户明确指定技能可直接用 `skill_tool` 加载，PPT 可沿用加速器路径；其他首次技能选择走 `search → load`，不通过文件工具绕过技能加载入口读取 SKILL.md。

上述替换仅作用于本模块识别出的原生技能段落，不修改 SDK 或默认提示词源文件。目录边界由当前 SDK 模板识别；若无法可靠识别，直接回退原生流程，避免误删原有规则。关闭模块或回退时，恢复原生提示词、目录和工具。

PPT 任务保留原有 `skill_acceleration_exec` 加速器路径，无需先做本地技能检索；加速器的发现和调用方式不变。其支持范围不限制 `search_installed_skills` 检索本地技能库，两者保持独立。

普通工具结果返回后仍保留这些工具，也不注入全量技能目录。渐进式工具发现、禁用配置和原生权限策略继续生效，不强制暴露其他已注册工具。

全量技能列表入口在正常路径中隐藏；普通技能发现使用检索工具，PPT 加速器独立处理其支持的任务。用户在前端明确选择或文字精确指定技能时，沿用原生加载路径，不强迫经过两轮排序；指定项被禁用、不存在或名称不唯一时不能自动换选。加载后可继续通过原生 `skill_tool` 读取嵌套指令。

只有候选判断阶段缩小发给模型的普通工具列表，不删除已注册工具，也不修改其他 Rail。每次模型调用结束或异常时恢复原始工具列表。执行阶段的工具策略、上下文与模型思考设置保持原有配置。

## Token 与耗时优化

| 优化 | 作用与边界 |
| --- | --- |
| 仅候选判断阶段发送一个检索工具 | 第一轮保留普通工具直达能力；候选返回后缩小工具列表，加载或回退后恢复 |
| 保持规则提示和检索 schema 稳定 | query、候选和随机票据放在普通工具消息中；完整工具列表会变化，不保证两轮复用相同缓存前缀 |
| 压缩候选返回值 | 描述通常保留前 640 字符，额外保留后文识别到的限制条款，并标注截断；静态能力资料中的支持、禁止、输出格式按操作分组，无损去重 |
| 不回传排序分数和重复 query | 排名分数留在诊断日志；候选资料仍供模型判断，不被当作可执行指令或能力认证 |
| 复用目录与索引 | 首次工具检索不重复扫描 SDK 已加载的原生目录；已验证快照供查询使用，过期检查合并到后台 |
| BM25 倒排索引 | 只遍历包含查询词的记录，预计算长度归一化项；排序公式及权重不变 |
| 有界等待与直接回退 | 工具检索的整体等待受 `query_timeout_s` 限制，后台建索引有独立预算；避免把启动预算全部变成用户等待 |
| 容忍无害的历史参数 | load 多填 query、keywords 时剔除这些字段，避免无意义的重试；票据、技能名和权限检查仍严格执行 |

描述压缩无法保证保留任意措辞的全部语义。支持、禁止和输出格式资料来自静态文本解析，不能替代执行验证；模型发现资料不充分时应回退。没有缩减候选数量，也没有强行关闭模型思考或限制输出 token 来换取速度。

这些优化减少可避免的上下文和本地等待，不能保证两次远程模型调用比一次默认调用更快。实际费用还取决于缓存命中与输出 token。基准必须区分本地检索耗时、两轮模型耗时和完整任务耗时。

## 回退与目录变更

空候选、超时、队列繁忙或异常时，检索工具直接标记回退，下一轮恢复原生目录和全部原生工具。若第二轮模型主动拒绝候选，随后需要第三轮在原生目录中选择；该成本会如实计入统计。

索引按目录和配置共享；票据与查询结果只在当前请求内复用。默认检查间隔为 5 秒：收到查询且快照过期时发起后台检查，没有请求时不持续扫描。新增技能在后台发布新快照后可见；更新期间可能暂时返回旧描述，加载前后会重新检查所选技能。权限撤销立即按原生当前范围过滤，不等待索引刷新。

强制刷新和已知刷新错误不会静默返回旧快照。新索引版本需要同步原生目录时才重新加载；只改启用、禁用集合无需再扫描所有文件。关闭模块后不发起新检索，已创建的有界线程池随进程退出释放。

默认使用 2 个查询线程、1 个索引线程，队列上限分别为 16、8。参数见 `config.py` 和 `execution.py`。原生 SkillUseRail 的初始化开销仍然存在，冷启动耗时不能算作每次 BM25 查询耗时。

## 接入和模块职责

宿主唯一接入点是 `server/runtime/agent_adapter/interface_flash.py` 中的可选 `build_rail()` 导入。配置模板声明默认关闭的模块参数。普通 Agent、Code、Team 的适配器及 SDK 无需修改，检索扩展自身也不依赖另一个模式的检索实现。

| 文件 | 职责 |
| --- | --- |
| `__init__.py`、`config.py` | 可选入口及配置校验 |
| `rail.py`、`tool.py`、`loading.py` | 模型工具视图、检索调用、请求生命周期及原生加载 |
| `prompt.py` | 隐藏全量目录，将旧技能加载入口指引适配到检索流程 |
| `presentation.py` | 模型侧候选压缩，完整票据留在服务端 |
| `catalog.py`、`cards.py`、`capability_metadata.py` | 建立检索文本与静态能力资料 |
| `bm25.py`、`pipeline.py`、`types.py` | 本地排序和可替换的检索接口 |
| `service.py`、`sources.py`、`freshness.py` | 共享快照、后台刷新和文件指纹 |
| `execution.py`、`request_state.py` | 有界工作线程、取消及请求内状态 |
| `query.py`、`explicit.py` | 消息封装解析、显式点名；素材边界过滤仅用于识别点名，不生成检索 query |
| `diagnostics.py`、`metrics.py`、`benchmark.py` | 运行统计和离线基准 |

## 验证与统计

回归测试位于 `tests/unit_tests/agentserver/test_flash_skill_selection.py`，覆盖真实 SDK 发给模型的请求：通用系统规则与完整用户文本保留、300 个技能目录条目不进入正常提示、普通工具直达及后续调用、候选返回后才精简工具、回退恢复目录和执行工具，以及普通工具和技能加载的权限中断、票据隔离、文件变更、配置开关和模块卸载。另验证中英文及空目录提示中的旧加载入口替换、显式指定技能仍可直接加载、异常恢复，以及无法识别提示模板时的原生回退。BM25 倒排实现与原公式做逐分数比较。测试采用离线模型替身，不代表线上召回准确率或响应耗时。

诊断版本为 `bm25-main-llm-v6`，新增 Office 技能优先指引，保留 PPT 加速器及用户指定技能直接加载的路径。两轮检索标记为 `flow: two_round`、`query_source: model_tool_argument`，不再输出 `prefetch` 字段。`event=search` 表示完成检索，`event=choice` 且 `loaded=true` 表示通过原生流程加载成功。

`request_progress` 记录每轮的 `call_stage`、`call_ms`、`call_usage`。`route` 表示候选返回前的自由选择阶段，可能直接回答、调用普通工具或生成检索 query；`select` 表示候选判断，`execute` 表示技能加载后的执行。`model_view` 记录 route、select 阶段实际发送的工具数量与 schema 字符数；`search` 记录候选字符数和目录检查耗时。诊断默认不复制用户原文。

`selection_stage` 在首次成功加载技能时汇总选技能阶段，`request_summary` 汇总整个调用。`input_tokens` 已含 `cache_tokens`，不可重复相加；`uncached_input_tokens` 为二者之差。取消或缺失用量时标记 `usage_complete: false`，不把缺失量当成零。`first_load_ms` 从首次进入检索模块的模型前置回调算起，不包含此前 SDK Rail 的工作。

若请求先调用普通工具、之后才检索技能，首次加载的累计指标也包含前面的普通工具流程；分析纯检索成本时需结合逐轮日志。只使用普通工具的请求不会产生 `selection_stage`。第一轮工具列表已恢复，旧版本两轮输入 Token 和耗时不能直接作为本版本基准。

离线基准：

```powershell
python -m jiuwenswarm.agents.harness.flash.skill_selection.benchmark --skills-dir '你的技能目录'
```

它使用固定的示例 query 和关键词，只读取本地技能，不调用模型或执行技能，报告热检索耗时与候选字符数。千条记录实验使用填充记录，仅测试排序耗时，不证明千技能召回率。线上对照应采用相同模型与任务，记录缓存命中，分别报告两轮选择阶段和完整任务的中位数、较慢样本、token 和成功率；回退、冷启动和中断单独统计。
