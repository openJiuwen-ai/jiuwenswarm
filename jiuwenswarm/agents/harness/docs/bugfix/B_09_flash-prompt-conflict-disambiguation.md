# Flash 提示词冲突段消歧

| 项 | 值 |
| --- | --- |
| 类型 | bugfix |
| 日期 | 2026-11-25 |
| 关联规约 | [S_05 agent skill rails](../../../../server/runtime/skill/docs/specs/S_05_agent-skill-rails.md) |

Flash 系统提示词中 5 处规则互相打架，模型会按任意一条执行：

1. 「整理」边界：总则「内部操作（读文件、搜索、**整理**）可放心执行」 vs 删除规范「不得把删除曲解为**整理/归档**」。删除规范末句限定「整理/归档」仅指移动用户文件，内部数据目录整理归内部操作。
2. 「复述」边界：思考纪律「**严禁**复述上下文」 vs 最终可见回复「最终轮仍须**完整复述**」。在最终可见回复的轮次纪律里声明两者作用域不同（前者只约束 reasoning_content），措辞按段标题指代、不引用段号。
3. 语言来源：输入消息约定里 `preferred_response_language` 的「用户期望的回复语言」说明与「按当前运行时语言回复，唯一来源」冲突。删掉该字段说明，JSON 示例字段保留。
4. todo 状态更新节奏：「状态变化时立即更新，不积攒」 vs 「可在连续推进多个任务后用一次批量更新」。删掉技能执行规范里的批量更新句。
5. todo 独占一轮的例外：「禁止 todo_modify 独占一轮，唯一例外是纯文本最终回复的前一轮」 vs 「放弃/跳过必须立即标 cancelled」（此时无工作工具可搭便车）。例外清单补上放弃/跳过/取消场景，并声明搭便车是效率约束、状态正确性优先；其它段明确要求逐个串行时按该段执行（多交付物加速通道）。

落点：1–3 在 `flash/prompt/content/` 的 120/510/520 常量内直接改；4–5 不改 common 共用正文，由 `FlashSkillProtocolRail` 按原文锚点带守卫改写 `skill_execution_rules`（接管路径）与 `skill_protocol`（回退路径），锚点漂移时保留原句并告警。deep 模式维持原行为。

回归：`test_flash_skill_protocol_rail.py` 覆盖删除批量句、扩展例外、best-effort 回退与端到端改写；`test_flash_prompt_offline.py` 覆盖三处正文消歧与「不引用段号」。产品场景需另行验证弱模型在放弃任务与最终回复时的实际行为。
