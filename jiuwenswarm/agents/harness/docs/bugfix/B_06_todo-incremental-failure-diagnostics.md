## 现象与根因

旧数组按 generation 过滤后允许追加进行项，随后却发布成保留多个进行项的版本化计划，下一次仅改内容也被拒绝。参数形状错误、领域错误重复包装和成功结果缺少显式状态，则让失败原因与统计难以区分。

此外，候选 scope 分支已修复的父类初始化、引擎归属与研究回写兼容尚未进入基线；研究旧 worker 绑定不能仅因同名 session 就覆盖当前宿主 provider。取消或回包丢失发生于发布请求之后时，也不能把应用数记为零。

## 决策

- 沿用原 Feat 的同对象完整事务、固定 plan、三次有界 CAS 与文件端条件原子替换；没有新增写入旁路或跨调用合批。
- 迁入 scope 分支的必要净改动，保留原普通/Code 创建规则，Flash 显式开启保护；普通研究空表保存完成阶段，已有用户任务只更新匹配阶段并保留其他行与计划身份。
- 所有候选在发布前校验目标格式。冲突保留文件、返回可纠正说明，不自动改任务状态；候选任务 ID 与“未提交”反馈一起给出。
- Core 保留部分成功，Compatible 保留严格批次及状态别名；已有领域错误透传。读取/写入阶段使用现有领域码，不另造线上错误协议。
- 结果/来源元信息保留为 Python 属性。仅 Todo opt-in 显式终态，内部转发与直接调用区分；缺模型 ID 记 direct，不将其自动认定为宿主或模型事件。准备日志标为 staging/pending，确认提交后才记终态。
- 条件发布在途取消保持 CancelledError；对外仍按原取消控制流处理，内部标记 unknown 与应用数未知，不自动重放。
- provider 明确指定的实际引擎优先于历史绑定，匹配同对象时仍尊重 Core 批次冻结引用；回写资格在取消前关闭，竞速报告交付不重新授予修改资格。

## 协议与兼容

未新增 E2A 事件、请求必填项、默认 todo_meta 或线上能力握手；todos 和工具结果 JSON 形态不变，默认 legacy 投影保留 generation/串行展示。工具卡只补已有字段约束，不使用条件 Schema。旧数组、旧结果对象缺失新增属性可读，旧后端只读兼容不扩张写权限。

SDK 与宿主须按原设计配套。当前官方锁仍未指向这些未提交修复；旧锁源码的基础 API 兼容不表示新修复已交付，不能单独替换 SDK 后假定所有旧宿主已配置 Flash 策略。

## 拒绝的方案

不全量覆盖旧分支文件，不恢复历史锁；不关闭并行调用，不放弃 CAS，不自动完成/取消旧代任务，不用空表冒充丢失/损坏；不默认解析字符串数组，不把所有字典判成功，不按默认标签或错误码出现次数计算唯一调用数。

## 验证与限制

执行证据统一维护在工程根 Checkpoint/debug/tools_failure_analysis/implementation.md，包含原始失败和修复后日志。用例覆盖真实临时文件、并发修改、计划变化、条件写、文件丢失、普通/Flash 回调、取消作用域、同名 session 的跨工作区绑定、终态及 SDK wheel；不将测试后端或临时 daemon 等同于云上/Windows/命名空间验收。

未承诺发布、远端 CI、官方固定 SDK 安装或原日志历史归因闭合。原 Feat 的消费端版本防回退与 Relay 空表刷新遗留不在本次代码改动中掩盖或重做。

## 2026-11-10：反馈、取消与历史边界补齐

保存请求已发出但结果未知时，原内部属性没有进入模型消息。Core 现通过既有错误文本明确提示先查询、勿盲目重试，保留领域码、取消控制流与未知计数；Flash 不再把 unknown 异常误识别为多个进行项的确定拒绝。

Flash 拒答取消后原先重读列表并发送无版本更新。现优先复用取消提交回执，显式 versioned 附带同次版本，默认 legacy 字段和展示保持。历史通过所属会话的实际工具后端及 generation 标记恢复，冷会话使用既有元数据解析；失败不读取宿主旧副本冒充权威状态。

Core 文件锁取消清理覆盖实际释放、内存标记与通知，并等待清理完成后传播取消；实际释放失败不清占用标记。宿主 Todo 初始化检查仅持单会话文件锁，保留跨线程/进程的一次性消费与异步写合并保护，解除全局锁等待。
