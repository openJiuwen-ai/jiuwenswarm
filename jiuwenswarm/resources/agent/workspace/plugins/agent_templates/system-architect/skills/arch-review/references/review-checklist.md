# 架构评审清单与风险识别框架

## 评审流程

```
1. 理解业务上下文和约束
2. 检查架构图（C4 模型完整性）
3. 逐项检查质量属性清单
4. 识别风险并评级
5. 输出评审报告和改进建议
```

## 质量属性检查清单

### 可扩展性

| 检查项 | 通过标准 | 风险信号 |
|--------|---------|---------|
| 水平扩展能力 | 无状态服务可水平扩展 | 依赖本地文件/内存会话 |
| 数据库扩展 | 读写分离/分片策略明确 | 单库承载全部读写 |
| 缓存策略 | 热点数据有缓存层，TTL 合理 | 无缓存或缓存无过期 |
| 异步处理 | 耗时操作异步化（消息队列） | 请求内同步等待长耗时操作 |
| 连接池 | 数据库/HTTP 连接池配置合理 | 每次请求新建连接 |

### 高可用性

| 检查项 | 通过标准 | 风险信号 |
|--------|---------|---------|
| 单点故障 | 无单点（多实例/多可用区） | 依赖单一实例/单一可用区 |
| 熔断降级 | 依赖故障时有熔断和降级策略 | 无熔断，故障级联传播 |
| 重试策略 | 幂等操作有重试+指数退避 | 无重试或无退避 |
| 优雅停机 | SIGTERM 信号处理+连接排空 | 强杀导致请求中断 |
| 健康检查 | liveness + readiness 双探针 | 无健康检查或仅 liveness |
| 容灾备份 | 数据定期备份+恢复演练 | 无备份或未验证恢复 |

### 可维护性

| 检查项 | 通过标准 | 风险信号 |
|--------|---------|---------|
| 模块边界 | 限界上下文清晰，依赖方向单向 | 循环依赖，跨模块直访数据库 |
| 代码分层 | Controller → Service → Repository | 业务逻辑在 Controller，DB 调用在 Controller |
| 配置管理 | 环境变量集中管理，启动校验 | 配置散落代码各处 |
| 错误处理 | 类型化错误体系+全局错误处理 | 通用 Error，catch 后静默忽略 |
| 输入校验 | 所有入口校验（Zod/Pydantic/Validator） | 信任客户端输入 |
| 技术债务 | 有债务清单和偿还计划 | 无债务管理，持续累积 |

### 可观测性

| 检查项 | 通过标准 | 风险信号 |
|--------|---------|---------|
| 结构化日志 | JSON 格式+请求 ID 传播 | console.log 纯文本 |
| 指标埋点 | 关键业务指标有 metrics | 无指标或仅系统级指标 |
| 链路追踪 | 分布式追踪（OpenTelemetry） | 无追踪，跨服务调用不可见 |
| 告警规则 | 关键指标有告警阈值 | 无告警或告警风暴 |
| 仪表盘 | 核心指标有可视化仪表盘 | 排障靠翻日志 |

### 安全性

| 检查项 | 通过标准 | 风险信号 |
|--------|---------|---------|
| 认证授权 | JWT/Session+RBAC | 无认证或硬编码角色 |
| 敏感数据 | 密码加密存储，日志脱敏 | 明文存储，日志含敏感信息 |
| CORS | 显式配置允许来源 | `*` 通配符 |
| 安全头 | helmet/等效安全头 | 无安全头配置 |
| 速率限制 | 公开端点有限流 | 无限流 |

### 成本

| 检查项 | 通过标准 | 风险信号 |
|--------|---------|---------|
| 成本预估 | 架构方案含月度/年度成本预估 | 无成本预估 |
| 自动伸缩 | 计算资源有 HPA/VPA 自动伸缩 | 固定实例无弹性 |
| 存储分层 | 冷热数据分层存储 | 全量存高性能存储 |
| 闲置资源 | 定期清理闲置资源（每月） | 未挂载磁盘/未使用 IP |
| Serverless 成本 | 有成本上限保护 | 高频调用成本失控 |

成本架构与 FinOps 详细参考见：
`cost-architecture.md`

### 合规性

| 检查项 | 通过标准 | 风险信号 |
|--------|---------|---------|
| 法规识别 | 识别适用法规（等保/GDPR/PIPL） | 未识别合规要求 |
| 数据驻留 | 敏感数据存储在法规要求区域 | 跨境传输未审批 |
| 审计留痕 | 关键操作有审计日志，留存达标 | 无审计或留存不足 |
| 被遗忘权 | 用户数据删除流程就绪 | 无删除流程 |
| PII 分级 | 敏感数据分级并采取对应保护 | 无数据分级 |

合规与监管架构详细参考见：
`compliance-architecture.md`

## 风险识别框架

### 风险评级

| 级别 | 定义 | 响应时限 |
|------|------|---------|
| P0-致命 | 单点故障可能导致整体不可用 | 立即修复，阻塞上线 |
| P1-高 | 特定场景下服务降级或数据不一致 | 上线前修复或有明确缓解措施 |
| P2-中 | 非核心功能受影响或可维护性差 | 纳入技术债务计划 |
| P3-低 | 优化建议，非必须 | 按优先级排期 |

### 常见风险模式

**数据一致性风险：**
- 跨服务事务无补偿机制 → 评估 Saga 模式
- 缓存与数据库不一致 → 缓存失效策略+延迟双删
- 事件消费非幂等 → 加幂等键/去重表

**耦合度风险：**
- 服务间循环依赖 → 引入事件解耦或合并服务
- 共享数据库 → 拆分数据库，API 通信
- 共享库版本耦合 → 契约测试+独立版本管理

**性能风险：**
- N+1 查询 → JOIN 或批量加载
- 大事务锁表 → 拆分事务，乐观锁
- 同步调用链过长 → 异步化或批处理

**可用性风险：**
- 依赖无熔断 → 引入 Circuit Breaker
- 无降级策略 → 识别核心链路，非核心降级
- 无容量规划 → 压测+容量评估
