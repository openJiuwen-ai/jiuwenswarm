# 发布检查清单与发布工程

## 6 道门禁

每次发布必须通过以下 6 道门禁，任一未过则阻止发布。

### 门禁 1：代码质量

```
✅ 所有 PR 已 Review 并 Approved
✅ Linter 通过（ESLint / Ruff / golangci-lint）
✅ 无 console.log / print / fmt.Println 残留
✅ 无 TODO/FIXME 标记在发布范围代码中
✅ 代码复杂度在阈值内（圈复杂度 < 15）
```

### 门禁 2：测试覆盖

```
✅ 单元测试通过率 100%
✅ 集成测试通过率 100%
✅ 代码覆盖率 ≥ 80%（核心模块 ≥ 90%）
✅ E2E 关键路径测试通过
✅ 契约测试通过（如有消费者/提供者）
✅ 无新增测试跳过（.skip / @pytest.mark.skip）
```

### 门禁 3：安全扫描

```
✅ 依赖漏洞扫描通过（npm audit / pip-audit / govulncheck）
✅ 无 Critical/High 漏洞在发布范围
✅ 密钥扫描通过（git-secrets / truffleHog）
✅ SAST 静态安全扫描无新增高危
✅ 容器镜像扫描通过（Trivy / Grype）
```

### 门禁 4：构建与打包

```
✅ 构建成功（无 Warning，或 Warning 已知并记录）
✅ 构建产物大小在合理范围（无意外膨胀）
✅ Docker 镜像构建成功
✅ 镜像标签正确（语义化版本 + Git SHA）
✅ .env.example 与代码配置项一致
✅ 数据库迁移脚本就绪且可回滚
```

### 门禁 5：部署验证

```
✅ Staging 环境部署成功
✅ Staging 冒烟测试通过（健康检查 + 核心接口）
✅ 数据库迁移在 Staging 验证通过
✅ 配置/环境变量已更新（Secrets 已注入）
✅ 回滚方案已验证（一键回滚可用）
✅ 监控仪表盘和告警规则已更新
```

### 门禁 6：发布后监控

```
✅ 生产部署成功（蓝绿/金丝雀/滚动）
✅ 健康检查通过（/health + /ready）
✅ 错误率 < SLO 阈值（持续 15 分钟）
✅ 延迟 P99 < SLO 阈值（持续 15 分钟）
✅ 无新增告警（持续 15 分钟）
✅ 关键业务指标正常（订单量/登录量等）
```

## 部署策略

### 蓝绿部署

```
当前：[蓝] ← 100% 流量
新版本：[绿] ← 部署，验证
切换：[绿] ← 100% 流量，[蓝] 待命回退
确认：[蓝] 下线
```

**适用**：可接受短暂双倍资源，需要快速回退。

### 金丝雀发布

```
阶段 1：新版本接收 1% 流量 → 监控 15 分钟
阶段 2：10% → 监控 15 分钟
阶段 3：50% → 监控 15 分钟
阶段 4：100% → 确认完成

每阶段判断：
- 错误率 < 阈值 → 继续
- 错误率 ≥ 阈值 → 回退到上一阶段或 100% 旧版本
```

**适用**：降低发布风险，逐步验证。

### 滚动更新

```
逐个替换实例：[旧][旧][旧] → [新][旧][旧] → [新][新][旧] → [新][新][新]
```

**适用**：K8s 默认策略，不可用实例数受 PDB 控制。

## 回滚策略

### 回滚决策矩阵

| 场景 | 回滚方式 | 决策时限 |
|------|---------|---------|
| 部署后错误率飙升 | 立即回滚到上一版本 | 5 分钟内 |
| 部署后延迟 P99 翻倍 | 回滚或扩容 | 10 分钟内 |
| 数据库迁移导致数据问题 | 逆向迁移 + 回滚代码 | 需评估数据影响 |
| 功能缺陷但不影响核心 | 修复补丁发布，不回滚 | 下一迭代 |

### 回滚检查清单

```
✅ 回滚目标版本号已确认
✅ 数据库迁移可逆向（down migration 已测试）
✅ 配置回滚方案就绪（旧配置已备份）
✅ 回滚后健康检查通过
✅ 回滚后通知 on-call 和相关团队
✅ 回滚后启动事后复盘（Post-mortem）
```

## 发布频率

| 频率 | 适用场景 | 关键支撑 |
|------|---------|---------|
| 每日多次 | 持续部署，高成熟度团队 | 全自动化 CI/CD + 强监控 |
| 每日一次 | 持续交付，大多数团队 | 自动化 CI/CD + 人工审批 |
| 每周一次 | 规律迭代发布 | 自动化 CI/CD + 发布窗口 |
| 每月一次 | 受控发布，合规要求 | 完整门禁 + 审批流程 |

```
原则：小步快跑 > 大爆炸发布
- 每次发布变更范围越小，风险越低
- 发布频率越高，每次发布变更越少
- 高频发布 + 自动化回滚 = 更高稳定性
```
