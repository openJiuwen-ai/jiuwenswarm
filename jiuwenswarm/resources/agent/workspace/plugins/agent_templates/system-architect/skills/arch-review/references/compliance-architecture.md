# 合规与监管架构

## 核心原则

合规不是事后补丁，而是架构约束。系统设计阶段就需识别适用的法规标准，将合规要求嵌入数据流、存储和访问控制。

## 法规框架速查

### 中国法规

| 法规 | 适用范围 | 架构影响 |
|------|---------|---------|
| 网络安全法 | 所有中国境内运营的系统 | 等保分级、日志留存 ≥ 6 个月、数据本地化 |
| 数据安全法 | 处理个人数据的企业 | 数据分级分类、跨境传输审批 |
| 个人信息保护法（PIPL） | 处理个人信息的组织 | 知情同意、最小必要、可删除、可携带 |
| 等保 2.0 | 信息系统安全保护 | 分级保护要求（五级） |

### 国际法规

| 法规 | 适用范围 | 架构影响 |
|------|---------|---------|
| GDPR | 服务欧盟用户 | 数据驻留、被遗忘权、数据可携带、DPO |
| CCPA/CPRA | 服务加州用户 | 知情权、删除权、不出售个人信息 |
| HIPAA | 医疗健康数据 | 加密、审计、访问控制、BAA 协议 |
| SOC 2 | SaaS 服务 | 安全/可用性/处理完整性/保密性 |
| PCI-DSS | 处理支付卡数据 | 网络隔离、加密、访问控制、审计 |

## 等保分级架构要求

### 等保级别与架构要求

| 级别 | 适用系统 | 架构要求 |
|------|---------|---------|
| 二级 | 一般业务系统 | 基本安全：防火墙、防病毒、日志审计 |
| 三级 | 重要业务系统 | 区域隔离、入侵检测、双因子认证、日志 ≥ 6 月 |
| 四级 | 关键信息基础设施 | 多层防护、冗余设计、实时入侵检测、日志 ≥ 24 月 |

### 三级等保架构要点

```
1. 网络区域划分
   ├── 外网区（DMZ）：对外服务，WAF + IDS
   ├── 应用区：业务服务，内部防火墙隔离
   ├── 数据区：数据库，严格访问控制
   └── 管理区：运维接入，堡垒机 + 审计

2. 访问控制
   ├── 双因子认证（密码 + 短信/Token）
   ├── 最小权限原则
   ├── 运维通过堡垒机，操作录屏
   └── 数据库访问审计

3. 安全审计
   ├── 日志留存 ≥ 6 个月
   ├── 安全事件实时告警
   ├── 审计日志不可篡改
   └── 定期安全评估
```

## 数据驻留与跨境传输

### 数据驻留架构

```
原则：数据存储和处理在法规要求的地理边界内

实施模式：
1. 区域部署：不同地区数据存不同区域数据库
2. 数据分类：区分可跨境数据 vs 不可跨境数据
3. 路由策略：按用户地理区域路由到对应区域
4. 同步策略：仅同步非敏感数据跨区域
```

### 跨境传输合规

```
中国数据出境要求：
- 数据出境安全评估（重要数据/大规模个人信息）
- 个人信息出境标准合同（SCC）
- 认证路径（APEC CBPR）

架构影响：
- 敏感数据不出境 → 区域化部署
- 跨境数据脱敏 → 出境前 PII 脱敏
- 审计留痕 → 记录所有跨境数据访问
```

## 审计留痕架构

### 审计日志要求

```
审计日志必须记录：
- 谁（用户 ID + 角色 + IP）
- 何时（时间戳 + 时区）
- 做了什么（操作类型 + 操作对象 + 操作前后值）
- 从哪里（来源系统 + 调用链 ID）
- 结果（成功/失败 + 错误原因）
```

### 审计日志架构

```typescript
// 审计中间件
app.use(auditMiddleware({
  log: (event) => {
    auditLogger.info('AUDIT', {
      userId: event.userId,
      action: event.action,        // CREATE / READ / UPDATE / DELETE
      resource: event.resource,    // 订单/用户/配置
      resourceId: event.resourceId,
      before: event.before,        // 变更前值
      after: event.after,          // 变更后值
      ip: event.ip,
      timestamp: event.timestamp,
      traceId: event.traceId,
    });
  },
  // 敏感字段自动脱敏
  maskFields: ['password', 'idCard', 'phone', 'email'],
}));
```

### 审计日志存储

```
✅ 审计日志独立存储（不与业务日志混存）
✅ 不可篡改（追加写，禁止更新/删除）
✅ 保留期满足法规要求（等保三级 ≥ 6 月，四级 ≥ 24 月）
✅ 定期备份到独立存储

❌ 审计日志和业务日志放同一索引
❌ 允许修改或删除审计日志
❌ 审计日志不含操作前后值
```

## 数据隐私架构

### PII 分级与处理

| 级别 | 数据类型 | 存储要求 | 展示要求 | 审计要求 |
|------|---------|---------|---------|---------|
| L1-极高 | 身份证/护照/生物特征 | 字段级加密 + KMS | 永不展示明文 | 每次访问记录 |
| L2-高 | 手机/邮箱/地址 | 加密存储 | 按角色脱敏 | 批量访问告警 |
| L3-中 | 行为/偏好数据 | 访问控制 | 可展示 | 定期审计 |
| L4-低 | 公开数据 | 基本控制 | 可展示 | 无 |

### 被遗忘权实现

```
用户请求删除 →
1. 标记删除（软删除，不立即物理删除）
2. 30 天宽限期（防止误操作/恶意请求）
3. 物理删除执行：
   - 业务数据库：删除或匿名化
   - 备份：标记，下次备份轮转时清除
   - 日志：脱敏（保留审计价值，去除 PII）
   - 缓存：立即清除
   - 分析库：匿名化或删除
4. 生成删除证明（记录删除时间、范围、操作人）
```

## 合规架构评审清单

```
✅ 识别适用的法规标准（等保/GDPR/PIPL/行业法规）
✅ 数据驻留策略符合法规要求
✅ PII 分级并采取对应保护措施
✅ 审计日志覆盖关键操作，留存期满足要求
✅ 被遗忘权/数据可携带流程就绪
✅ 跨境数据传输合规（安全评估/SCC）
✅ 等保级别对应的安全措施就位
✅ 数据分类分级文档维护
✅ 合规决策记录在 ADR 中
```
