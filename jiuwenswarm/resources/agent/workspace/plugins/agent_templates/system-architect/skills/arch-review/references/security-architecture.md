# 安全架构

## 核心原则

安全不是功能，是架构属性。安全设计从威胁建模开始，贯穿架构决策全生命周期。

## 威胁建模

### STRIDE 框架

| 威胁类型 | 含义 | 对应安全属性 | 架构对策 |
|---------|------|------------|---------|
| **S**poofing | 身份伪造 | 认证 | mTLS、JWT 签名验证、证书轮换 |
| **T**ampering | 数据篡改 | 完整性 | HMAC 签名、数据库审计日志、WAF |
| **R**epudiation | 否认操作 | 不可否认性 | 审计日志链、操作签名、时间戳服务 |
| **I**nfo Disclosure | 信息泄露 | 机密性 | 数据加密（传输+存储）、PII 脱敏、最小权限 |
| **D**oS | 拒绝服务 | 可用性 | 限流、熔断、CDN 缓存、DDoS 防护 |
| **E**levation | 权限提升 | 授权 | RBAC/ABAC、垂直/水平越权检查 |

### 威胁建模流程

```
1. 绘制数据流图（DFD）：外部实体 → 进程 → 数据存储 → 数据流
2. 识别信任边界：标注信任级别变化点
3. 逐组件应用 STRIDE：每个组件/数据流检查 6 类威胁
4. 评估风险：影响 × 可能性 = 风险等级
5. 制定缓解措施：按风险等级排序处理
6. 验证缓解措施：安全测试/渗透测试
```

### 攻击树示例

```
目标：获取用户敏感数据
├── 直接访问数据库
│   ├── SQL 注入 → 参数化查询 + ORM + WAF
│   └── 数据库凭据泄露 → 密钥管理服务 + 最小权限
├── 通过 API 越权
│   ├── 水平越权（访问他人数据）→ 资源所有权校验
│   └── 垂直越权（普通用户访问管理接口）→ RBAC 强制校验
├── 通过日志/缓存泄露
│   ├── 日志含敏感数据 → 日志脱敏中间件
│   └── 缓存含敏感数据 → 敏感数据不缓存或加密缓存
└── 通过中间人攻击
    ├── 传输层窃听 → TLS 1.3 + HSTS
    └── 证书伪造 → 证书钉扎（移动端）
```

## 零信任架构

### 核心原则

```
1. 永不信任，始终验证 — 每次请求都验证身份和权限
2. 最小权限 — 默认拒绝，按需授权
3. 假定被入侵 — 纵深防御，限制爆炸半径
4. 持续监控 — 实时检测异常行为
```

### 架构模式

```
客户端 → ┌─ 身份验证（Who）─┐
         ├─ 设备验证（What）─┤ → 策略引擎 → 授权决策 → 资源访问
         ├─ 上下文验证（Where/When）─┤
         └─ 行为分析（How）─┘
```

**关键组件：**
- **身份提供者（IdP）**：统一身份认证（OIDC/OAuth2）
- **策略引擎**：基于属性的策略评估（ABAC）
- **微分段**：网络层面限制东西向流量
- **持续验证**：会话超时 + 风险重评估

## 数据隐私架构

### PII 分级

| 级别 | 数据类型 | 示例 | 保护措施 |
|------|---------|------|---------|
| L1-极高 | 直接身份标识 | 身份证号、护照号 | 加密存储 + 字段级加密 + 审计日志 |
| L2-高 | 间接身份标识 | 手机号、邮箱、地址 | 加密存储 + 访问控制 + 脱敏展示 |
| L3-中 | 行为/偏好数据 | 购买记录、浏览历史 | 访问控制 + 匿名化分析 |
| L4-低 | 公开数据 | 昵称、头像 | 基本访问控制 |

### 数据脱敏策略

```
存储层：敏感字段字段级加密（AES-256-GCM）
传输层：TLS 1.3 全链路加密
日志层：脱敏中间件（正则匹配 + 掩码替换）
展示层：按角色脱敏（手机号 138****1234）
分析层：k-匿名化 / 差分隐私
```

### 数据最小化原则

- 只收集业务必需的数据
- 设置数据保留策略（TTL 自动清理）
- 用户数据删除请求流程（GDPR/个保法合规）
- 数据导出能力（可移植性）

## 安全架构决策模式

### 认证架构

| 模式 | 适用场景 | 架构要点 |
|------|---------|---------|
| 网关鉴权 | 统一入口、简单 API | API 网关统一 JWT 验证，下游服务信任网关 |
| 服务间 mTLS | 零信任、多服务 | 每服务证书，双向验证，Sidecar 代理 |
| 委托令牌 | 需要用户上下文传递 | 网关验证后传递用户身份令牌给下游 |
| OAuth2 资源服务器 | 第三方 API | 每服务独立验证 Access Token |

### 密钥管理

```
✅ 密钥存储在 KMS/Vault，运行时获取
✅ 密钥轮换自动化（30-90 天）
✅ 不同环境使用不同密钥
✅ 密钥访问审计日志

❌ 密钥硬编码在代码或配置文件
❌ 同一密钥跨环境使用
❌ 密钥通过日志/聊天/邮件传递
```

### 安全架构评审清单

- [ ] 威胁建模已完成（STRIDE），风险已评级
- [ ] 认证方案明确（网关鉴权 / mTLS / OAuth2）
- [ ] 授权策略覆盖垂直和水平越权
- [ ] 敏感数据分级并采取对应保护
- [ ] 密钥管理方案明确（KMS/Vault + 轮换）
- [ ] 审计日志覆盖关键操作
- [ ] 限流和 DDoS 防护就位
- [ ] 安全头和 CORS 配置正确
- [ ] 依赖漏洞扫描纳入 CI
- [ ] 数据保留和删除策略合规
