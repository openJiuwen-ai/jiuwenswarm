# 内容增强

用这个技能在当前回复中增强已有内容。保持增强后的成果可见且可直接使用，优先于流程说明。

## 核心工作流

1. 判断请求属于资料调研与引用、开篇优化、标题优化还是文本润色。
2. 识别现有内容最需要什么——证据缺口、薄弱开篇或语言质量问题。先找最影响质量的 1-2 个问题，不盲目全面铺开。
3. 选择本请求所需的最小参考集。不默认加载所有参考文件——加载不需要的参考会浪费 context 且可能引入无关规则。
4. 产出可见的增强成果：可插入的引用段落、优化后的开篇或润色后的文本。
5. 说明剩余核验需求和单一下一步。

## 参考路由

- 用户需要调研支撑、引用补充、证据背书或缺口识别时，阅读[资料调研与引用](references/research-and-citation.md)。
- 用户想要诊断、改善或重写开篇时，阅读[开篇优化](references/opening-optimization.md)。
- 用户想要诊断、优化或重写文章标题时，阅读[标题优化](references/title-optimization.md)。
- 用户想要在不改变结构和事实的前提下提升语言质量——用词、句式节奏、去冗、语气统一和去 AI 腔时，阅读[文本润色](references/text-polishing.md)。

## 示例

**输入**：用户已有正文第2段——"随着数字化转型的深入，企业效率显著提升。"，要求"加个引用"

**输出（摘要）**：
> **缺口识别**：P0 事实断言——"数字化转型""效率提升"缺少数据支撑
> **可插入引用**：> 据麦肯锡《2024数字化报告》，完成数字化转型的企业运营效率平均提升 23%。 ——[verification_pending：建议核验麦肯锡报告原文]
> **待核验**：麦肯锡报告具体数据 → 关键词：麦肯锡 数字化转型 效率提升 2024

## Tool 协作

- **citation_formatter**：补充引用时调用。传入引用条目（author、title、year、source_type 等）和目标格式（gbt7714、apa、mla 或 inline）。工具返回标准化格式化引用字符串。始终确保引用条目来自用户提供的材料或标注为 `verification_pending`——不编造引用数据喂给工具，因为虚构的引用来源会误导读者。
- **何时不调用**：用户只要求"指出哪里需要引用"但不要求格式化时，直接在正文中标注待核验即可，不需要调用工具。
- **调用顺序**：先识别缺口并写出引用段落 → 需要格式化时调 citation_formatter → 格式化结果传给 document_exporter（如用户要求导出）。

## 通用底线

- 从用户实际内容出发，不虚构缺失的调研、引文、事件或授权——虚构内容会误导读者且用户无法核验。
- 匹配用户的语言和语气，保持术语、人名、数字和观点与提供的内容一致。
- 不声称文件已保存或导出，除非当前任务有可见的成功写入回执。

## 增强专属规则

- 区分三种引用状态：material_provided、model_inferred、verification_pending——区分是因为用户需要知道哪些引用可以直接信任，哪些需要自己核验。所有非用户材料提供的引用必须标注。
- 不伪造链接、DOI、ISBN 或其他可追溯标识——这些标识可以被验证，伪造会损害用户信誉。
- 保留用户的核心立场、事实边界和作者声音。增强提升质量，不改变意思——因为用户要的是"更好的版本"，不是"不同的文章"。
- 对法律、医疗、金融或监管内容，要求适当来源并标注 human_review_pending——这些领域的错误信息可能造成实际伤害。

## 输出策略

- 资料调研与引用：调研缺口清单、可插入引用段落、引用标注、待核验清单。
- 开篇优化：开篇诊断、优化后开篇正文、简短变更说明。
- 标题优化：标题诊断、2-3 个优化方案含策略标注、变更说明。
- 文本润色：润色等级、逐段润色文本或前后对比、变更汇总。
- 不把普通正文强行写成 JSON——JSON 不可读。只在缺口优先级或前后对比需要更清晰检查时使用表格。

## 外部能力策略

即使连接器、网络或文件工具不可用，也要从对话中完成核心增强。可选能力仅在可见、相关且获用户明确授权时增强，要求有界超时，不阻断核心工作，不把待发请求写成成功。

## 完成检查

回复前确认：

- 至少有一个用户可编辑的增强成果；
- 用户的核心立场和事实边界得到保留；
- 引用状态和证据缺口可见；
- 恰好一个清晰的推荐下一步。
