# First Value Writing / 首值写作

从零散材料（提纲、访谈记录、笔记、旧稿片段）启动新内容时的写作流程。

## 核心原则

**第一轮就给可见价值**：材料足以开始时，第一轮输出结构和实质性正文，不得只提问、只给计划、只复述能力或只给空模板。

## 文档类型判断

根据材料特征判断最可能的文档类型：

| 材料特征 | 可能的文档类型 | 典型结构 |
| --- | --- | --- |
| 有论点、论据、数据 | 议论文/评论/分析报告 | 提出问题→分析→论证→结论 |
| 有人物、事件、时间线 | 叙事文/人物稿/案例故事 | 引子→背景→发展→高潮→收束 |
| 有步骤、方法、操作记录 | 教程/指南/操作手册 | 概述→前置条件→分步操作→注意事项 |
| 有观点集合、多角度素材 | 深度报道/专题/综述 | 切入→多角度展开→交叉验证→总结 |
| 有产品信息、卖点、受众 | 营销文案/产品介绍 | 痛点→方案→证据→行动号召 |
| 有研究问题、文献、方法 | 学术论文/研究报告 | 引言→文献→方法→结果→讨论 |

判断不确定时，列出 2-3 个候选类型并标注暂定假设，让用户确认或修正。

## 启动卡输出格式

第一轮按以下顺序给出"内容启动卡"：

### 1. 文档判断
- 文档类型（含暂定假设标注）
- 目标读者
- 核心目标/核心主张
- 建议篇幅或交付形态

### 2. 建议目录与章节任务
- 给出足以推进的目录（3-7 章/节）
- 每章用一句话说明要解决的问题和需要的材料
- 标注哪些章节材料已充足、哪些待补

### 3. 实质性正文
- 直接写出开篇、首节或最关键样段
- 正文必须能被用户继续编辑
- 不能用"这里以后再写""此处插入正文"代替
- 材料较少时正文可以较短，但仍要形成完整段落
- 材料丰富时优先写最能验证方向的一节

### 4. 主要风险
- 只列最影响成稿的 2-3 项
- 类型：事实缺口、结构冲突、版权或时效风险、受众偏差
- 说明每项风险会影响哪里

### 5. 单一下一步
- 推荐用户下一次最值得完成的一件事
- 表述成可直接执行的动作（如"补充第二章需要的 XX 数据"）

### 6. 续写口令
- 给出一条可复制到新会话的口令
- 包含：文档定位、已完成位置、下一节目标、必须保留的约束

## 材料成熟度分级

| 成熟度 | 特征 | 首值产出 |
| --- | --- | --- |
| 高 | 有明确主题、核心素材、目标读者 | 完整结构 + 1-2 节正文 |
| 中 | 有主题和部分素材，缺受众或部分论据 | 结构 + 开篇正文 + 待补标注 |
| 低 | 只有零散笔记或提纲 | 暂定文档类型 + 骨架结构 + 1 段示范正文 |

低成熟度也要产出：哪怕只有一段示范正文，也比只给计划有价值。用明确标注的暂定假设推进，不等待"完美需求"。

## 写作标准

- 优先具体名词、清楚动词和可验证关系，减少空泛形容词和流程口号。
- 保持章节职责单一：一章解决一个主要问题，一节完成一个明确推进。
- 引用、数字、专名和关键定义在全文保持一致；不确定处使用醒目的待核验标记。
- 用户要求特定格式时遵循其格式；否则使用清晰的 Markdown 标题和短段落。
- 不为展示"专业"而堆叠内部术语。用户首先应看到可用正文，其次才是必要说明。

## 禁止

- 第一轮只有追问、计划、能力介绍或空模板，没有结构和实质性正文。
- 用"根据您的需求，我建议如下"等套话代替实际内容。
- 伪造材料中不存在的事实、数据或引文。
