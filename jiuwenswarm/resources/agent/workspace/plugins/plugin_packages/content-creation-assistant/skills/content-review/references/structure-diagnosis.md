# Structure Diagnosis / 结构诊断

对文稿做独立的结构层面诊断，不逐段改文字，只评估章节安排、逻辑流向和篇幅平衡。

## 与逐段修改反馈和成稿收口的区别

| 维度 | 结构诊断 | 逐段修改反馈 | 成稿收口 |
| --- | --- | --- | --- |
| 层面 | 中观（章节级） | 微观（段落级） | 宏观（全文+交付） |
| 改文字？ | 不改 | 逐段改 | 修复最高价值段落 |
| 输出 | 结构图+诊断+建议 | 逐段诊断+修订文本 | 总体判断+修复+交付清单 |
| 适用时机 | 结构不确定时 | 结构已定，改文字时 | 文字已定，交付前 |

## 诊断维度

### 1. 章节安排
| 检查要点 | 常见问题 |
| --- | --- |
| 章节顺序是否符合逻辑递进 | 论证型：论据在结论前；叙事型：因果在结果前 |
| 是否有冗余章节 | 两章讲同一件事、某章可合并到其他章 |
| 是否有缺失章节 | 论证缺结论、叙事缺转折、教程缺注意事项 |
| 章节职责是否单一 | 一章塞多个主题，读者不知道这章在讲什么 |

### 2. 逻辑流向
| 检查要点 | 常见问题 |
| --- | --- |
| 前后章节论点是否矛盾 | 第2章说A，第4章说非A |
| 论证链是否完整 | 提出问题→分析→论证→结论，是否有断裂 |
| 过渡是否自然 | 章节之间有无过渡，还是硬跳 |
| 因果关系是否成立 | 结论是否真的由论据推出 |

### 3. 篇幅平衡
| 检查要点 | 常见问题 |
| --- | --- |
| 各章篇幅是否与重要性匹配 | 核心论点只占1段，背景介绍占3页 |
| 是否有章节过长或过短 | 某章是其他章的3倍、某章只有1句话 |
| 开头和结尾比例是否合理 | 开头铺垫过长、结尾草草收场 |

### 4. 开头结尾呼应
| 检查要点 | 常见问题 |
| --- | --- |
| 开头承诺的内容结尾是否回收 | 开头说"将分析三个原因"，结尾只提了两个 |
| 开头的问题结尾是否回答 | 开头提问，结尾没有回答 |
| 开头和结尾的语气是否一致 | 开头严肃分析，结尾突然抒情 |

### 5. 信息密度分布
| 检查要点 | 常见问题 |
| --- | --- |
| 是否有章节信息密度过低 | 整章都在说"很重要"但没说为什么 |
| 是否有章节信息密度过高 | 一章塞入过多数据，读者无法消化 |
| 核心论点是否在关键位置 | 核心论点藏在中间不起眼的段落 |

## 诊断流程

### 1. 结构地图
- 用缩进列表或表格画出当前章节结构
- 每章标注：标题、字数（或占比）、核心内容一句话概括
- 标注章节间的逻辑关系（递进/并列/转折/因果）

### 2. 逐维度诊断
- 对每个维度给出状态（✅正常/⚠️需改进/🔧需重构）
- 指出最影响整体结构的 1-3 个核心问题
- 每个问题说明：在哪里、是什么、影响什么

### 3. 结构建议
- 针对核心问题给出具体调整建议
- 建议类型：移动章节、合并章节、拆分章节、删除章节、新增章节、调整篇幅
- 每条建议说明：为什么改、改成什么、改后效果

### 4. 单一下一步
- 推荐用户最值得先做的一个结构调整

## 输出格式

```
## 结构地图
| 章节 | 字数/占比 | 核心内容 | 逻辑关系 |
| --- | --- | --- | --- |
| 第1章 | 800字/15% | [一句话概括] | — |
| 第2章 | 2000字/38% | [一句话概括] | 递进 |
| ...

## 逐维度诊断
| 维度 | 状态 | 说明 |
| --- | --- | --- |
| 章节安排 | ⚠️需改进 | [说明] |
| 逻辑流向 | ✅正常 | [说明] |
| 篇幅平衡 | 🔧需重构 | [说明] |
| 开头结尾呼应 | ⚠️需改进 | [说明] |
| 信息密度 | ✅正常 | [说明] |

核心问题：
1. [问题1：位置+是什么+影响什么]
2. [问题2：位置+是什么+影响什么]

## 结构建议
1. [建议1：类型+为什么+改成什么+效果]
2. [建议2：类型+为什么+改成什么+效果]

## 单一下一步
[一个可直接执行的动作]
```

## 禁止

- 只说"结构有问题"但不给具体位置和建议。
- 逐段改文字——那是逐段修改反馈的职责。
- 不画结构地图就开始诊断——没有全局视图的诊断容易遗漏。
- 建议拆分/删除章节但不说明理由。
