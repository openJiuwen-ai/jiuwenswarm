# Manuscript Writing / 文稿撰写

基于已定结构进行完整章节和段落撰写的工作流程。

## 核心原则

**连续产出可用正文**：不是只写开篇，而是基于已定结构逐节推进，每节产出完整、可编辑的正文段落。保持跨章节的风格一致性和信息密度控制。

## 章节撰写流程

### 1. 确认承接位置
- 从用户给出的最后一个稳定锚点继续
- 说明本次承接的章节位置和目标
- 不重复上一段已经完成的内容

### 2. 章节撰写
- 每节解决一个明确问题，完成一个清晰推进
- 先写正文，再给章节完成说明
- 缺失的跨章事实标为待补，不自行创造为既定事实
- 材料充足时节写完整；材料不足时写能验证方向的核心段落，标注待补

### 3. 章节完成说明
- 本节完成了什么
- 与前一节的衔接关系
- 下一节的单一下一步和更新后的续写口令

## 跨章节一致性控制

| 维度 | 控制要点 |
| --- | --- |
| 术语统一 | 同一概念全文用同一术语，不中途换词 |
| 逻辑连贯 | 后章节不与前章节论点矛盾；论证递进有层次 |
| 叙事线 | 人物、时间线、事件顺序前后一致 |
| 数字一致 | 同一数据全文一致，不出现不同版本 |
| 语气统一 | 全文语气与目标读者匹配，不中途突变 |
| 指代清晰 | 代词和指代有明确先行词，不产生歧义 |

## 信息密度控制

- 每段传达一个明确信息点，不堆砌多个未展开的论点。
- 避免信息密度过低（整段都在说"很重要"但没说为什么）。
- 避免信息密度过高（一段塞入过多数据，读者无法消化）。
- 关键数据用具体数字，不用"很多""大量"等模糊量词。
- 抽象论点后紧跟具体例证，不让抽象悬空。

## 不同文体的章节写作规范

| 文体 | 章节结构 | 写作要点 |
| --- | --- | --- |
| 议论文/评论 | 提出分论点→给论据→分析→小结 | 每节论证一个分论点，论据具体，分析到位 |
| 叙事文/人物稿 | 场景→冲突→发展→转折 | 每节推进一个叙事单元，保持场景感和节奏 |
| 深度报道/专题 | 切入角度→展开→交叉验证→深化 | 每节从一个角度展开，多源交叉 |
| 教程/指南 | 概述→分步操作→注意事项→小结 | 每节完成一个操作单元，步骤可执行 |
| 营销文案 | 痛点→方案→证据→行动号召 | 每节推进一个说服阶段，证据具体 |
| 学术论文 | 引言→方法→结果→讨论 | 每节完成一个研究环节，逻辑严密 |

## 续写口令

每次章节撰写完成后，给出更新后的续写口令，包含：

- 文档类型、目标读者和核心目标
- 已完成的章节与当前停点
- 已确认的事实、术语、语气和不可改动项
- 仍缺的材料或待核验事项
- 下一节要完成的唯一目标

续写口令是用户可见文本，不代表系统已经保存状态。新会话只能依据用户再次提供的口令继续。

## 写作标准

- 优先具体名词、清楚动词和可验证关系，减少空泛形容词和流程口号。
- 保持章节职责单一：一章解决一个主要问题，一节完成一个明确推进。
- 结构调整要解释为什么；风格调整不得偷换事实、立场或作者声音。
- 引用、数字、专名和关键定义在全文保持一致；不确定处使用醒目的待核验标记。
- 用户要求特定格式时遵循其格式；否则使用清晰的 Markdown 标题和短段落。
- 不为展示"专业"而堆叠内部术语。用户首先应看到可用正文，其次才是必要说明。

## 禁止

- 只给章节计划或大纲，不写实质性正文。
- 重复已完成的上一段内容。
- 自行创造材料中不存在的跨章事实。
- 为追求篇幅一次性铺满全文，牺牲质量。
- 跨章节术语、逻辑、数字不一致而不标注。
