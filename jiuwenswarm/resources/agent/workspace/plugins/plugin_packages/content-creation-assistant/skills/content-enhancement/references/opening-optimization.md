# Opening Optimization / 开篇优化

诊断和优化已有开篇（或全文首段）的工作流程。

## 核心原则

**先诊断后优化**：先指出当前开篇的具体问题，再给出优化后的开篇正文。不盲目重写，不无理由地推翻用户原稿。

## 开篇诊断维度

逐维度检查当前开篇：

| 维度 | 检查要点 | 常见问题 |
| --- | --- | --- |
| 吸引力 | 是否在前三句抓住读者注意力 | 开头太平淡、离题太远、套话太多 |
| 信息量 | 读者读完开篇是否知道文章要讲什么 | 核心信息缺失、主题模糊 |
| 节奏 | 从开篇到正文的过渡是否自然 |铺垫过长、跳跃太快、缺少过渡句 |
| 语气一致性 | 开篇语气是否与全文/目标读者匹配 | 语气突变、过于学术或过于口语 |
| 具体性 | 是否用了具体名词和场景而非空泛概括 | 全是形容词、没有画面感 |
| 承诺匹配 | 开篇承诺的内容是否与后续章节对应 | 开篇承诺了后文没有的内容 |

## 优化流程

### 1. 开篇诊断
- 逐维度给出当前开篇的状态（正常/需改进/严重不足）
- 指出最影响阅读体验的 1-2 个核心问题
- 引用原文具体句子作为诊断依据

### 2. 优化策略
- 针对核心问题给出优化方向（不是泛泛的"写得更好"）
- 策略选项：
  - **场景切入**：用一个具体场景或细节开头，替代抽象概述
  - **问题切入**：用读者关心的问题开头，制造阅读动机
  - **数据切入**：用一个出人意料的数据开头，制造认知冲突
  - **对比切入**：用对比或反差开头，制造张力
  - **叙事切入**：用一个简短故事或人物开头，建立情感连接
  - **直述切入**：直接陈述核心观点，适合信息密度高的文体

### 3. 优化后开篇正文
- 直接写出优化后的开篇完整段落
- 必须是可以直接替换原稿的成品正文
- 保留用户原文中有效的事实、语气和关键信息
- 不改变用户的核心立场和事实边界

### 4. 变更说明
- 列出主要变更点（如"删除了开头套话""增加了场景细节""调整了节奏"）
- 说明每项变更的理由
- 保留原文锚点，方便用户对比和回退

## 开篇优化标准

- 前三句必须让读者知道"这篇文章在讲什么"或"为什么要读下去"。
- 避免以"随着……的发展""在当今社会""众所周知"等套话开头。
- 避免在开篇堆砌定义和背景信息，这些可以放到第二段或后续。
- 开篇长度通常 1-3 段（150-400 字），根据文体调整。
- 开篇承诺的内容必须在后文兑现；如果后文没有，修改开篇承诺而非空许诺。

## 不同文体的开篇策略

| 文体 | 推荐切入策略 | 开篇目标 |
| --- | --- | --- |
| 议论文/评论 | 问题切入或数据切入 | 让读者知道你要论证什么、为什么要关注 |
| 叙事文/人物稿 | 场景切入或叙事切入 | 建立场景感和人物兴趣 |
| 深度报道/专题 | 数据切入或对比切入 | 制造认知冲突，引出主题 |
| 教程/指南 | 问题切入或直述切入 | 让读者知道能学到什么 |
| 营销文案 | 痛点切入或对比切入 | 建立共鸣，引出解决方案 |
| 学术论文 | 直述切入 | 简洁陈述研究问题和价值 |

## 输出格式

```
## 开篇诊断
| 维度 | 状态 | 说明 |
| --- | --- | --- |
| 吸引力 | 需改进 | [具体说明] |
| 信息量 | 正常 | [具体说明] |
| ...

核心问题：
1. [最影响阅读的问题1]
2. [最影响阅读的问题2]

## 优化策略
[针对核心问题的优化方向，1-2 句话]

## 优化后开篇
[优化后的完整开篇正文，可直接替换原稿]

## 变更说明
| 变更点 | 原文 | 优化后 | 理由 |
| --- | --- | --- | --- |
| 删除套话 | "随着……的发展" | （删除） | 套话开头降低吸引力 |
| 增加场景 | 无 | "XX 具体场景" | 建立画面感 |
```

## 禁止

- 不诊断就直接重写，不给变更理由。
- 改变用户的核心立场、事实边界或作者声音。
- 把开篇优化变成全文重写。
- 用"建议优化如下"等套话代替实际优化正文。
