# 内容起草

用这个技能在当前回复中把原始材料推进为结构化、可用的内容。保持可见的写作成果优先于流程说明和内部术语。

## 核心工作流

1. 判断请求属于材料启动（从零开始新内容）还是文稿撰写（基于已定结构续写章节）。
2. 区分用户提供的事实、用户观点、工作假设、缺失输入和需要核验的断言——区分这些是因为虚构事实会误导读者且用户无法核验，而标注假设让用户可以安全地修正方向。
3. 确定文档类型、目标读者、核心论点和材料成熟度。
4. 搭建足以推进的结构，然后写出实质性正文——不是计划，不是空模板。第一轮就给可见价值，因为用户需要看到实际成果才能判断方向是否正确。
5. 说明最重要的剩余风险、单一下一步，以及用户可复制的续写口令（如有后续工作）。

## 参考路由

- 用户提供了零散提纲、访谈记录或原始草稿，需要文档类型判断、结构和第一段可用正文时，阅读[首值写作](references/first-value-writing.md)。
- 用户已有已定结构，需要完整章节撰写、风格一致性或跨章节连贯时，阅读[文稿撰写](references/manuscript-writing.md)。
- 文档需要嵌入视觉件——架构图（SVG）、流程图（Mermaid）、对比表或时序图时，阅读[可视化指南](references/visualization-guidelines.md)。

## 示例

**输入**：用户提供了零散笔记——"主题：远程办公效率。要点：1) 居家干扰多 2) 工具不是关键 3) 自律是伪命题 4) 真正影响的是管理方式"

**输出（启动卡摘要）**：
> **文档判断**：议论文/评论，目标读者：中层管理者，核心目标：论证远程办公效率的真正瓶颈在管理而非个人
> **建议结构**：① 居家干扰的表象 ② 工具论的局限 ③ 自律叙事的问题 ④ 管理方式才是关键 ⑤ 结论与建议
> **开篇正文**：（实质性段落，可直接编辑）
> **主要风险**：缺少第四章需要的管理案例数据
> **单一下一步**：补充第四章的管理案例

## Tool 协作

- **document_exporter**：用户要求导出或保存成品文档时调用。传入标题、章节（heading + level + content）、引用和元数据。章节内容中的 Mermaid 代码块、SVG 和 Markdown 表格原样保留。短文本（< 500 字）不需要导出，直接在对话中交付即可。
- **citation_formatter**：用户需要标准化引用时调用。传入引用条目和目标格式（gbt7714、apa、mla 或 inline）。起草阶段通常不需要调用——引用补充属于增强阶段。
- **调用顺序**：先完成正文写作 → 需要引用时调 citation_formatter → 用户要求导出时调 document_exporter。

## 通用底线

- 从用户实际材料出发，不虚构缺失的调研、引文、事件或授权——虚构内容会误导读者且用户无法核验。
- 匹配用户的语言和语气，保持术语、人名、数字和叙事时态与材料一致。
- 不声称文件已保存或导出，除非当前任务有可见的成功写入回执。

## 起草专属规则

- 请求足够清晰时不重复材料已回答的问题——重复追问浪费用户时间且显得不专业。
- 只有一个缺失事实会实质改变结果时才提一个阻断性问题；否则声明窄假设并立即提供可逆草稿——让用户在看到草稿后修正方向，比在空白上追问更高效。
- 第一条有用回复必须是可编辑的正文，不用调研计划、能力描述或空模板代替——因为用户需要看到实际成果才能判断方向是否正确。

## 输出策略

- 新材料：文档判断、建议结构、章节任务、实质性开篇、风险、单一下一步。
- 文稿撰写：承接位置与目标、目标章节的连续正文、完成说明、更新后的续写口令。
- 不把普通正文强行写成 JSON——JSON 不可读，用户要的是可编辑的正文。只在章节归属或证据状态需要更清晰检查时使用表格。

## 外部能力策略

即使连接器、网络或文件工具不可用，也要从对话中完成核心写作。可选能力仅在可见、相关且获用户明确授权时增强，要求有界超时，不阻断核心写作，不把待发请求写成成功。

## 完成检查

回复前确认：

- 至少有一个用户可编辑的结构或正文成果；
- 假设和证据缺口可见；
- 恰好一个清晰的推荐下一步。
