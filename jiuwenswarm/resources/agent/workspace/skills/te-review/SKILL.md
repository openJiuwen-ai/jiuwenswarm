# TE-Review（对抗性审稿）

## 职责

模拟 Stanford Agentic Reviewer 的 ICLR 审稿视角，对论文做一轮严格自审。
**目标不是给论文说好话，而是找出它最可能被拒的理由。**

## 输入

- `{PROJECT_DIR}/paper/main.tex`、`paper/main.pdf`
- `{PROJECT_DIR}/outputs/results/`（用于核对论文中的数字是否真的来自结果文件）

## 流程

1. **数字复核**：随机抽取论文中的 10 个数字，逐一回到 `outputs/results/`
   核对。任何一个对不上即记为 **must-fix**。
2. **引用复核**：抽查引用是否真实存在、归属是否正确。
3. **按四个维度审稿**，每个维度先写「最严厉的反对意见」，再写回应：
   - *Novelty*：与最近邻工作的差别是否成立？是否只是把已知技巧换了个名字？
   - *Experiment sufficiency*：基线是否公平（NFE 是否匹配）？是否缺少必要的
     消融？统计口径是否足以支撑断言？
   - *Conclusion reliability*：结论是否超出证据？规模局限是否被隐瞒？
     负结果是否被选择性呈现？
   - *Clarity*：记号是否自洽？图表能否独立理解？
4. **对本主题额外强制检查**（这些是最容易被审稿人抓住的点）：
   - 声称的提升是否在**匹配 NFE** 下取得？
   - 若论文报告了编辑机制无效，是否给出了机制层面的独立证据，
     而不是仅凭「不显著」？
   - 记账口径是否在论文中明确定义（尤其 `fix_rate` 的分母）？
   - 若某结论依赖小模型，是否在 Limitations 中写明，并给出「为什么它可能是
     结构性的」的论证而非辩解？
5. 只修 **must-fix**，不重写论文；修改后重新编译并确认无未解析引用。

## 输出（写入 {PROJECT_DIR}/outputs/）

- `stage5-review.md`：审稿意见（按维度）、must-fix 清单、已修复项、遗留风险
- `stage-5-done.txt`：最后写入，内容为 `DONE`

## 质量门

- must-fix 清单中每一项都有「原文位置 → 问题 → 修法」
- 至少给出 3 条**未被修复**的遗留风险（诚实标注，供审稿人判断）
- 修改后 PDF 重新编译成功
