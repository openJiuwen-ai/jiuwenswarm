# TE-Planning（规划模块）

## 职责

把假设翻译成可执行、可被单次运行检验的实验方案。这一阶段定下的规矩决定了
后面所有数字是否可信，因此**口径比脚本更重要**。

## 输入

- `{PROJECT_DIR}/outputs/stage1-ideation.md`（假设表）

## 流程

1. **把主张拆成链条**。逐环给出「主张 → 实验编号 → 被否证条件」。
   链条中最弱的一环决定论文强度，必须显式标出哪一环是弱环。
2. **确定算力口径**：本领域统一用 **NFE**（去噪器前向次数），因为它直接决定
   推理墙钟时间。所有比较必须在**匹配 NFE** 下进行，否则结论无意义。
3. **确定模型与数据**：规模必须小到能在评测机上完整复现（无 GPU）。
   写明已知的规模局限，以及哪些结论是结构性的、哪些依赖规模。
4. **确定评估口径**，以下四条必须写进方案（它们是本主题最容易出错的地方）：
   - **配对案例**：案例流的随机种子只由 `(mask_frac, seq_len, repeat)` 决定，
     **不含解码配置**。这样每个配置评的是同一批窗口，可以做配对检验。
   - **分离解码随机性**：解码随机性用另一条依赖配置的随机流，避免采样器
     被意外相关。
   - **指标定义**：准确率只统计**需要生成**（初始被掩码）的位置。统计全部位置
     会加上一个巨大常数并压缩所有方法差异。
   - **统计**：配对 t 检验 + bootstrap 95% CI + 胜/负计数 + 多重比较校正。
     显著但微小的差异必须如实报告为「显著但微小」。
5. **写出编辑动作的记账定义**（否则数字一定错）：
   - 一次编辑 = 一个**额度（slot）**。重掩码模式下 token 先被抹掉、之后才被
     重新预测，**必须在编辑「结算」时统计，而不是在抹除时统计**；在抹除时统计
     测的是调度而非算子。
   - `fix` = 编辑前错、编辑后对；`break` = 编辑前对、编辑后错。
   - `fix_rate = fixes / (fixes + breaks)`，**0.5 是盈亏平衡线**，低于即净破坏。
   - 另记 `recommit rate` = 模型重新预测出自己已提交 token 的概率，用**真正的
     leave-one-out 重掩码**测（token 在场时预测不是算子所查询的条件分布）。
6. **列出脚本清单**，并指定 `smoke_test.py`：用随机权重 checkpoint 以极小样本量
   跑通每个脚本，使语法与接线错误在秒级暴露，而不是在长跑 40 分钟后。

## 输出（写入 {PROJECT_DIR}/outputs/）

- `stage2-plan.md`：主张链条表、模型/数据、配置空间表、评估口径、记账定义、
  脚本清单、**「若立论失败将报告什么」**章节
- `stage-2-done.txt`：最后写入，内容为 `DONE`

## 质量门

- 每个配置空间旋钮都列出了具体取值
- 「若立论失败将报告什么」必须给出可发表的负结果形态，而不是留空
- 记账定义写清楚到可以照着实现
