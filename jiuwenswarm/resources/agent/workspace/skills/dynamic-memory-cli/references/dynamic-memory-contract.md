# Dynamic Memory Contract

## Formal state

The SQLite database owns the atomically published tuple:

```text
(memory_revision, snapshot_revision, covered_through, snapshot, UT set, Built index)
```

UT build state has exactly two values: `pending` and `built`. A task-local proposal file is not published memory. A UT becomes formal Long-term Memory only after `publish-pending` commits it with the Snapshot and cursor.

## Proposal schema

```json
{
  "base_memory_revision": 4,
  "base_snapshot_revision": 7,
  "from_cursor": 81,
  "to_cursor": 120,
  "snapshot": {
    "resident_memory": [],
    "recent_context": [],
    "current_state": [],
    "completed": [],
    "next_actions": [],
    "constraints": []
  },
  "changed_uts": [
    {
      "action": "upsert",
      "id": "ut-stable-id",
      "memory_id": "memory-stable-id",
      "priority": 80,
      "content": "Answer-bearing durable memory.",
      "queries": ["future query one", "future query two"],
      "must_include": ["durable memory"],
      "evidence_refs": ["raw-history:event-101"],
      "source": "session-id",
      "tags": ["decision"]
    }
  ],
  "evidence_refs": ["raw-history:range-81-120"],
  "semantic_statement": "The Snapshot and UT changes preserve every future-relevant effect in the frozen range."
}
```

`from_cursor` must equal the current `covered_through + 1`, and `to_cursor` must not move backward. Empty `changed_uts` is valid but still requires a non-empty Snapshot, evidence references, and semantic statement.

## Retrieval

Pending search scores the current UT content and Agent-authored queries directly. Built search scores only the committed Built document whose content hash still matches the current UT. Merge by stable UT ID; current Pending content shadows a stale Built artifact. Return complete memory content and `build_state`.

Pending and Built have the same target semantics. Built-only validation proves every frozen UT query retrieves its own complete content with every `must_include` assertion present. It deliberately disables Pending fallback.

## Concurrency and recovery

Use SQLite `BEGIN IMMEDIATE` transactions for publication and migration. A frozen build batch includes stable IDs, exact content, and content hashes. `build-pending` skips or rejects any item changed since freezing; it never clears unrelated Pending UTs. Failure leaves the prior published state searchable.

The Harness may retry a proposal only against the revisions and cursor on which it was based. A stale proposal must be regenerated by the extraction Agent.
