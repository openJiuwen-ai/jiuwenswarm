# Writing
Pipeline: input inventory → evidence/readiness → versioned paper contract → visual planning/review → chapter contracts → specialized English writers and handoffs → integration → claim/literature/argument/visual review → coordinated revision → title and abstract → final-paper review → controlled TeX → Tectonic → PDF validation.

`visual_planner` may select only registered templates and evidence advertised by `assets/visual_capability_catalog.json`. It first considers an auditable Module-3 figure and reuses it when the figure is inside the registered artifact root, is manifest-listed, has exactly one experiment scope, and declares its displayed metrics and caption assertions. A cross-experiment or semantically undocumented Module-3 image is rejected rather than relabelled; only then may the deterministic renderer create a different evidence role from source records. `visual_reviewer` checks the realized manifest before prose is written. The renderer, not an LLM, reads source records and creates PDF/PNG/TeX assets plus data snapshots. Missing data blocks only the affected visual; it never licenses a fabricated chart.

Generated figures use tight export bounds and a height cap so a short horizontal schematic does not consume a mostly blank page. Result tables keep a readable `\footnotesize` floor: they never use `resizebox`, abbreviate display-only labels with a provenance map, and split more than three metrics into vertical panels instead of overflowing or shrinking type. Captions are compact locators; run-level IDs and complete display-label mappings remain in the asset manifest and evidence snapshots.

All writers consume a versioned paper contract. Conflicts are recorded rather than silently resolved; a final reviewer only sees the integrated manuscript after title and abstract exist. Long JSON responses are validated for balanced delimiters before tolerant JSON repair; a detected truncation receives one bounded compact retry rather than silently becoming an incomplete section. Section-writing defaults to three attempts only when no explicit `WRITING_AGENT_MAX_ATTEMPTS` is configured; an operator-set limit always wins. Every terminal result, including input, protocol and controlled-audit exits, carries a stable `verdict` for callers.

States: `success` means verified evidence, deterministic integrity checks and PDF validation have passed. In the default draft-release policy, bounded and explicitly disclosed non-blocking editorial findings (for example wording, caption clarity or layout) may accompany a generated PDF as warnings; false/untraceable claims, evidence conflicts, invalid citations, missing required artifacts and failed PDF validation never do. Set `WRITING_RELEASE_POLICY=strict` when every specialized review must pass before delivery. `synthetic_test` is development-only; `needs_experiment_data` produces ledgers but no results paper. PDF validation uses an installed Python reader when available and otherwise performs a Poppler structural fallback; unavailable text extraction is disclosed as a warning rather than being misreported as a malformed PDF.

Hypothesis state separates execution from truth: `planned` means its linked experiment has not completed, while `evaluated` means the linked experiment ran. `evaluated` never by itself means supported. Positive prose must use a separately supported claim and remain scoped to the recorded dataset and protocol. The deterministic audit rejects categorical proof/confirmation language and guessed numeric Figure/Table references even if an LLM reviewer returns pass.
