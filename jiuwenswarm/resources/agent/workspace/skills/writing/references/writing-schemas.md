# Structured contracts

Every writer or integration `conflicts` item must be a structured blocking contradiction with non-empty `conflict_id`, `statement`, `owner`, `required_action`, `next_action`, and `status` (`unresolved` or `resolved`). Ordinary caveats, optional gaps, and follow-up notes belong in `open_dependencies`, not in `conflicts`; anonymous conflict strings are invalid.

`PaperContract` is the versioned factual source shared by every writing role. It contains stable claim IDs, their evidence status and experiment scope, deterministic aggregates, citation IDs, section owners, and the argument map. Agents may add only validated planning or prose metadata; they may not alter factual evidence.

`ChapterContract = {contract_version, section_id, owner, purpose, allowed_claims, allowed_claim_ids, allowed_assets, allowed_citation_ids, experiment_scopes, prohibitions, dependencies}`.

`Section = {section_id, title, paragraphs:[{paragraph_id,rhetorical_role,text,claim_ids,asset_ids,evidence_assertions}]}`. `claim_ids` may contain only IDs explicitly allowed by that chapter contract; fact/configuration/analysis/citation identifiers are separate namespaces and must never be placed there. An empirical mean uses `{type:"metric_value", aggregate_id, experiment_id, method, metric, statistic:"mean", run_count, value, claim_id?}`. A comparison additionally binds `comparison_aggregate_id` and `comparison_method`. The aggregate identity and run count are indivisible: configured seeds do not prove repeated execution, a per-run value is not a mean, training time is not total wall-clock time, and unmeasured parameter counts must not enter prose.

Every specialist writer returns `{section, chapter_handoff}`. `chapter_handoff` records the consumed claim/asset IDs, defined terms, open dependencies, and conflicts. The integration editor returns `{sections, integration_handoff}`. Specialized reviewers return `{verdict, issues}`; the revision coordinator returns `{verdict, actions, conflicts}`. When an evidence-located issue survives a real target change, `revision_adjudicator` returns `{verdict:"repair|review_quality_failure|failed", repairs:[{target_kind,target_id,paragraph_id,claim_id,evidence_kind,evidence_id,required_change,acceptance_criteria}]}`. A `repair` must cover every repeated issue exactly once and is applied only once per fingerprint. Formatter returns `{title, abstract, claim_ids}`. The final-paper reviewer uses the reviewer contract only after title and abstract exist.
