# 版面契约

## 权威来源

`../references/template.pptx` 是本 skill 当前的模板事实来源。它是一个中性白板模板：
Office 默认主题，无 Logo、无背景装饰、无密级框架。若用户提供自己的模板，以用户文件为准，
并重新提取本契约。

当前模板包含：

- 16:9 画布，原始尺寸 13.333 × 7.50 英寸；
- 1 个 Slide Master；
- 11 个 Slide Layout（Office 标准版式，空白版式是 `slideLayout7.xml`）；
- 5 张骨架页：封面、目录、两张空白内容页、结束页。

模板由 `../scripts/make_blank_template.py` 生成，可随时重新生成。

空白内容页揭示核心边界：模板固定页面身份与外围框架，内容区域有意开放给设计者。

## 必须继承

### 页面身份

- 使用 16:9 画布；合并进模板或复用原始 Master/Layout 时使用模板的原始画布尺寸。
- 保持封面、目录、内容页、结束页之间的视觉家族关系。
- 标准内容页保留固定底部框架：主题色一句话总结条、左下页码。

### 封面固定元素

封面无论使用组件、模板原页还是自绘复刻，都必须满足：

- 主标题使用主题色 `#4472C4`，不得使用深灰、黑色或模板占位符的默认颜色；
- 主标题保持单行，过长时缩小字号或改写，不折行、不缩到不可读；
- 部门、汇报人、日期使用深色正文，只承担次级信息，不与主标题争夺层级。

### 内容页副标题

`addSlideTitle` 的 `subtitle` 是这一页的第二句话，不是参考文献条目。

- **不得以作者引用开头。** `Wang et al., 2024（arXiv:2406.04692）` 这种写法把版面最显眼的
  第二行让给了出处，而出处读者并不需要在这里知道——它已经由页脚的 `addSourceNote` 承担。
- **要提作品就写全名。** 写 `Mixture-of-Agents Enhances Large Language Model Capabilities`，
  不写 `Wang et al., 2024`。全名本身就说明了这一页依据什么，作者缩写不说明任何事。
- **副标题要有实质内容**：交代这一页的范围、口径、机制或结论前提。
  剥掉 `et al.` / `arXiv:xxxx.xxxxx` / 年份 / `§x.x` 之后，剩下的实质文字不得少于 6 个视觉字。
- **宽度是硬约束**：框宽 9.0"、10.5pt、单行高 0.24"，正文区从 `y=0.95"` 起，只有 0.03" 余量。
  按 CJK 记 1em、ASCII 记 0.55em 计算，单行容量约 61 em，超出会压到正文。
  论文全名本身就占约 33 em，所以中文说明尾巴要相应精简。

```
✗ Wang et al., 2024（arXiv:2406.04692）—— 每个 agent 把上一层全部输出当作辅助信息，逐层精炼直至聚合
✓ Mixture-of-Agents Enhances Large Language Model Capabilities（arXiv:2406.04692）—— 逐层精炼直至聚合
```

该规则由 `audit_pptx.py --lock execution-lock.json` 强制，作用于 `role: "standard-content"` 的页面。

### 目录页

**必须调用 `addTocSlide(pres, { title, sections })`，不得自绘。** 目录只有三层文字：
22pt 页面标题、13pt 编号徽标、16pt 章节标题。

- **不得加第四层。** 反复出现的偏差是照抄 `addTocSlide` 的几何、再在每条标题下补一行
  ~10pt 灰色描述。组件的 `sections` 只接受 `{num, title}`，多余字段会被丢弃——这是设计如此，
  不是缺陷；不要为了加描述行而改组件或改成自绘。
- **章节标题写成描述性短语，不是四字标签。** 目录是全篇唯一的结构预告，标题本身就要交代
  这一章讲什么：写「核心架构设计与 MOA 编排机制」「技术栈与多模型推理配置」，
  不写「架构」「技术栈」。10–18 字为宜。正因为标题已经承载了信息，才不需要描述行。
- 最多 7 条；超出时在 `slides.js` 里合并章节，不改组件。

该规则由 `audit_pptx.py --lock execution-lock.json` 强制：execution lock 中 `role: "toc"`
的页面若出现低于编号徽标层级的文字，判硬错误。

### 标准内容页固定底部框架

每张标准内容页必须且只能出现一次以下元素；封面、目录、分节页和结束页使用各自模板，不叠加这一框架：

- 总结条：页面底部页脚上方的通栏主题色块，白色粗体居中，只承载本页一句话结论；
- 页脚：左下页码。

密级文字是**可选**的：`addSlideFooter` / `addContentChrome` 的 `classification` 参数
默认不传就不绘制，需要密级标识时才传入（如 `"Internal Use Only"`）。

10 × 5.625 兼容坐标固定为：总结条 `x=0.30, y=4.70, w=9.40, h=0.40`；页码 `x=0.60, y=5.21`；
密级（如启用）`x=0.90, y=5.21`。内容必须在 `y=4.65` 以上结束。

使用原始 13.333 × 7.5 Master/Layout 时，优先继承母版已有页脚对象；总结条及缺失的底部对象
按同一相对位置等比实现，不得自行改变层级与位置。当前空白内容版式是 `slideLayout7.xml`。

### 颜色

模板主题的核心色：

| 角色 | 色值 | 用途 |
|---|---|---|
| accent | `#4472C4` | 标题、关键结论、关键数据、强调线、总结条 |
| accent mid | `#8FAADC` | 受控的次级强调，不与主色争夺层级 |
| accent light | `#B4C7E7` | 弱化的同族填充 |
| dark text | `#1D1D1A` | 主体文字 |
| white | `#FFFFFF` | 页面底色与反白文字 |
| neutral dark | `#232323` | 深色中性元素 |
| neutral mid | `#666666` | 次级文字、坐标轴、注释 |
| neutral light | `#919191` / `#C4C4C4` | 分隔、弱化数据、边框 |
| warning | `#C00000` | 真正的告警语义，不作装饰使用 |

绿、黄、橙等辅助色仅在数据或类别编码有真实语义时使用。不得把主题色理解成每页都要用齐的调色板。

主题色定义在 `../scripts/components.js` 的 `THEME`。改主题色需要同步三处：
`THEME`、`execution-lock-reference.json` 的 `brand.colors`、
`../scripts/validate-execution-lock.js` 的 `brandConstants`。

### 字体

- 模板拉丁字体为 Arial。
- 中文优先使用 Microsoft YaHei；不可用时选择清晰的无衬线 CJK 字体并在交付时说明替代。
- 标题、正文、注释、来源和页脚维持稳定的 deck 级层级；同一角色不因页面拥挤而随意缩放。

## 内容区自由度

内容页可以根据内容采用：

- 自由文本排版；
- 非对称或对称分栏；
- 全幅或局部图表；
- 架构、流程、关系或因果图；
- 论文原图、用户图片或合规网络图片；
- 表格、时间轴、地图、照片叙事；
- 大数字或强结论主导的版面；
- 自定义 PptxGenJS/SVG 构图。

除固定底部框架外，模板不要求：左图右文、固定区域数量、固定卡片数量或固定内容组件。

## 实现边界

`../scripts/components.js` 使用 10 × 5.625 英寸坐标系按比例复刻模板语言，适合生成可编辑内容；
它不是原始 Master/Layout 本身。新建 deck 默认用
`merge_slides.py --source-layout-mode template --template-layout slideLayout7.xml`
等比放大并继承模板版式。此模式调用 `addContentChrome(..., { footerMode: "master" })`，
避免与母版页脚重复。

`--source-layout-mode source` 只作为旧项目兼容开关：它会复制 PptxGenJS 的母版和版式，
不能被描述为「继承模板母版的输出」。

组件实现与模板冲突时，以模板为准并修正组件。参考图片与模板冲突时，以模板为准，
参考图只影响内容区设计。
