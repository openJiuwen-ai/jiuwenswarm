# 上下文驾驶舱

看清一次会话里上下文用了多少、由什么组成，以及每一轮和每次模型请求的变化。

## 功能

- **当前上下文**：展示已观测的输入 Token、窗口容量与占用率；数据缺失时显示未知，不用估算冒充实际用量。
- **上下文组成**：按系统提示词、工具定义、技能、消息给出分类估算，占比只按已知分类合计。
- **逐请求趋势**：最近 24 次模型请求的输入 Token 与相邻变化量，可展开查看模型、耗时、输出与缓存，以及这段时间出现的工具调用。
- **Agent Loop 执行脉络**：模型步骤和工具批次的状态、耗时与用量，工具参数与结果以脱敏摘要呈现。
- **完成轮次与消息浏览**：最近 12 个完成轮次的用量记录，以及最近 12 条会话消息，每条最多 600 字。

## 生效机制

- 安装后无需配置。在聊天输入框上方点击「上下文观察」打开侧边面板，之后的轮次会自动更新；也可以随时点击「刷新」重新读取。
- 插件订阅 `context.usage.updated`，在每个轮次结束后刷新占用与用量；订阅 `turn.step` 和 `tool.call`，持续补充执行脉络。
- 数据全部来自公开的会话 Ops（usage / model / turns / messages），只读使用，不介入模型推理和工具执行。
- 最近 12 个完成轮次保存在本地，重启后恢复；执行脉络与逐请求趋势只在本次运行内保留。不保存消息正文。
- 分类组成是估算，未知数据保持未知；页面资源随插件交付，不依赖 CDN 或外部服务。

## 优势

- 长会话里快速判断上下文是否吃紧，决定何时清理或新建会话。
- 某一轮变慢时，能顺着执行脉络看到模型步骤和工具调用的耗时。
- 换模型或换 Agent 后，直接对比输入规模的变化，评估上下文使用是否合理。
