# persona markdown 规范

persona 文件是 agent 的角色定义，路径固定为 `persona/<agent-name>.md`。**纯 markdown，无 frontmatter**——不像 skill 的 SKILL.md，persona 不靠 frontmatter 被识别，靠 manifest 的 `persona.dir` 指向。

## 正文结构（四段式）

```markdown
# {角色名} - {人设名}

{一段角色描述：你是谁、服务谁、核心任务是什么、用什么语气和风格工作}

## 核心能力
1. **{能力1}**：{描述，说清楚能干什么、怎么干}
2. **{能力2}**：{描述}
3. **{能力3}**：{描述}

## 工作流程
1. **{阶段1}**：{步骤，说明何时进入、做什么、调用什么工具/skill}
2. **{阶段2}**：{步骤}
3. **{阶段3}**：{步骤}

## 输出规范
- {规范1：输出格式、详略、风格}
- {规范2}
- {规范3}

## 注意事项
- {约束/边界条件，如：不是医生、不推极端方案、数据不外传等}
- {边界2}
```

## 写作要点

1. **开头一句话定调**：第一段必须让读者（和 LLM）立刻明白「这是谁、擅长什么」。
2. **工作流程要有触发条件**：每个阶段写明「什么时候进入」，如「首次建档」「用户问练什么」「用户报体重」。
3. **输出规范约束风格**：明确语气（直接/鼓励/不说教）、详略（一屏内/附数字依据）、格式（编号列表/表格）。
4. **注意事项划边界**：什么情况拒绝、什么不做、数据存在哪、禁止手改什么文件。
5. **如果 agent 带 tool**：persona 里要写明「档案读写一律通过 `{tool_name}` 工具完成，禁止手改 {数据文件}」，把工具调用嵌入流程而不是另起一段。

## 关键约束

- **文件名 = agent-name**：`persona/<agent-name>.md`，不要用通用名如 `persona.md`。
- **无 frontmatter**：persona 是纯正文，不要加 `---` YAML 头。
- **标题用角色名**：第一行 `# {角色名} - {人设名}`；人设名只属于 persona 正文，不写入 manifest 的唯一标识。
