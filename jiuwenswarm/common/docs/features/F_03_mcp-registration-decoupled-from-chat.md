## 背景

注册面（`mcp.server.*` + `mcp_server_list`）让对话路径只读工具缓存、不做工具发现，但只
覆盖了凭证写在注册配置里的用户连接器。凭证每个请求都不同的服务仍走旧通道
（`office_claw_mcp`、`request_mcp_servers`），每条对话都要起进程列一次工具：office-claw
的调用 ID 与回调令牌在进程环境变量里，pptx-mcp 的能力令牌在请求头里，IAM 连接器的临时
凭证在环境变量里。首条对话的首字延迟里，这段工具发现是占比最大的一项。

要把这些服务也放进注册面，注册配置里就不能有随请求变化的值。本特性让注册项只声明
「执行时需要哪些参数、怎么传给服务」，参数值随每条对话请求下发。

## 决策

**声明与取值分开。** 注册项用 `runtime_params` 声明参数名与传入方式，对话请求用
`mcp_runtime_params` 给值。声明计入配置指纹；值只绑定在本轮的工具对象上，不进注册表、
不进工具缓存、不落盘、不进日志，池键只用值的 sha256 摘要。

**三种传入方式，各自对应一种进程或连接模型。**

| 方式 | 传输 | 怎么传 | 进程 / 连接 |
|---|---|---|---|
| `meta` | stdio | 每次 `tools/call` 的 `_meta` | 跨请求共享；按分组键摘要分组，组内最多 N 个串行 worker |
| `header` | sse / streamable-http | 建连时的请求头 | 参数值相同才共用；可声明随请求独占、请求结束即关 |
| `env` | stdio | 启动进程时的环境变量 | 参数值相同才共用 |

`meta` 是首字延迟收益的来源：进程不再随请求起停，参数随每次调用走。`header` 与 `env`
的参数只能在建连或启动时给，所以按参数值指纹区分连接，收益来自省掉每轮的工具发现。

**能力标识只报已实现的部分。** `mcp.server.list` 的应答带 `capabilities`，由模块内的
支持集合常量生成；未放开的声明在注册时拒绝。这样可以分阶段合入：每个阶段只放开自己实现
完的那一项，调用方按能力逐个服务切换，不会出现「声明被接受但参数没下发」。

**系统条目有属主。** `system: true` 的条目记录注册它的连接，属主在线时其它连接不能改
配置或删除，属主断开后可以接管。迁自旧通道的两个 office-claw 条目额外沿用启动身份校验
（同一个函数、同一份环境变量白名单），声明为 `env` 的执行时参数名也必须在这份白名单内；
并以严格方式装载：先于其它条目占名，工具名冲突时整组不装。

**对话请求里的失败只影响出问题的那个服务。** 缺必填参数或参数值不合法时跳过该服务并在
连接器目录结果里注明，其它服务与对话照常。只有字段形状非法才让整个请求失败。

**扫描参数用完即弃。** 列工具需要凭证的服务，注册、更新、复扫时可带一次性的
`scan_params`。它并入本次扫描用的配置副本，扫描返回的连接参数去掉这些值之后才入缓存。

**复扫经现有连接进行。** `mcp.server.rescan` 在配置不变时重新列工具，失败保留原缓存，
同一服务并发的复扫合并为一次。三种自动复扫（stdio 服务的 `tools/list_changed`、worker
重建、周期扫描遇到凭证随请求下发的远程服务）都经活动 worker 的会话列工具，不另起进程或
连接。

**调用身份的读取收口到一个函数。** 调用 ID 与投递线程原来散落在三处直接读进程环境变量。
注册面条目的身份在执行时参数里，所以统一经 `office_claw_tool_identity_value` 读取，先看
执行时参数、再看环境变量，新旧通道的一致性校验共用同一套逻辑。

**工具对象的构造收口到一个函数。** 对话装载与进程内扩展的按需装载都经
`create_request_scoped_mcp_tool` 构造，扩展用 `build_registered_mcp_tools` 得到的工具对象
与对话装载路径的在标识、参数、连接模型上完全相同。

## 拒绝的方案

- **把参数值存进注册配置、每轮 `mcp.server.update`。** 改配置会触发重新扫描并退役全部
  worker，等于把工具发现从对话路径挪到了它前面，延迟没有减少；并发会话还会互相覆盖。
- **AgentServer 自己缓存 office-claw 的工具定义，进程仍随请求起停。** 省掉了列工具，但
  进程冷启动还在，而且缓存的新鲜度要靠文件指纹猜。旧通道已经这样做过，收益有限。
- **用 `tools/call` 的参数传凭证。** 凭证会出现在模型可见的工具参数、对话历史和日志里。
- **`meta` 方式不分组，所有用户共用一个进程。** 服务端按进程缓存的用户态会串；分组键
  摘要让不同用户落在不同进程上，组内仍可复用。
- **`header` 方式固定一条连接、每次调用改请求头。** 高层 MCP client 在建连时确定请求头，
  连接上还有服务端会话状态，换头等于换身份却复用旧会话。
- **缺参数时让整个对话请求失败。** 一个连接器的令牌过期不应让用户发不出消息。
- **能力标识一次性报全量。** 分阶段合入时会有一段时间声明被接受而参数不下发，调用方切过去
  之后工具调用全部失败，且无法从协议上察觉。
- **系统条目按条目名硬编码。** 原来有两处判断条目名是否等于 `office-claw`，
  `office-claw-single-agent` 进注册面后都会失效。改为按 `system` 声明判断，只有启动身份
  校验与严格装载仍按名字限定，因为它们依赖进程启动时登记的那一份身份。

## 验证

- 声明校验 20 类非法用例各返回对应错误码；不带新字段的注册结果除扫描失败多一个 `code`
  外与原来相同。
- 真实 stdio 回显服务：同组 3 个并发调用加另一组 1 个调用，各自收到自己的 `_meta`；同组
  只起 2 个进程，第 3 个调用排队；占位全部归还。
- 真实 stdio 服务中途增加工具并发 `tools/list_changed`：缓存版本加一；换掉 worker 后缓存
  跟随新进程的工具列表。
- 扫描参数在注册表、工具缓存、`list` / `get` 应答里都不出现；同名的固定请求头被放回。
- 审批恢复：同一会话的恢复请求带新的调用 ID，短名映射、资源管理器里的工具对象、注册的
  调用 ID 都指向恢复请求，先清理后注册与先注册后清理两种次序结果相同。
- 进程内扩展用公开函数得到的工具对象与对话装载路径逐字段相同。
- 现有 MCP 回归（注册表、请求级 office-claw、远程连接器、DeepResearch 委派、团队可见性）
  全部通过。

## 已知遗留

- 请求头是否到达对端只验证到「并入 worker 的连接参数」，没有起真实 HTTP 服务校验。
- 远程服务的 `tools/list_changed` 不处理，靠周期扫描与 `mcp.server.rescan` 收敛。
- worker 总数没有硬上限，为「活跃分组数 × 每组上限」加上各参数指纹的连接，靠空闲回收
  收敛。多用户共用一个 AgentServer 时需要再评估。
- 每个请求的值都不同的 `header` 凭证（带时间戳的预签名头）必须声明
  `connection_scope: request`，否则每个请求留下一条等空闲回收的连接。协议上不强制。
- 经 HTTP 入口注册的系统条目属主是常量，不会随连接断开释放，WS 连接无法接管。
- 连接器目录注解用注册名最后一个冒号之后的部分作为连接器名，依赖调用方的命名规则。
- 并发合并的复扫用先到请求的扫描参数，后到请求自带的不生效。
- 周期扫描经活动连接复扫凭证随请求下发的远程服务，结果写入全局缓存，适用于工具列表与
  凭证无关的服务。按租户裁剪工具列表的服务会被某一个请求的视角覆盖，需要按租户隔离的工具
  缓存时另行支持。这类服务逐个串行复扫，单个上限 30s。
- 旧通道（`office_claw_mcp`、`request_mcp_servers`）完整保留，待调用方全部切换后另行清理。
