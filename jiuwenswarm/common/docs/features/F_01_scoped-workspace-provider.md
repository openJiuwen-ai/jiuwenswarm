## 背景

PR6170 的工作区目录改名分散在多个后端调用点。第一步已将这些路径收口到
`get_agent_workspace_dir(agent_root=...)`。第二步需要让租户明确的路径也经过
已有 WORKSPACE Provider，并保持无插件时的路径结果和原有显式最终路径优先级。

## 决策

- Provider 收到当前解析的 Agent 根和租户身份；解析其他作用域时清除无关 bound workspace，
  不修改请求的 ContextVar，也不缓存跨请求的 Provider 结果。
- 原有无参 getter 优先级不变；带作用域调用失败时回到原作用域的默认拼接结果。
- 历史迁移、相对路径、全局缓存和启动检查使用 `use_provider=False`。目录改名迁移
  仍指向原默认新目录，避免把“插件返回路径”隐式变成“搬迁用户数据”。
- Provider 加载完成后补种默认插件工作区；租户池按完整租户身份补种其工作区。
  播种只补缺失模板，不覆盖用户文件。
- Agent 工作区、Agent 根和租户根分别解析，不能从插件工作区的父目录猜测租户身份。
- Web 继续使用原逻辑路径和 zone。后端挂载插件物理工作区并在该根内执行安全校验，
  外置工作区纳入原租户配额缓存，不修改阈值或删除白名单。
- 旧文件接口的兼容根不同于租户运行时根：单独传入运行时 PathContext，保证按 Agent 根
  改名的 Provider 与运行时一致；插件无覆盖时仍回到原文件接口兼容目录。

## 拒绝的方案

- 将所有 `agent_root` 调用无差别交给 Provider：会改变迁移目标、相对配置和 bootstrap。
- 把完整显式 workspace 当作作用域提示：会破坏已有“显式最终路径优先”契约。
- 放宽 commonpath 或删除 zone：会扩大可访问/可删除范围，不能作为路径插件适配手段。
- 修改前端路径常量或服务级 received_files 存储层级：与本次工作区路径接管无关。

## 验证

按 N15 和 N12 验证路径回退、上下文、并发隔离、播种、逻辑路径映射与删除安全边界。
新增测试和路径核心文件的静态检查通过。全体改动 Python 文件的未定义名称检查发现
`app_gateway.py` 中已有的 `RoutingTarget` 告警；在修改前 HEAD 中可复现，本次未扩大修复范围。

## 已知边界

路径插件不负责历史数据搬迁。插件加载前仍准备默认工作区；TUI 本地固定路径提示、
包内模板与 Node 安装脚本沿用默认布局。独立覆盖 MEMORY、SKILLS 等子类别时，
插件需要保证其安全边界与 WORKSPACE 一致；本次挂载映射针对 WORKSPACE 根。
