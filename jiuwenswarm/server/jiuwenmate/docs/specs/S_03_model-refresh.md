## 1. 范围与适用条件

适用于本地命名空间的 Persistent 同事模型热更新。复用既有配置持久化与个人版运行时重载，不改变个人版语义、草稿显式发布边界或执行中的 Request 版本。此处状态不是用户任务状态，也不是模型连通性检查。

## 2. 数据与接口契约

`jiuwenmate.models.list` 的模型项可携带公开厂商标识 `vendor_key`，取自同一配置快照中对应模型的客户端配置，仅用于图标展示。`provider` 表示客户端协议实现，不代替厂商身份；缺少 `vendor_key` 时沿用公共图标组件的自定义模型分类。响应不携带地址、密钥或其他连接字段。

管理页统一编辑链路读取最新设置后仅合并本次修改，保留模型选择，由服务端校验其有效性；编辑不得因前端目录未加载而将原选择置空。没有模型时仅调用设置保存并读取最新员工状态，作为未发布草稿返回，不调用 `publish`；有模型时继续保存并发布，发布失败照常上报。服务端 `publish` 对缺失模型的拒绝规则不变。

员工只读视图的 `has_unpublished_model_changes` 为布尔值，比较当前所选模型与既有发布设置快照；模型非空且尚无发布版本，或快照中的模型选择不同时为真。整体草稿修订号 `has_unpublished_changes` 不代表模型变化。未选择模型时为假；历史数据已有版本但无发布设置快照时不推断差异。该字段不存储凭据、不增加持久化列。

模型保存先持久化配置并执行原有运行时重载，再安排 Persistent 后台刷新；保存响应不等待同事全量重发布。`applied_without_restart` 只表示既有重载接受结果，不能证明 Persistent 同事全部生效。显式 `agent.reload_config` 的成功载荷附带 `persistent_model_refresh`，结构与下述查询一致；非模型 scope 不触发刷新。

`models.refresh_status` 为只读 Web RPC，请求参数 `{}`。Gateway 在共享目录和远程部署下都代理至持有队列的 AgentServer Worker；不可用时沿用代理的 `SERVICE_UNAVAILABLE` 错误，不从本地配置推断状态。查询不初始化数据库、同事或执行运行时。

| 成功载荷字段 | 类型与约束 | 含义 |
| --- | --- | --- |
| `status` | `pending`、`applied`、`failed` | 最新一代刷新未结束、已应用或未全部应用 |
| `generation` | 非负整数，进程内递增 | 用于区分连续通知；不是配置版本，不能跨 Worker 重启比较 |
| `detail` | 可选字符串 | 安全说明，不含配置、凭据或原始异常文本 |

首次尚未通知时返回 `applied / 0`，仅表示没有待处理通知，不证明所有存量快照已经复核。页面不为该初始值展示“全部已生效”。状态为 Worker 内存事实，不写入 `agents.sqlite3`。

## 3. 不变量与生命周期

1. 同一队列串行刷新；保存配置在入队前复制。运行中的一代完成后，只处理最新待处理配置，中间通知允许合并；旧一代不能覆盖最新一代状态。不含 `models` 的后续通知沿用最近一次明确提供的模型配置，不能丢弃尚未应用或失败的保存快照；只有新的模型配置才能替换它。
2. 有未发布修改的同事不自动发布。初始化创建、尚未经过用户编辑的默认员工（`is_default=true`、`revision=1`）例外：模型为空或历史发布快照仍为模板占位时，允许在有效默认模型就绪后完成首次初始化。选择更新和所有关联 Agent 的版本发布在同一事务完成；并发编辑或发布失败不得留下半更新设置。已绑定真实模型的员工不自动切换到其他默认模型。部分同事失败时保留原版本并继续其他同事，最新状态为 `failed`；不撤销已保存配置，也不把部分失败转换成保存失败或网关自动重启。
3. 新 Request 在后台刷新生效后读取新版本；刷新期间可读取尚未更新的版本。已受理的 Request 仍固定原版本。不同同事的发布不是全局事务。
4. 发布不准备或下载 tokenizer；可保留离线可选元数据，由 agent-core 在缺少本地 tokenizer 时使用其计数回退。不改 core 的容量、80% 换窗触发或新窗口 40% 上限。
5. 宿主正常关闭时等待已排队刷新结束，避免取消 await 后线程仍写库；适配器再次使用时允许继续刷新。进程强制终止不恢复内存通知，已有启动刷新从持久化模型配置重新生成快照。

合法状态转移：初始 `applied / 0`；新通知使任意状态变为新一代 `pending`；仅当前代完成可变为 `applied` 或 `failed`。下一次保存可从失败重新入队，不设置无限自动重试。

## 4. 页面与兼容边界

团队版模型列表与模型解析共用配置就绪过滤：排除占位模型名、示例地址、占位密钥及必要连接配置缺失的条目；显式无密钥认证仍可配置。过滤保留原列表下标，不重排 `name#index`。未配置模型时创建默认员工但不发布。再次进入团队版或配置后台刷新时均尝试恢复未完成的默认初始化；没有有效模型、存在用户草稿或发布失败时不返回员工全部刷新成功。

未发布且未选择模型的员工拒绝受理消息，返回 `MODEL_NOT_CONFIGURED`，不创建 Request；已选择模型但尚未发布时返回 `NOT_PUBLISHED`。私聊页面按这两个稳定错误码显示中英文配置引导，不向用户展示内部异常。员工未发布时保留可编辑草稿，禁用按钮和回车提交；发布后恢复发送。

团队版重连、返回设置页之外或收到 `models.updated` 后重新观察现有刷新状态；后台刷新结束后重新读取员工和模型清单。无可选模型时使用“尚未配置模型”提示，不展示虚假的默认模型。列表就绪只表示本地配置完整，不代表已验证远端模型连通性。

私聊输入区的模型选择与员工管理页共用员工设置保存、发布和重新读取链路。保存前读取最新设置，只合并本次编辑，保留人设、技能、权限等其他字段；私聊无论查看哪个 IM 工作区，都修改配置员工 ID，而非独立会话模型。成功后更新两处共用的员工状态；保存期间禁止重复切换，发布失败保留错误和草稿，已选择模型的未发布状态标记为“待生效”并允许重新选择原值重试；初始化尚未选择模型时只显示“尚未配置模型”，不显示“待生效”。已受理 Request 的配置版本不变。团队版模型菜单复用个人版的触发器、菜单、选中样式和图标规则，仅显示已配置模型与新增模型入口，不展示限时免费模型、领取入口或单一列表多余的“已配置模型”分组标题。

保存弹窗不等待刷新查询。自定义模型、模型组和免费模型设置成功保存后都通知页面重新查询；拒绝保存或无修改关闭不产生通知。页面独立查询并在 `pending` 时轮询；超时或断连不能显示为已应用，重连后重新查询；卸载或新查询使旧响应失效。失败保留独立状态提示，不掩盖配置保存结果。

新版前端连接没有此 RPC 的旧 Worker 时，显示状态不可用，不回退为“全部已应用”。旧版前端仍可消费原有保存字段，但不能据此判断后台完成；升级前后端应配套。此规约不提供多 Worker 的全局刷新一致性或实时生效时限。
