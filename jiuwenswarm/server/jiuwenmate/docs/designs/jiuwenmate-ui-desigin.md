# JiuwenMate 前端设计

## 1. 目标与范围

在现有 JiuwenSwarm Web 前端中新增一套独立的 JiuwenMate 页面，视觉以项目提供的 JiuwenMate 设计稿为准。第一阶段只实现页面呈现和页面内导航，使用固定演示数据，不连接后端接口，不实现真实创建、聊天、飞书接入、定时任务或统计计算。

JiuwenMate 不得改变个人版单 Agent、现有 Team 模式、会话恢复、WebSocket 或后端执行逻辑。用户通过左下角切换入口进入或退出 JiuwenMate；JiuwenMate 内部拥有自己的页面状态，退出后个人版原有状态保持不变。

## 2. 页面范围

第一阶段覆盖设计稿中的主要页面和可见状态：

1. 办公室介绍页：空态说明、三步介绍和创建入口。
2. 创建同事：专家选择页、自定义创建页以及创建完成后的页面跳转。
3. 同事工作台：同事列表、会话列表、频道消息列表、定时任务列表和右侧会话起始页。
4. 频道记录：群聊消息记录、频道切换和轨迹查看页。
5. 轨迹页面：时长/Token 页签、轮次/工具调用筛选、轨迹条目和原始记录展示。
6. 办公室：办公室成员、活跃数据和任务中心三个页签，其中成员和活跃数据按设计稿完整呈现，任务中心提供与设计稿风格一致的静态状态。
7. 公共入口：市场、资产、技能、扩展和设置继续使用现有 Swarm 页面，不复制已有实现。

设计稿中同一页面的悬停、选中、空态和弹出菜单作为组件状态实现，不为每一张截图创建一套重复页面。

## 3. 前端结构

新增 `src/features/jiuwenmate/`，由一个 JiuwenMate 外壳统一管理页面导航，避免继续扩大 `App.tsx`：

```text
features/jiuwenmate/
├── JiuwenMateApp.tsx           # JiuwenMate 外壳与页面切换
├── jiuwenmate.css              # JiuwenMate 布局，全部使用现有主题变量
├── mockData.ts                 # 同事、频道、轨迹、统计演示数据
├── types.ts                    # 纯前端页面状态类型
├── components/                # 导航、同事卡片、头像、页签等共享组件
└── pages/
    ├── OfficeIntroPage.tsx
    ├── ColleagueCreatePage.tsx
    ├── ColleagueWorkspacePage.tsx
    ├── ChannelTracePage.tsx
    └── OfficeDashboardPage.tsx
```

`App.tsx` 只增加 JiuwenMate 是否启用的顶层状态、左下角切换入口和 `JiuwenMateApp` 挂载点。JiuwenMate 需要打开既有市场、资产、技能、扩展或设置时，通过明确的回调交给现有 `activeNav`，不在 JiuwenMate 模块内部复制这些页面。

## 4. 页面状态与交互边界

页面交互只为展示设计状态服务：创建按钮进入创建页，模板卡片和自定义创建进入对应表单，提交后把静态同事加入当前页面状态；同事、页签、频道和轨迹条目可以选中；管理菜单、空态和筛选按钮可以展开或切换。刷新页面后恢复初始演示数据是预期行为。

聊天输入框、飞书授权、发送消息、上传文件、创建真实定时任务、统计查询和轨迹查询均不调用接口。不能工作的操作保持可见但使用禁用态或静态反馈，不伪造成功的后端结果。

## 5. 视觉规则

- 页面层级、留白、三栏宽度、卡片比例、圆角、字体层级、选中态和空态位置对齐设计稿。
- 业务组件不写死颜色，使用现有 `--color-*`、阴影和表面主题变量；设计稿中的角色插画和多色素材可作为图片资源保留原色。
- 图标优先使用仓库已有 SVG 或 `lucide-react`，新加入的单色 SVG 使用 `currentColor`。
- 新页面支持当前最小浏览器 Chrome 107，并保证窗口缩小时可滚动、侧栏不遮挡主内容。
- 所有新增交互元素和业务区域按前端 `AGENTS.md` 规则添加 `data-testid`，新增模块登记 `jiuwenmate` 前缀。
- 新增用户可见文本同时写入中文、英文 locale；设计稿中文是视觉验收主口径。

## 6. 验收方式

1. 从个人版左下角切换到 JiuwenMate，再切回个人版，个人版原页面和状态不被破坏。
2. 对照设计稿逐页截图，检查导航宽度、内容起点、卡片尺寸、页签、字体、边框、空态和弹层位置。
3. 验证创建页、同事工作台、频道记录、轨迹和办公室页签之间可以通过前端状态切换。
4. 验证页面在常用桌面尺寸和窄窗口下可访问，主内容可以滚动。
5. 运行 `npm run build`、相关前端测试和 `git diff --check`；第一阶段不新增后端测试。

## 7. 明确不做

- 不新增或修改后端接口。
- 不保存同事、会话、频道、定时任务或统计数据。
- 不实现模型调用、消息发送、飞书授权及 Agent 执行。
- 不修改现有个人版和集群模式的业务含义。
- 不直接引入 Pixso 导出的编译后网页代码；只复用设计图片和必要的视觉素材。
