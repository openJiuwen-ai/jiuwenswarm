# Todo 增量更新与并发一致性

多个工具从旧列表分别整表保存，会丢失已经成功的更新；回放旧事件又会使展示回退。现在 SDK 在同一存储对象上执行读、增量变换和条件原子替换，事件随提交 receipt 携带身份和 revision。宿主负责捕获执行归属、迁移特殊写入方、读取历史及恢复通知。

版本化格式显式激活，默认仍为数组。拒绝仅用模型提示、工具实例锁、UI 状态取最大值和读失败清表；它们无法同时解决持久化竞争、合法 reopen 与恢复。采用同文件元信息避免双文件提交，完整快照避免事件重放累计误差；代价是本地 CAS 读核对与配套版本发布。

DeepResearch 在 v1/v2 均通过实际宿主 Todo 工具的异步事务投影；启动时捕获工作流归属，v1 首次投影额外校验初始 hash/存在性，后续仅更新自己阶段。旧无绑定工作流不获得父表写权限，旧同步投影入口明确拒绝；工作流事件仍可继续。无事务能力的旧 SDK 不执行不安全的投影。

实现和本地证据见工作区 `Feat/req01-todo-edit/04-implementation.md` 与 `checkpoint/feat/req01-todo-edit/validation/`。非 editable SDK wheel 组合已验证，正式 lock/目标包仍待配套交付。隔离实例曾启动，用户登录未成功后明确暂缓实测，实例已停止；不记业务验收通过。未创建提交或 PR。
