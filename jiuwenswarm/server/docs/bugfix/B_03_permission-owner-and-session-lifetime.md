# 多实例配置相互覆盖、会话 key 累积与企业 persist 刷新缺失

## 元信息

| 项 | 值 |
|---|---|
| 日期 | 2026-10-29 |
| 严重程度 | 高：实例配置隔离；中：容量与持久化可用性 |
| 范围 | AgentServer 权限发布、请求/子 Agent 生命周期、persist 写入口 |
| 关联 spec | S_03_runtime-agent-management.md |
| 关联修复 | B_02_permission-callback-fail-open.md 中列出的三项剩余问题 |

## 根因

企业版相同业务 key 可对应多个仍存活的 Agent 实例，原 WeakSet 查询要求“恰好一个”，
且实例共用注册 key。会话配置仅靠删除会话/Agent uninit 清理，正常请求结束不回收；
发布错误又在请求准备阶段被吞掉。企业 persist 依赖任务 ContextVar 以及已有 session
publisher，缺失时不能把新规则可靠发布给当前调用方。

## 修复

| 缺口 | 当前行为 |
|---|---|
| publisher 所有权 | 保留原业务 key 作为 routing_key，每个实例拥有独立注册 key；按 owner key 明确注册/查找，旧实例关闭不删除新实例配置 |
| 会话 key 生命周期 | 请求准备阶段发布并持有租约，正常结束/异常/取消/流关闭均在现有 finally 清理链释放；后台子 Agent 独立保留父会话，最后一个使用者才回收 |
| 会话复用与遗漏清理 | 重新发布使用新代次；旧释放回调幂等且不影响新代次。实例未正常 uninit 而被 GC 时，仅移除其自身拥有的配置 |
| 容量 | 空闲会话缓存全局最多 128 个；SDK 容量错误仅通过 LRU 回收空闲会话重试，在途配置不参与。全部在途时显式失败，请求不继续使用旧策略 |
| 企业 persist | 审批写入上下文绑定真实会话，用所属实例基线加该会话 overlay 合成；写入后显式发布该会话，即使此前未缓存；缺会话时返回失败并记录日志 |

发布在 pending reload 完成后进行。租约从请求准备延续至交互流关闭；共享会话使用引用
计数，后台 invoke/stream 包装负责完成或取消时释放。删除会话是显式失效，允许立即移除
配置；容量淘汰不具备这一权限。关闭中的旧实例收到 overlay 变更时失效旧配置，不能
阻断替换实例的发布。

“始终允许”只合并本次工具变更和原有授权字段，保留先前会话变更。临时绑定 Agent
基线的 ContextVar 成对恢复；不写回租户基线或 SDK default。读侧依旧只选择并传递 key，
所有配置读取、合成、发布与回收均发生在配置写入或生命周期入口。

## 拒绝的方案

不靠 WeakSet 中实例数量推断所有权；不覆盖共享 default 或租户基线来绕过刷新失败；
不提高/绕过 SDK 配额；不在读取权限时补注册；不淘汰在途 key。

## 验证

定向用例覆盖同租户双实例、旧实例关闭、1100 次顺序请求、共享租约、后台子 Agent
invoke/stream 取消和关闭、全在途容量耗尽、孤立 owner GC、旧回调/旧 key 失效、冷/热
会话 persist、连续两次授权、缺会话日志、原租户/其它会话配置不变，以及真实流初始化
异常后执行释放回调。原权限、HITL、Flash、文件授权与网页传输回归一并验证。

## 边界

同时活跃的配置本身超过 SDK 上限时拒绝新请求，不放宽策略。Grant/overlay 保留原有
存储和会话删除语义；本修复回收编译配置，不把一轮请求结束当作用户授权撤销。
测试使用匹配 SDK 源码；本地缺失的 agent-runtime 仍由原 conftest stub 处理，未做部署
E2E。沙箱、Gateway A2A manager 和当前暂存区均不修改。
