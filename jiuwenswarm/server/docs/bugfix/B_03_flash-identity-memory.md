# Flash 未注入工作区身份且缺少 embedding 时无法使用内置记忆

## 元信息

| 项 | 值 |
|---|---|
| 日期 | 2026-10-30 |
| 范围 | Flash 适配器、Flash 记忆工具说明及对应测试 |
| 关联 spec | [S_03 runtime-agent-management](../specs/S_03_runtime-agent-management.md) |

## 现象与根因

Flash 默认不会把工作区的 `USER.md` 等身份文件带入模型输入：请求准备未创建身份上下文组件，动态组件清理也不保留它。组件读取的是当前 agent 工作区，与外部记忆和云画像是不同来源。

另一个独立问题是：启用内置记忆但没有完整 embedding 配置时，Flash 仍以空值构造必填配置，校验失败后放弃创建整个记忆工具。MaaS 未配置独立 embedding 时，上游有意不复用聊天地址，下游应允许 SDK 的关键词检索路径工作。

agent-core 的共享索引还存在必要的配套缺陷：索引重开时将自身创建的 `tokenize='trigram'` 表误认为旧表并清空，但迁移标记又使重建被跳过。于是无 embedding 场景下即使首次能够关键词检索，重新打开索引后仍会返回空结果。该问题也影响其他使用同一 SDK 索引的模式。

## 决策

- Flash 在请求准备时复用 SDK 现有的上下文装配组件，并在其保留清单中保留该组件；注册时传入禁用工具和渐进式工具可见列表。
- 串行化首次挂载，注册失败时回滚部分注册；热重载保留已有组件，避免 SDK 对同一个组件重复注册回调，并在后续请求绑定当前工作区及文件操作对象。
- 内置记忆在 embedding 地址、模型或凭据缺失时传入无有效凭据的配置，让 SDK 使用已有关键词索引；完整配置仍原样传递。Flash 工具说明同步表述关键词与语义检索。
- 本次不修改 agent-core。Flash 仅传递无有效 embedding 的配置，索引的持久化、迁移与恢复继续由 SDK 负责。

## 拒绝的方案

- 只增加保留清单：首次请求仍不会创建身份上下文组件。
- 调用普通 agent 的完整装配流程：会把本次身份修复无关的动态组件带入 Flash。
- 把 MaaS 聊天网关当作 embedding 服务：上游已明确区分两者，聊天接口不一定提供 embedding。

## 验证与边界

`tests/unit_tests/agentserver/test_flash_identity_memory.py` 验证合成工作区身份在真实 SDK 模型调用边界可见、跨工作区隔离、重载后回调不重复；同时验证无 embedding 的真实 SQLite 关键词写入、检索与重开，以及与模拟外部记忆和画像服务共存。未修改 SDK 下，相关 Flash 定向回归为 **115 passed、1 failed**；锁定 SDK 下关键组合为 **24 passed、1 failed**。两者均在索引重开后的检索断言失败，该用例继续保留，不能把关键词记忆的持久可用性视为通过。模型及远端 HTTP 为模拟，未执行真实 OfficeAce 服务或 Windows 实机验收。

普通 agent 的无 embedding 构造入口仍存在相同问题，本次未修改；用户自定义的任意身份文件也未加入自动装配清单。SDK 的索引重开缺陷尚未修复，因而相关组合测试仍失败，也可能阻塞包含该测试的 CI。现场安装包版本和故障请求的完整模型输入尚未取得，不能仅凭隔离测试宣布原现场问题闭环。
