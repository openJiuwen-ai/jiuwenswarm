# Flash Word / Excel 未优先进入 Turbo

| 项 | 值 |
|---|---|
| 日期 | 2026-10-29 |
| 类型 | bugfix |
| 关联规约 | S_02、S_09 |

## 复现场景与根因

Docx / Xlsx 的 enable_turbo=true 且可发现时，Flash 加速指引仍只强制新建 PPT 首次调用加速器；检索提示要求 Office 先检索加载，并只给 pptx-craft 加速例外。文字或前端明确指定 Docx / Xlsx 也被引导至 skill_tool。候选返回后工具精简进一步延续标准加载路径。

工具描述的模板排除及工具入口的模板、选区拦截未限定 PPT，Word 的“修改要求”和 Excel 的模板路径会收到错误的 PPT 标准流程指引。内部 planner 的 PPT 专用排除也没有明确其他技能继续参与匹配。

## 修复口径

- 按当前工具描述中的准确技能名称和支持范围统一加速优先规则，适用于普通请求、文字指定和前端选择；不增加固定的 Office 技能白名单。
- 保留用户指定其他技能、用户禁用加速、工具缺席、任务不支持和失败后标准流程回退的边界，HITL 暂停语义不变。
- PPT 专属提示及入口兜底限定在 PPT 请求；planner 按技能独立判定，PPT 排除不排除 Word / Excel。
- 保留候选选择阶段的工具隔离，不通过放宽技能检索边界强迫加速。

## 验证

- Flash 真实 SDK 模型入参：PPT / Docx / Xlsx × 检索开关 × 懒加载开关 × invoke / stream，覆盖普通请求及显式选择。
- 文字 / 前端显式选择的加速提示，工具不可用时的原生加载，以及中英文指南。
- Word / Excel 编辑和模板请求不被 PPT 入口误拦截；PPT 模板与编辑仍受保护。
- planner 多技能提示边界，以及既有注册开关、描述刷新、HITL / 降级回归。

测试使用离线模型替身验证装配和工具契约，不代表所有线上模型必定遵循提示词。
