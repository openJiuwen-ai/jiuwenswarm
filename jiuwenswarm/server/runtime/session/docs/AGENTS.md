# session/docs

`jiuwenswarm.server.runtime.session` 模块的设计归档目录。代码看 `git log` / 模块
`AGENTS.md`，本目录承载**长期设计规约文档（specs）**与**变更归档（features /
bugfix）**。结构规约、命名与提交约定见本文；基础约定与域级
[../../docs/AGENTS.md](../../docs/AGENTS.md) 保持一致，本文只写模块特有内容。

## 目录用途

| 目录 | 用途 | 关联触发 |
|---|---|---|
| `specs/` | 模块设计规约：不变量、接口契约、执行路径、修改检查单。**长期有效**，描述"系统现在是什么样、改代码前必须知道什么"。现有 S_01~S_07（7 份，见模块 `AGENTS.md` 的 spec 索引）。 | 任何**模块设计规约变动**（契约 / 不变量 / 执行路径 / 持久化结构变化）都必须同步修订对应 spec；新规约主题 = 新 spec 文件 |
| `features/` | 特性变更归档：一次完整设计/重构/新特性的来龙去脉（决策 + 拒绝的方案）。**只增不删**，描述"为什么这么改"。目录尚未建立，自首份 `F_NN` 归档时创建。 | 每次特性更新提交代码前归档 `F_NN_<slug>.md`；归档日期写进文档元信息 |
| `bugfix/` | 缺陷修复归档：触及 spec 描述的执行路径 / 不变量的修复（复现场景 + 根因 + 修复口径）。**只增不删**。目录尚未建立，自首份 `B_NN` 归档时创建。 | 触及 spec 路径 / 不变量的 bugfix 落地时归档 `B_NN_<slug>.md`，随单个 `fix(session)` 提交落地（见提交约定） |

`specs/` 是状态快照（描述当前），`features/` 是变更日志（描述过程）。spec 改动
通常对应一份 feature 文档解释"为什么改成这样"。

## 命名规约

```
specs/    S_NN_<slug>.md    例：S_06_git-diff-watch.md
features/ F_NN_<slug>.md    例：F_01_xxx.md
bugfix/   B_NN_<slug>.md    例：B_01_xxx.md
```

- 前缀 `S_` / `F_` / `B_` 表明文档类型，grep / IDE 列表可视识别
- `NN` 是两位**递增序号**，目录内已有 N 份文档时新文档编号 `N+1`；不复用、不回填空缺
- `<slug>` 短横线分隔的英文小写 slug，描述主题
- 文件名末尾不带日期——日期写在文档元信息表里

不允许：序号跳号（features / bugfix 不允许删除）、大写字母、下划线（`_` 仅用于
前缀分隔）、空格、未带 `S_` / `F_` / `B_` 前缀的散落 markdown。

**编号空间独立**：本目录的 `S_NN` 只在本目录内编号递增，与域级
`server/runtime/docs/specs/` 及其它子模块（如 `skill_turbo/docs/specs/`）的同名
编号互不冲突。跨目录引用时写相对路径或模块名限定，如
`runtime 域 [[S_04]]` 歧义时写 `[[runtime/S_04]]`；仅本模块内引用时裸写 `[[S_NN]]`。

## specs 内容约定

本模块 specs 采用域级标准七段式骨架（与
[../../docs/AGENTS.md](../../docs/AGENTS.md) 一致）：

```markdown
# <Spec 名称>

## 元信息
| 项 | 值 |
|---|---|
| 类型 | spec |
| 编号 / slug | S_NN / <slug> |
| 关联模块 | jiuwenswarm/server/runtime/session/<path>（含跨目录文件时写全路径） |
| 最近一次修订日期 | <YYYY-MM-DD> |
| 关联 feature | F_NN_<slug>.md（暂无时写"暂无"） |

## 范围 / 边界
（本规约管什么、不管什么→指向其它 spec）

## 不变量
（N1、N2… 编号，每条可判定；点名数量的句子是契约的一部分）

## 接口契约
（关键签名 / 参数语义 / 错误语义）

## 数据结构
（状态字段 / 谁写谁读 / 何时清理——含持久化键与生命周期）

## 执行路径
（P1、P2… 编号路径，标注 文件+方法名；这是"改哪些路径才算改全"的依据）

## 修改检查单
（"改 X → 必须连带检查 Y" 格式）

## 与其它 spec 的关系
```

skill_turbo 模块骨架另有的三个特色章节（执行路径全景 / 异常分支与退出路径 /
边界 case 清单）是**该模块特有**要求，不适用于本模块：session 的规约重心在
持久化协议与并发纪律（不变量 + 接口契约承载），执行路径以 P_NN 编号按需展开
即可。个别 spec 需要更细的分支刻画时可在标准骨架内加小节，但不强制。

### specs 间的引用与分工

- 跨 spec 引用一律写 `[[S_NN]]`（上下文明确时），不复制对方内容——单一真相源。
- spec 内不变量用 `N1`/`N2` 编号（各 spec 独立编号），供 code review 单条引用；
  模块 `AGENTS.md` 的"架构铁律"从各 spec 不变量中提炼，铁律条目回链 `[[S_NN]]`。
- 模块内文件的规约分工以各 spec 的"范围 / 边界"为准；同一文件跨多份 spec 时
  （如 `session_history.py` 兼涉 [[S_02]] 与 [[S_03]] 的边界），以 spec 间
  "与其它 spec 的关系"章节声明归属，不在两份 spec 里重复描述同一段行为。

### 行号锚点维护

spec 内用 `文件名:NNN` 形式的**行号锚点**（如 `session_metadata.py:835`）导航到
具体实现。行号锚点指向**落地时刻的代码行**，代码没有自动同步机制，因此：

- 任何改动使 spec 引用的 `:NNN` 行号漂移（哪怕纯新增行导致整体下移）时，
  **必须连带修订对应 spec 的行号锚点**，与代码改动放同一提交序列（见提交约定）。
- 修订行号时以**当前工作区代码**为基准重新核对（用 `grep -n` 定位符号实际行号），
  不要沿用旧 spec 里的行号做增量推算——增量推算会累积误差。
- 锚点引用优先"符号名 + 行号"并列（先写函数 / 常量名，再写行号），行号漂移后
  符号名仍能定位，把损害降到最低。纯行号裸引用只用于"函数体第 N 行"这类
  无法用符号表达的位置。
- 行号漂移未修订视同"契约改了 spec 不改"（见反模式）。

## 提交约定

涉及本目录文档（`S_*` / `F_*`）更新的特性改动，**特性代码、测试代码、文档拆成
三个连续提交**：

1. **提交 1 — 特性代码**：`feat(session): <实现>`（或 `fix` / `refactor` 等对应 type）。
2. **提交 2 — 测试代码**：本次新增 / 改动的单测，`test(session): ...`。
3. **提交 3 — 文档**：本次涉及的 `specs/S_NN_*.md` 修订与 `features/F_NN_*.md` 新增，
   `docs(session): ...`。

三个提交必须**连续紧邻**，在同一工作单元 / PR 内落地。bugfix 触及 spec 描述的
执行路径 / 不变量时，归档 `bugfix/B_NN_<slug>.md`（复现场景 + 根因 + 修复口径），
代码、测试、文档合并为**一个** `fix(session)` 提交——三连续提交的唯一例外，与
域级（`server/runtime/docs/AGENTS.md`）及 skill_turbo 模块**已统一**；未触及
spec 的普通小修复不必归档。

## 与其它 AGENTS.md 的关系

- `jiuwenswarm/server/runtime/session/AGENTS.md`：模块入口索引 + 文件地图 +
  架构铁律 + **本目录的归档强制约束**
- `jiuwenswarm/server/runtime/docs/AGENTS.md`：域级归档规约（本文的上位约定）；
  跨子模块的规约一律升到域级 `specs/`，不塞进本目录
- 本 `docs/AGENTS.md`：只讲归档结构与命名规约，**不重复设计内容**——内容写在
  对应 `S_*` / `F_*` 文档里

## 反模式

- **把 commit message 复制粘贴当 feature 归档**：feature 要写 commit 写不下的东西
  （拒绝的方案、设计思路、follow-up）
- **靠 docs 维护代码行为**：实现行为是代码 + 单测的事；specs 描述契约 / 路径 /
  检查项，不是 source of truth
- **契约改了 spec 不改**：执行路径 / 不变量 / 持久化结构变了但对应 spec 没改，
  下次读 spec 的人（或 agent）会被误导——提交前自查
- **模块改了行号锚点不同步**：spec 引用的 `:NNN` 行号已随代码改动漂移但未修订，
  锚点指向错误位置比没有锚点更误导——改模块时连带核对（见"行号锚点维护"）
- **在元信息里写 commit hash**：只写日期（`YYYY-MM-DD`）
- **spec 里堆砌问题故事**：specs 写"系统现在是什么样 + 改动必须检查什么"；
  变更缘由归 feature 文档
- **一次连贯设计拆成 N 份小文档**：一次设计变动归档一份
