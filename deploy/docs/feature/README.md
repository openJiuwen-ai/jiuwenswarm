# feature —— 每次较大改动一份文档

本目录是 JiuwenSwarm 部署模块的**项目记忆**。新功能、行为变化、重构、部署形态变化或里程碑应新增一份文档，说明“为什么这样改、当时确认了什么、如何验证”。局部 bugfix、注释或文案修改不需要单独建档。

## 写作规范

- **时机**：改动定稿时编写，与代码在同一提交中提交；未提交的工作区改动先标记“待提交”，提交时补充 hash。
- **命名**：`YYYY-MM-<短横线-slug>.md`；有里程碑编号时可加入编号。
- **结构**：使用 [_TEMPLATE.md](_TEMPLATE.md)，完成后在下方索引增加一行。
- **内容纪律**：
  - 明确记录与需求方确认的决策及其适用边界；
  - 记录被否方案和否决理由，避免后续重复设计；
  - 验证必须包含命令、用例数量或产物扫描结果，不能只写“已验证”；
  - 尚未设计或交由后续工程师处理的事项必须明确列为开放问题。
- **颗粒度**：一次连贯改动一份。判断标准是半年后是否仍需了解这次改动的设计原因与兼容约束。
