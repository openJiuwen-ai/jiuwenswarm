# 模式系统（Modes）

JiuwenSwarm 支持多种运行模式，不同模式对应不同的工具集、权限策略和记忆行为。

> **注意**：在 Web 前端中，用户可通过对话输入区域的**模式选择器**在「**单Agent模式**」和「**集群模式**」之间切换。`/mode` 命令主要用于 IM 受控通道和 TUI。

---

## Web 前端模式

Web 前端提供两种执行模式：

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **单Agent模式** | 单个智能体独立处理任务，支持任务规划与动态调整 | 大多数日常任务、问答、代码生成等 |
| **集群模式** | 多智能体协作模式，由 Leader 编排多个专业智能体分工协作 | 大型复杂任务、需要多角色协作的场景 |

![模式选择器](../assets/images/current-ui/12-模式选择器.png)

## 命令行模式（IM/TUI）

通过 `/mode` 命令可切换更细粒度的模式。用户可通过 `/mode` 命令在对话中切换。

### 模式总览

下表的代号均为新三段命名 canonical 模式的旧别名（详见下文
[新三段命名（canonical 模式）](#新三段命名canonical-模式)）。运行时
`params["mode"]` 写回的是 canonical 形式，但旧客户端仍可发送这些别名串。

| 模式 | 旧别名 | canonical | 说明 |
|------|--------|-----------|------|
| Agent | `agent` | `agent.work.normal` | 统一单 Agent 模式（曾经的 `agent.plan` / `agent.fast` 模式已合并）。全工具 + 被动记忆 |
| Code（常规） | `code.normal` | `agent.code.normal` | 编码模式 + 编码记忆，侧重代码执行 |
| Code（团队） | `code.team` | `team.code.normal` | 以 Code 配置启动的团队协作模式 |
| Team | `team` | `team.work.normal` | 多 Agent 协作模式，基于配置中的 `team` 定义 |

> **兼容说明**：旧串通过 `deprecate_mode()` 静默映射到新串（不抛错、不告警）。
> 其中 `agent.plan` 映射到 `agent.work.plan`（保留 plan 状态），**不是**
> 映射到 `agent`。Web 模式下 `agent.plan` + `work_mode` 会开启硬规划模式
> （只读规划，需经 `exit_plan_mode` 审批后才能执行），与旧版「规划子模式」
> 语义不同。详见下文「工作模式（work_mode）」。

## 新三段命名（canonical 模式）

后端中枢层（`jiuwenswarm/common/mode_matrix.py`）新增 8 个三段命名的 canonical
模式串，作为统一对外标识。三段语义为 `大类.工作环境.是否规划`：

- **大类**：`agent`（单 Agent）/ `team`（集群）
- **工作环境**：`work`（Deep Agent profile）/ `code`（Code Adapter profile）
- **是否规划**：`normal`（可执行）/ `plan`（只读规划，需审批后才能执行）

| 新 canonical | 含义 | 旧串（兼容别名） |
|--------------|------|-------------------|
| `agent.work.normal` | 单 Agent + work profile + 可执行 | `agent` / `agent.fast` |
| `agent.work.plan`   | 单 Agent + work profile + 规划 | `agent.plan` |
| `agent.code.normal` | 单 Agent + code profile + 可执行 | `code.normal` |
| `agent.code.plan`   | 单 Agent + code profile + 规划 | `code.plan` |
| `team.work.normal`  | 集群 + work profile + 可执行 | `team` |
| `team.work.plan`    | 集群 + work profile + 规划 | `team.plan.normal` |
| `team.code.normal`  | 集群 + code profile + 可执行 | `code.team` |
| `team.code.plan`    | 集群 + code profile + 规划 | `team.plan.code` |

> **迁移策略**：旧串通过 `deprecate_mode()` 静默映射到新串（不抛错、不告警），
> 写回 `params["mode"]` 时统一落新串。新代码应直接发新串；旧客户端继续发旧串
> 也能正常工作，但运行时记录的 canonical mode 永远是新串。

### plan 入口契约（`plan_entry_source`）

「显式进入 plan」是一次性字段 `plan_entry_source`，前后端共享字面量契约：

| 值 | 来源 |
|----|------|
| `slash_command` | TUI 的 `/plan` 命令产出的 entry source |
| `plan_toggle` | Web 用户手动打开 Plan 开关的那一条消息产出的 entry source |

后端 `AgentWebSocketServer._is_explicit_plan_entry_request` 防重入闸门只认这两个
字面量；前端（TUI `core/plan-entry-source.ts` / Web `features/planMode/planEntrySource.ts`）
必须引用同名字面量。字面量定义在 `jiuwenswarm/common/schema/chat_send.py` 的
`PLAN_ENTRY_SOURCES` 常量集合，跨层契约测试见
`tests/unit_tests/test_plan_entry_source_contract.py`。

## 切换命令

在频道对话中输入以下命令切换模式：

```
/mode agent          # 切换到 Agent 模式（默认使用 agent.plan）
/mode plan           # TUI 本地简写，等价于 agent.plan
/mode code           # 切换到 Code 模式（默认使用 code.normal）
/mode team           # 切换到 Team 模式
/mode agent.plan     # 直达 Agent 规划子模式
/mode agent.fast     # 直达 Agent 快速子模式
/mode code.normal    # 直达 Code 常规子模式
/mode code.team      # 直达 Code 团队子模式
/mode team.normal    # TUI 本地写法，等价于 team

# 新三段命名 canonical 形式（新代码建议直接发送）：
/mode agent.work.normal  # 单 Agent + work profile + 可执行
/mode agent.work.plan    # 单 Agent + work profile + 规划
/mode team.code.normal   # 集群 + code profile + 可执行
```

> 兼容性：`/mode plan`、`/mode team.normal` 是 TUI 本地命令能力。Gateway 受控通道接受的输入集为以下三部分的并集：
> - 8 个新三段命名 canonical：`agent.work.normal`、`agent.work.plan`、`agent.code.normal`、`agent.code.plan`、`team.work.normal`、`team.work.plan`、`team.code.normal`、`team.code.plan`
> - 10 个旧 canonical（`DEPRECATION_MAP` 的 key）：`agent`、`agent.plan`、`agent.fast`、`code`、`code.normal`、`code.plan`、`code.team`、`team`、`team.plan.normal`、`team.plan.code`
> - 2 个正式别名（`MODE_ALIASES` 的 key）：`team.plan`（→ `team.work.plan`）、`team.code`（→ `team.code.normal`）
>
> 不在此集合内的串会被前置校验判为「非法指令」（`jiuwenswarm/gateway/message_handler/message_handler.py` 的 `_VALID_MODE_INPUTS`）。旧串经 `deprecate_mode()` 静默映射到新 canonical。

也可用 `/switch` 在同一大类内切换子模式：

```
/switch plan         # Agent 下切到 plan；Code 下切到 plan
/switch fast         # Agent 下切到 fast
/switch normal       # Code 下切到 normal
/switch team         # Code 下切到 code.team
```

> 上述示例描述的是 IM 频道经过 Gateway 解析的受控命令。TUI 仅在 `agentos-tui` 托管启动（`AGENTOS_TUI_SUPERVISED=1`）时注册语义不同的同名命令：`/switch claude` 用于 handoff 到 Claude TUI，`/switch list` 用于查看可切换目标。独立启动的 TUI 不注册该命令；在 TUI 中切换模式请使用 `/mode ...` 或 `/plan`。

## 配置

在 `config/config.yaml` 的 `modes` 段中定义各模式的工具和约束：

```yaml
modes:
  agent:
    # plan / fast 已合并为单一 agent 模式：记忆固定被动（is_proactive 开关已下线）
    memory:
      enabled: true
    rails: []
    tools: []

  code:
    rails:
      - FileSystemRail          # 文件系统安全约束
      - SkillUseRail            # 技能调用约束
      - LspRail                 # LSP 辅助约束
    tools:
      - web_free_search
      - web_fetch_webpage
      - web_paid_search
      - user_todos
    embedding_config:
      model_name: null
      base_url: null
      api_key: null

  team:
    jiuwen_team:
      team_name: jiuwen_team
      lifecycle: persistent
      teammate_mode: build_mode
      spawn_mode: inprocess
      leader:
        member_name: team_leader
        display_name: 团队领导
        persona: "天才项目管理专家，擅长任务分解和团队协调"
      agents:
        leader:
          workspace:
            stable_base: true
          max_iterations: 200
          completion_timeout: 600.0
      workspace:
        enabled: true
      transport:
        type: inprocess
      storage:
        type: sqlite
```

### 各段说明

| 路径 | 说明 |
|------|------|
| `modes.agent` | 统一 Agent 模式：被动记忆；规划 / 子代理 / 演进等能力由运行时装配，不再按 plan/fast 分叉 |
| `modes.code.rails` | Code 模式的动态安全 Rails（固定 Rails 不在此配置） |
| `modes.code.tools` | Code 模式的动态工具白名单（`coding_memory_*` 和 `send_file_to_user` 由运行时自动注册） |
| `modes.code.embedding_config` | Code 模式专属 Embedding 配置（留空则用全局配置） |
| `modes.team.<name>` | Team 模式定义：团队名、lifecycle、leader/agents 配置 |

### 通道默认模式

每个频道可在 `config.yaml` 的 `channels.<channel>.default_mode` 中指定默认模式：

```yaml
channels:
  web:
    enabled: true
    default_mode: agent         # 该频道对话默认使用统一 Agent 模式
```

## 工作模式（work_mode）

`work_mode` 与执行 `mode` 正交，取值：

| 值 | 含义 |
|----|------|
| `work` | 普通办公协作 profile（Deep Agent），不默认暴露 Git 能力 |
| `code` | 代码工程 profile（Code Adapter），绑定项目目录并展示 Git 状态 / diff |

使用 E2A 协议时建议在 `chat.send` 的 `params` 中同时发送 `mode` 与 `work_mode`，
由后端 `mode_matrix` 组合成最终运行形态（例如 `mode=agent` + `work_mode=work`
→ 可执行 Agent；`mode=agent.plan` + `work_mode=work` → 硬规划模式）。

> **过渡状态**：新三段命名 canonical 已在中段编码 work profile
> （`agent.work.*` / `agent.code.*`），因此在 canonical 模式上 `work_mode`
> 对 mode 解析而言已是冗余字段。按本项目模式重构决策，`work_mode` 当前
> **暂不丢，渐进退场**：它仍作为默认项目分桶键使用（无显式
> `project_id` 的会话：`work` → `default` 项目，`code` → `default_code`
> 项目）。新代码建议直接发送新 canonical `mode` 串；旧 Web 客户端可继续
> 发 `mode` + `work_mode`，过渡期内后端仍同时接受。完整退场计划见
> `PLAN_drop_work_mode.md`。

## 模式行为差异

不同模式不只是 UI 名称不同，还会决定 AgentServer 选择哪个运行时
profile、挂载哪些 Rails、如何注入记忆与团队协作能力。

| 模式 | 运行时 profile | Agent 行为侧重点 | 主要 Rails / 工具差异 | 记忆策略 |
|------|----------------|------------------|------------------------|----------|
| `agent` | Deep Agent（`mode=agent`） | 统一单 Agent 对话。适合日常任务、多步推理、技能调用与需要子代理协助的场景。 | 统一挂载原 plan 档能力（如 `TaskPlanningRail`、`SubagentRail`；按配置启用 `SkillEvolutionRail` / `SkillCreateRail`）；保留通用搜索、多模态、技能等工具。 | 使用 `modes.agent.memory`；固定被动记忆，按需读写。 |
| `code.normal` | Code Adapter（`mode=code`, `sub_mode=normal`） | 编码任务的执行阶段。适合改文件、跑命令、验证、交付结果。当前不支持 Skill 自演进。 | 使用 Code 专用英文系统提示；固定挂载 `LspRail`、`ProjectMemoryRail`、`CodingMemoryRail`、`AgentModeRail`、`StructuredAskUserRail`、`ConfirmInterruptRail`、文件系统/权限 Rails；动态启用 `modes.code.rails` / `modes.code.tools` 中的能力。 | 编码记忆 + 项目记忆。 |
| `code.team` | Code Adapter + Team sub-mode（`mode=code`, `sub_mode=team`） | 以 Code profile 启动团队协作。适合代码项目中让团队成员分工，同时继承编码工作区与代码工具语义。 | 主 Agent 仍使用 Code profile；Team 成员会通过 TeamManager 启动，并尽量继承 Code 侧项目目录、代码工具和成员技能工具包。 | 团队成员使用 Team 配置；编码/项目上下文由 Code profile 和团队运行时共同影响。 |
| `team` | Team runtime（`mode=team`） | 标准多 Agent 协作。Leader 负责分解、调度、汇总，成员按角色并行处理。 | Team 成员挂载 `RuntimePromptRail`、`ResponsePromptRail`、`SysOperationRail`、`TaskPlanningRail`、`SecurityRail`、`AvatarPromptRail` 等；Leader 额外支持 Team 技能演进/创建；工具来自可继承白名单和团队配置。 | 由 `modes.team.<name>.memory` 决定，可启用共享 `TEAM_MEMORY.md`、自动提取、成员记忆注入等。 |

### 关键区别速记

- 曾经的 `agent.plan` / `agent.fast` 模式已合并为统一 `agent`：同一 Deep Agent profile，统一挂载规划 / 子代理 / 技能演进等能力，记忆固定被动。
- Web 模式下 `agent.plan` + `work_mode` 会开启硬规划模式，与统一 `agent` 可执行对话不同。
- `code.team` 与 `team` 都会进入团队协作，但入口不同：`code.team` 从 Code profile 进入，适合代码项目分工；`team` 是标准 Team runtime。
