# 日志

JiuwenSwarm 提供了完善的日志系统，用于记录系统运行状态、调试信息和审计日志，帮助用户监控系统运行、排查问题和分析系统行为。

## 1. 日志基础

### 1.1 存储位置

JiuwenSwarm 有两个独立的日志系统，分别存储在不同目录：

| 日志目录 | 所属系统 | 说明 |
|---------|---------|------|
| `~/.jiuwenswarm/agent/.logs/` | JiuwenSwarm 应用层日志 | 记录网关、渠道、智能体服务等应用层日志，由 `jiuwenswarm/common/utils.py` 管理，配置在 `config.yaml` 的 `logging:` 段 |
| `~/.jiuwenswarm/logs/logs/` | OpenJiuwen 框架层日志 | 记录运行器、会话、LLM、记忆、工具等框架层日志，由 OpenJiuwen 框架自身的日志系统管理，配置在独立的日志配置文件中 |

### 1.2 JiuwenSwarm 应用层日志（agent/.logs/）

应用层日志根据组件类型分类存储，支持日志轮转，归档文件以时间戳命名：

| 日志文件 | 记录内容 |
|---------|---------|
| `gateway.log` | 网关相关日志，包括 `app`、`gateway`、`evolution`、`utils` 等模块 |
| `channel.log` | 渠道相关日志，包括所有 `channels` 下的模块 |
| `agent_server.log` | 智能体服务器日志，包括 `agents` 和 `.server` 下的模块 |
| `full.log` | 所有组件日志的汇总 |
| `permissions.log` | 权限相关日志 |
| `ws-dev.log` | Web 服务开发模式日志 |

**归档日志**：当日志文件达到 20MB 时自动轮转，归档文件命名格式为 `{文件名}_{YYYYMMDD_HHMMSS}.log`，例如 `full_20260519_153045.log`。系统最多保留 20 个归档文件，超出则删除最旧的。

### 1.3 OpenJiuwen 框架层日志（logs/logs/）

框架层日志根据功能模块分类存储，支持子目录结构：

| 日志文件/目录 | 记录内容 |
|-------------|---------|
| `run/jiuwen.log` | 主运行日志（所有模块的通用日志） |
| `runner.log` | 任务运行器日志 |
| `session.log` | 会话管理日志 |
| `llm.log` | LLM 调用日志 |
| `memory.log` | 记忆系统日志 |
| `sys_operation.log` | 系统操作日志 |
| `tool.log` | 工具调用日志 |
| `team.log` | 团队协作日志 |
| `interface/jiuwen_interface.log` | 接口层日志 |
| `interface/jiuwen_prompt_builder_interface.log` | Prompt 构建器接口日志 |
| `performance/jiuwen_performance.log` | 性能日志 |

### 1.4 日志内容类型

日志系统根据内容类型分为两种主要类型：

#### 1.4.1 普通日志

普通日志按组件分类，记录系统运行状态、错误信息、调试信息等：
- 使用标准的 Python logging 模块实现
- 根据组件类型存储到不同文件中（见1.2节）

#### 1.4.2 审计日志

审计日志以结构化 JSONL 格式记录沙箱操作详情，包括：
- 命令执行（`exec_command`）
- 文件传输（`file_transfer`）
- 网络请求（`network_request`）

每条审计日志包含操作类型、参数、结果、执行时间等信息。

## 2. 查看日志

### 2.1 实时查看日志

使用 `tail` 命令实时查看日志：

```bash
# 实时查看 full.log
$ tail -f ~/.jiuwenswarm/agent/.logs/full.log

# 实时查看特定组件日志
$ tail -f ~/.jiuwenswarm/agent/.logs/gateway.log
```

### 2.2 查看历史日志

使用 `cat` 查看日志

```bash
# 查看完整日志文件
$ cat ~/.jiuwenswarm/agent/.logs/full.log
```

## 3. 日志轮转策略

日志系统采用以下轮转策略（参数为硬编码常量，不可通过 config.yaml 配置）：

- **大小限制**：每个日志文件最大 20MB（即 20 × 1024 × 1024 = 20,971,520 字节，常量 `_LOG_FILE_MAX_BYTES`）
- **保留数量**：保留最新的 20 个归档文件（常量 `_LOG_FILE_BACKUP_COUNT`）
- **自动轮转**：当日志文件达到 20MB 时，自动归档当前文件并创建新文件
- **归档命名**：归档文件以时间戳命名，格式为 `{stem}_{YYYYMMDD_HHMMSS}{suffix}`，例如 `gateway_20260519_153045.log`
- **清理策略**：归档文件超过 20 个时，自动删除最旧的文件

如需调整轮转参数，需修改源码中 `jiuwenswarm/common/utils.py` 第 47-48 行的常量定义。

## 4. 日志系统架构

### 4.1 核心模块

- **日志配置**：`jiuwenswarm/common/utils.py` 中的 `setup_logger` 函数
- **默认日志实现**：`openjiuwen/core/common/logging/default/default_impl.py`

### 4.2 日志流程

1. 各模块通过 `logging.getLogger(__name__)` 获取 logger
2. 根据 logger 名称自动分类到不同组件
3. 日志同时输出到控制台和对应组件的日志文件
4. 所有日志汇总到 `full.log`
5. 当日志文件达到大小限制时自动轮转

## 5. 日志配置

### 5.1 JiuwenSwarm 应用层日志配置

应用层日志级别通过 `config.yaml` 文件中的 `logging` 部分配置：

```yaml
logging:
  level: INFO           # 默认日志级别
  console_level: INFO   # 控制台日志级别
  gateway: INFO         # 网关组件日志级别
  channel: INFO         # 渠道组件日志级别
  agent_server: INFO    # 智能体服务器日志级别
  full: INFO            # 完整日志级别
```

> **注意**：日志轮转参数（`max_bytes`、`backup_count`）为硬编码常量，不可通过 `config.yaml` 配置。如需调整，需修改源码中 `jiuwenswarm/common/utils.py` 第 47-48 行的定义。

### 5.2 环境变量

可以通过环境变量覆盖控制台日志级别：

```bash
LOG_LEVEL=DEBUG jiuwenswarm-start
```

### 5.3 配置生效方式

修改日志配置后**需要重启服务**才能生效：

- `config.yaml` 中的日志配置在服务启动时加载，运行期间不会自动重新加载
- 环境变量需要在启动命令前设置，或通过 `.env` 文件设置后重启服务
- OpenJiuwen 框架层日志配置修改后，同样需要重启服务

## 6. 日志级别

JiuwenSwarm 支持标准的 Python 日志级别：

| 级别 | 描述 |
|------|------|
| DEBUG | 调试信息，用于开发和调试 |
| INFO | 一般信息，记录系统正常运行状态 |
| WARNING | 警告信息，记录潜在问题 |
| ERROR | 错误信息，记录系统错误 |
| CRITICAL | 严重错误信息，记录系统崩溃等严重问题 |

## 7. 日志格式

日志格式包含时间戳、日志级别、模块名和日志消息：

```
2026-05-19 15:30:45.123 INFO jiuwenswarm.app: Service started successfully
```

### 7.1 审计日志格式

审计日志使用结构化 JSON 格式：

```json
{
  "timestamp": "2026-05-19T15:30:45.123Z",
  "event_type": "exec_command",
  "sandbox_id": "9284a4bf-870",
  "command": "ls -la",
  "workdir": "/home/user",
  "ok": true,
  "exit_code": 0,
  "stdout": "total 40\ndrwxr-xr-x  5 user user 4096 May 19 15:30 .",
  "stderr": "",
  "duration_ms": 123
}
```

## 8. 常见问题与排查

### 8.1 日志文件过大

**问题**：日志文件增长过快，占用过多磁盘空间

**解决方案**：
- 降低日志级别以减少日志输出（修改 `config.yaml` 中的 `logging.level` 等配置）
- 定期清理过期的归档日志文件（手动或编写定时任务）
- 如需调整轮转参数，修改源码 `jiuwenswarm/common/utils.py` 第 47-48 行的常量：
  ```python
  _LOG_FILE_MAX_BYTES = 20 * 1024 * 1024  # 修改此值调整单文件大小
  _LOG_FILE_BACKUP_COUNT = 20             # 修改此值调整归档数量
  ```

### 8.2 无日志输出

**问题**：找不到日志文件或日志内容为空

**解决方案**：
- 检查日志目录权限是否正确
- 检查日志级别配置是否过高
- 检查服务是否正常启动

### 8.3 日志乱码

**问题**：日志文件包含乱码字符

**解决方案**：
- 确保系统编码设置正确（推荐使用 UTF-8）
- 使用支持 UTF-8 编码的文本编辑器查看日志

## 9. 最佳实践

1. **开发环境**：使用 DEBUG 级别获取详细调试信息
2. **生产环境**：使用 INFO 或 WARNING 级别减少日志输出
3. **定期清理**：定期清理过期日志文件，避免占用过多磁盘空间
4. **集中管理**：考虑使用日志收集工具（如 ELK Stack）进行日志集中管理
5. **敏感信息**：注意日志中可能包含的敏感信息，如 API 密钥、密码等
