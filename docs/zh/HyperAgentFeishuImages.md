# HyperAgent 飞书群图片问答

在同一条飞书消息中选择 `@AI同事`，输入问题并粘贴图片，再发送。例如：`@ISSUE解决大师 请读取红框中的文字，说明蓝色圆形在什么位置。` 图片应与问题放在同一条消息里。

当前处理触发任务的群消息，支持独立图片节点、图文混排以及同一帖子里的多张图。沿用同事原有响应策略：发送图片本身不保证触发，优先使用图文混排并显式 @。先单独发图、再另发一句问题，或引用历史图片，尚未接入自动追图。私聊、视频和精确像素差异对比不在本次范围。

## 管理员配置

机器人继续使用该同事已绑定的飞书应用，不需要用户个人飞书 CLI 登录。应用需要有读取消息和下载对应图片资源的权限；是否需要审批取决于租户现有授权。群历史批量读取权限不是本功能的必需条件。

在服务数据目录的 `config/.env` 配置以下变量并重启服务。不要将真实密钥提交到代码仓。

```dotenv
VISION_ENABLED=true
VISION_MODEL=qwen4-max
VISION_BASE_URL=https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
VISION_API_KEY=<可访问该视觉模型的密钥>
VISION_MAX_RETRIES=1
VISION_REQUEST_TIMEOUT_SECONDS=60
```

也支持现有的 `VISION_MODEL_NAME` 和 `VISION_API_BASE` 变量。以服务实际生效的环境变量为准；本功能不新增配置页面或热更新入口。聊天模型继续负责对话，图片工具使用上述视觉模型。复用聊天密钥需要管理员明确配置，代码不会自动借用。Qwen4-Max 的官方能力说明见[阿里云文档](https://help.aliyun.com/zh/model-studio/qwen4-max)，仍需用部署账号验证模型访问权限。

## 处理与失败

只下载原消息中登记过的图片节点，不把正文里的图片 key 或任意链接当作附件。每条最多 8 个图片节点；单图下载最多 20 MiB、解码尺寸最多 4,000 万像素，整个准备过程最多 45 秒。图片按消息中的顺序编号，重复图片共用下载文件；某张图失败时保留其余图片及原编号。

视觉工具只接受本次任务的 `feishu-image:N` 编号，每次调用前再次检查消息和群读取条件。文件保存在当前会话下的执行专属临时目录，结束、失败和取消后删除；异常退出残留在该会话下一次准备图片时按一天期限清理。请求来源记录保留消息版本和图片 key，不保留原图，供重试恢复核对；它随会话目录保留。

视觉工具的图片范围不改变同事已有 Bash 权限，不承诺隔离已有完全访问权限下的所有文件操作。下载失败或视觉模型未配置时应明确说明原因，不能编造图片内容。视觉服务默认最多等待 60 秒；超时可重试。底层 SDK 已发出的远端模型请求可能继续完成，超时不代表服务商取消计算或费用。

## 手工验收

1. 制作图片，在红框内写一个仅图片里出现的随机字符串，并放一个蓝色圆形。
2. 将图片、@同事和提问放在同一条消息中。验证回复的字符串、图形和位置关系，而不只看“已受理”。
3. 同一帖子放两张不同图片，分别问图一、图二；核对编号和内容对应。
4. 测试原消息撤回、超大或损坏图片、模型关闭，确认回复说明原因，不声称已看图。
5. 查看执行记录中的视觉工具调用与结果，并检查任务结束后临时图片已删除。
