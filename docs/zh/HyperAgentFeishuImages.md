# HyperAgent 飞书群图片问答

在同一条飞书消息中选择 `@AI同事`，输入问题并粘贴图片，再发送。例如：`@ISSUE解决大师 请读取红框中的文字，说明蓝色圆形在什么位置。` 图片应与问题放在同一条消息里。

当前处理触发任务的群消息，支持独立图片节点、图文混排以及同一帖子里的多张图。沿用同事原有响应策略：发送图片本身不保证触发，优先使用图文混排并显式 @。先单独发图、再另发一句问题，或引用历史图片，尚未接入自动追图。私聊、视频和精确像素差异对比不在本次范围。

## 管理员配置

机器人继续使用该同事已绑定的飞书应用，不需要用户个人飞书 CLI 登录。应用需要有读取消息和下载对应图片资源的权限；是否需要审批取决于租户现有授权。群历史批量读取权限不是本功能的必需条件。

在页面「设置 → 模型 → 多模态模型」添加可理解图片的模型，填写模型名称、API 地址及 API Key，并勾选图片处理能力。然后在「设置 → 智能体 → 工具 → 图片处理」开启开关并选择该模型。AI 同事与其他功能使用同一份配置，不需要额外给同事配置密钥；不会自动借用聊天模型的密钥。配置影响之后启动的执行，已运行的执行保留已装配的模型。

旧部署尚未保存统一多模态配置时，仍兼容 `VISION_ENABLED`、`VISION_MODEL`（或 `VISION_MODEL_NAME`）、`VISION_BASE_URL`（或 `VISION_API_BASE`）及 `VISION_API_KEY`。一旦存在统一配置，以页面保存的开关和模型为准；页面关闭图片处理后，遗留环境变量不会重新开启它。不要将真实密钥提交到代码仓。若页面提示组件版本不匹配，需要部署与当前版本锁定依赖一致的 AgentServer、Gateway 和协议组件。

`VISION_REQUEST_TIMEOUT_SECONDS` 可调整视觉请求等待上限，默认 60 秒。模型是否支持图片仍需使用部署账号实际验证，不能仅依据模型名称判断。

## 处理与失败

只下载原消息中登记过的图片节点，不把正文里的图片 key 或任意链接当作附件。每条最多 8 个图片节点；单图下载最多 20 MiB、解码尺寸最多 4,000 万像素，整个准备过程最多 45 秒。图片按消息中的顺序编号，重复图片共用下载文件；某张图失败时保留其余图片及原编号。

入站图片通过本次任务的 `feishu-image:N` 编号读取；通用执行层也接受 `media:image:N` 别名。每次调用前再次检查消息和群读取条件。下载文件保存在 AI 同事数据目录的 `media-cache/executions/` 私有临时目录，移出普通办公空间，避免普通文件读取规则覆盖它；结束、失败和取消后删除，异常退出残留按一天期限回收。`media-cache/feishu-sources/` 只保存请求来源版本与图片 key，不保存原图或重复的群聊正文。这是媒体缓存，不是另一份群聊记录库。

AI 同事也可以识别当前会话 `output/` 中生成的截图，支持会话相对路径及 `sessions/<当前会话>/output/...` 办公空间相对路径。权限确认或服务重启后，当前会话输出仍可读取；其他会话输出、未授权办公文件及任意网络地址被拒绝。WeLink 保持当前触发消息已接收附件目录的读取能力。通用媒体范围与渠道下载接口分离，后续渠道可提供适配器；本次没有新增其他渠道图片下载或音视频理解。

页面对话执行时，输入框右侧的发送按钮会变成停止按钮。图片准备任务使用同一个停止入口；停止会取消下载并等待其清理，不再继续启动模型。本次不新增飞书停止命令。

升级时，WeLink 新收到附件的目录改为完整消息 ID 的摘要，避免旧命名方式把不同消息写入同一目录。升级前仍在运行或等待权限确认的旧格式附件任务，需要重新发送消息；不自动开放可能混有其他消息文件的旧目录。

视觉工具的图片范围不改变同事已有 Bash 权限，不承诺隔离已有完全访问权限下的所有文件操作。下载失败或视觉模型未配置时应明确说明原因，不能编造图片内容。视觉服务默认最多等待 60 秒；超时可重试。底层 SDK 已发出的远端模型请求可能继续完成，超时不代表服务商取消计算或费用。

## 手工验收

1. 制作图片，在红框内写一个仅图片里出现的随机字符串，并放一个蓝色圆形。
2. 将图片、@同事和提问放在同一条消息中。验证回复的字符串、图形和位置关系，而不只看“已受理”。
3. 同一帖子放两张不同图片，分别问图一、图二；核对编号和内容对应。
4. 测试原消息撤回、超大或损坏图片、模型关闭，确认回复说明原因，不声称已看图。
5. 查看执行记录中的视觉工具调用与结果，并检查任务结束后临时图片已删除。
