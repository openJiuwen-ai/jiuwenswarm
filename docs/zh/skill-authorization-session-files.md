# 会话级 Skill 授权文件

Skill 授权属于逻辑会话，不属于承载请求的 AgentServer Pod。AgentServer 默认将完整授权和活跃技能写入系统会话目录，不需要额外的 Redis 配置。

## 存储与生命周期

```text
<租户 Agent 目录>/sessions/<session_id>/
└── .skill_authorization/
    ├── state.lock          # 跨进程、跨 Pod 的互斥锁
    └── state.json          # Grant、执行窗口、活跃技能和失效状态
```

该目录使用系统的会话路径解析规则，按租户、会话和 Agent 作用域隔离，与用户选择的项目目录无关。多个会话共用项目目录时，授权仍互相独立。

`state.json` 保存 Skill 身份摘要、权限快照、审批决定、审批工具调用标识及授权状态。激活时继续校验 Skill 正文和权限摘要、版本及审批调用绑定，沿用 SDK 的授权状态转换。

授权没有独立的过期 TTL。Runtime 路由过期、Pod 切换、适配器回收或进程重启不会删除授权文件。Skill 完成、撤销、切换和活跃状态闲置回收继续遵守原有语义：例如“会话内允许”的授权完成后保留为未激活的审批记录，“本次允许”则回收。永久删除会话会先写入删除标记，再随会话目录清除文件。

## 一致性与安全

每次操作读取文件并临时调用 SDK 状态机，AgentServer 不保留授权或活跃技能缓存。撤销结果因此会被旧 Pod 的下一次权限检查读到。只读查询不重写状态文件；状态变化在文件锁内执行，通过临时文件、同步写入和原子替换提交，防止并发覆盖和半写文件。

进程内按状态目录分别加锁，不同会话可以并行访问。共享失效版本由写端加锁并原子替换，读端直接读取完整文件，事务结束前再次核对版本；不使用延迟缓存。

生效配置关闭授权功能时，权限检查停止叠加 Skill 权限，同时使持久化授权失效；新启动的 Pod 也执行该检查。全局清理使用共享失效版本，审批记录另绑定会话实例标识，阻止关闭开关或删除并重建会话后的迟到审批恢复旧授权。缺失、损坏、锁超时或存储不可用时不使用旧授权，也不回退到内存。

系统会话目录及失效版本目录对沙箱工具只读，禁止通过 `sandbox.files.allow` 为其开放写入。授权文件仅由宿主服务修改。

## 部署与使用

单机使用原有会话目录即可。多个 AgentServer Pod 必须通过现有共享数据卷访问相同租户的会话目录；该文件系统须支持跨主机文件锁和同目录原子替换，例如正确配置的 NFS。仅共享项目目录、各 Pod 会话目录仍在各自本地磁盘的部署不满足要求。

进程内锁和跨进程文件锁各自最多等待 0.3 秒，此值不是整个文件操作的超时，底层文件系统 I/O 仍可能耗时更长。锁等待失败时不使用旧授权；技能状态写入失败会停止当前执行并提示重试，防止继续使用未成功清理的状态。已删除或尚未初始化的会话不会由活跃技能回调重建。文件损坏不会自动恢复旧授权，应先排查存储异常。

部署时应结合实际会话并发量检查共享卷延迟和锁支持。出现 `session file unavailable`、`state update failed` 或 `Skill state ... lock timed out` 时，检查共享卷、同会话并发操作和存储延迟；增加等待时间不能替代解决锁竞争。

用户通过现有 Skill 加载与审批界面授权，无需填写新的存储参数。不要手动编辑授权文件。删除会话使用现有会话删除接口，以便同时回收运行状态、审批等待和目录。
