# 多模态模型设置

个人版在「设置 > 模型 > 多模态模型」统一管理模型，在「设置 > 智能体 > 工具」选择模型。普通对话模型、模型组和决策模型使用原入口。

## 添加与选择

点击「添加模型」，选择模型用途和模型能力：

| 模型用途 | 可多选的模型能力 |
| --- | --- |
| 多模态理解 | 图片处理、音频处理、视频理解 |
| 多模态生成 | 图像生成、视频生成 |

请仅勾选该模型实际支持的能力。理解类、生成类沿用原来的供应商和连接表单校验；例如 vLLM-Omni 允许不填写密钥和模型名，其他供应商保持原要求。模型展示名称在输入模型名后失焦、或选中模型时自动填写；手工改名后保留，清空后可重新自动填写。切换供应商且模型名为空时，不使用供应商名称自动填写。

保存后，没有绑定模型的对应工具会自动选择该模型并开启；已有选择和手动关闭状态会保留，新模型成为候选。编辑模型时新勾选能力也使用这一规则。

工具下拉框只展示支持该工具能力的模型。关闭工具会保留选择，再次开启直接使用原模型。没有选择时开启工具，会打开添加模型弹框，并预填当前用途和能力；这些选项可以修改。若保存时未包含入口工具所需的能力，模型仍会添加，入口工具保持原状态。

模型名称可以重复。同名候选会显示真实模型名和地址；仍完全相同时显示模型 ID，便于区分。

## 修改与删除

修改模型连接配置会同步到所有已绑定工具，包括关闭的工具。移除能力或改变用途时，如果影响已有绑定，保存前会列出受影响工具并要求确认。

删除模型会要求确认；模型被使用时，会列出全部已绑定工具，包括关闭项。确认删除或移除能力后：

- 有其他匹配模型：切换到列表顺序中的第一个，保留原开关状态。
- 没有匹配模型：清空选择和模型配置，并关闭工具。

取消确认不会保存，编辑草稿会保留。

## 历史配置与保存结果

升级后首次启动 Runtime 服务时，自动迁移原五类工具配置；进入设置页只读取结果。同一用途且完整连接配置和高级参数一致的模型会合并，能力取并集；每个工具的开关独立保留。已存在但不完整的历史字段原样迁移，之后编辑保存仍需满足原表单校验。

图片、音频、视频的模型名若分别精确等于模板占位值 `your-vision-model-name`、`your-audio-model-name`、`your-video-model-name`，该工具配置不会导入，也不会创建绑定，开关关闭；此规则不检查其余连接字段。之后添加真实模型时，会正常自动绑定并开启。

历史环境变量引用按原有规则解析成实际值。同义地址和图片模型名归一为统一模型中的字段，编辑后不会再被旧别名覆盖。音频历史独立转写/问答模型名会保留；主动修改统一模型名时，两种用途都改用新模型名。

模型目录、绑定关系和原执行配置由服务端一起保存。若出现「已保存，应用失败」，配置已经落盘，使用「重试」重新应用。保存过程不会为正在运行的任务增加配置快照保证，沿用现有热更新行为。

保存方式与普通模型一致：服务端读取当前配置后更新本次操作的模型或工具；多个页面修改同一模型时，以最后一次成功保存的内容为准。每次成功保存都会执行刷新，包括内容未改变的保存。删除或移除能力时，服务端仍会核对当前受影响工具；清单变化后需要重新确认。

本功能需要配套的 Web、AgentServer、独立 Gateway 和协议包版本。原两版共用的后端启动迁移统一升级，企业版设置页不增加模型或工具入口，已不维护的 TUI 不纳入此改造；Gateway 沿用原有版本分流，不额外限制六个新方法。目录初始化后，旧客户端不能绕过统一入口直接修改五类模型参数。
