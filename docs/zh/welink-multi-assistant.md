# WeLink 一群多助手

同一员工的阅读登录可以供多位 AI 同事共用。每位同事配置自己的助手 AK/SK，并在同事渠道页分别绑定或取消；新增、取消其他同事不会重启未变更的助手连接，也不会重置共享阅读游标。最后一位取消后停止阅读器，登录配置保留。

## 配置和使用

1. 在第一位同事的渠道页登录阅读账号，创建助手或填写 AK/SK。
2. 为第二位同事绑定另一套助手凭证，复用已有阅读登录。
3. 填写每位助手在群成员列表中的完整账号 `assistant_account`，用于确认该助手是否在群里。可以手填凭证时填写，也可以扫码创建助手后补充。
4. 自行把助手拉入群。平台 @ 通过对应助手连接，只唤醒该同事；普通消息按各同事自己的“被动/自适应”设置处理。

**身份映射限制：**目前尚无已验证的 AK 到群成员账号转换规则。程序匹配显式 `assistant_account`（或与 AK 完全相同的群成员账号），不按名字、下划线后缀猜测。映射缺失时，多助手的普通消息分发、发送确认和交接可能暂缓。旧单助手仅在唯一启用绑定且群中只有一个所属助手时保留原有兼容行为，增加第二个绑定后必须提供映射。

配置形状：

```yaml
channels:
  welink:
    account: "<员工账号>"
    cli_authorized: true
    reader_credential_dir: "<阅读目录>"
    bindings:
      - persistent_agent_id: "<同事ID>"
        assistant_credential_id: "<AK>"
        assistant_secret: "<SK>"
        assistant_account: "<群成员中的助手账号>"
        credential_dir: "<助手目录>"
        enabled: true
```

重复同事 ID、重复 AK、不同阅读账号和无效轮询间隔会在保存前拒绝。公开状态不包含 SK。旧单槽配置兼容读取，新保存采用 bindings；旧阅读目录不会因删除原同事而被清理。

## 首次补读、重启与交接

共享阅读器只轮询一次。每位同事首次观察某个群时独立补读最新页，使用原发送时间或原归档时间建立可读起点；既有同事的起点不变，窗外触发在创建任务前结束，不向群里发送失败说明。

群归档每条消息一份，各同事的任务各自去重。待处理队列、目标同事身份、提及与历史消息的别名均持久保存。暂时失败保留队列，重启继续；凭证转绑不会把旧同事的待处理任务投给新同事。

回复中的 `[[agent:id]]` 替换为可见姓名。发送后仍为未知，历史确认送达后，复查目标助手仍在群里，再以历史消息 ID 交接。已确认交接的待办可在重启后恢复，重复执行不重复建任务。真实平台 @ 帧字段未确认，本版本只实现本机交接，不自造协议。

## 部署边界

Gateway 与 AgentServer 一起升级。阅读账号仍只读，不代发、不建群、不拉人。核对由独立后台任务执行，仍只读取最新 20 条历史，未找到证据保持未知且不自动重发。忙碌群中较早结果可能需要人工核实。旧 account 路由只允许查询已有投递账本，不作为新发送的通道别名。

新增队列和别名文件随阅读目录保存；投递账本仍在各助手目录中。上述文件含会话资料，应与会话数据一起保留和管理。
