# 原生插件通用运行时

普通零参 Rail 插件无需声明运行时，沿用原有加载流程。需要主模型、轨迹或数据目录时，在 ZIP manifest 中声明通用契约，无需为插件新增宿主管理器：

```json
{
  "package_type": "plugin",
  "id": "notes",
  "name": "Notes",
  "version": "1.0.0",
  "metadata": {
    "plugin_runtime": {
      "contract_version": 1,
      "profiles": ["code"],
      "role_scope": "main",
      "requires": ["main_model", "agent_data_workspace"],
      "capabilities": ["notes"],
      "direct_tools": []
    }
  },
  "rails": [{"file": "rail.py", "class": "NotesRail"}]
}
```

requires 目前支持 main_model（模型/名称二元组）、trajectory（共享处理器及独立租约）、agent_data_workspace（数据根 Path）、embedding_factory（provider 构造能力）。未声明或不可用的服务调用 runtime.require 会报错。需要新基础服务时才扩展宿主，不能声明任意服务名就自动获得能力。

profiles 可以为 code、work 或两者；仅支持主 agent，不支持 team、子 agent 或其他 Harness。capabilities 为互斥能力名，同一 Agent 的目标集合不能重复。不同插件可同时运行；direct_tools 只标记已存在的工具，不创建工具。

## 插件自己解析配置和构造

```python
from openjiuwen.harness.rails.base import DeepAgentRail


class NotesRail(DeepAgentRail):
    @classmethod
    def prepare_plugin_context(cls, runtime):
        # Optional synchronous preflight. Do not start work or write data here.
        options = dict(runtime.package_config.get("notes", {}))
        options.update(runtime.options)  # host plugins.notes overrides
        if not isinstance(options.get("enabled", True), bool):
            raise ValueError("enabled must be a boolean")
        return options

    @classmethod
    def from_plugin_context(cls, *, params, context):
        runtime = context.extras["plugin_runtime"]
        if runtime.contract_version != 1:
            raise RuntimeError("Unsupported plugin runtime")
        rail = cls()
        rail.model, rail.model_name = runtime.require("main_model")
        rail.data_root = runtime.require("agent_data_workspace")
        rail.options = runtime.options
        return runtime.register_resource(rail)

    async def aclose(self, *, timeout, grace_timeout):
        # Stop admitting work, await real tasks, then clean owned attachments.
        # Return only when dependencies can safely be released.
        pass
```

host_config、package_config、options 为只读配置；预检返回 dict 会替换有效 options。服务及配置不序列化。prepare_plugin_context 只做校验和必要读取，不能启动后台工作或产生业务写入；构造资源必须在工厂返回前 register_resource，以便 init 失败时清理。

trajectory 在获取租约后才可用，因此应在 from_plugin_context 中请求，不能在 prepare_plugin_context 中请求。其他已声明服务可用于预检。

## 宿主提供的生命周期

宿主先预检全部候选，再获取租约/包快照并关闭旧绑定。工厂构造和 init 失败时恢复已变更运行插件的旧快照；配置、模型变化同样受 fresh-turn 限制。普通插件任意 Python 副作用和业务数据写入不属于全局事务。

默认关闭预算为 10 秒加 5 秒宽限。超时保留 closer、依赖和看护，不取消 awaiter 后冒充线程已停止。插件需要自己实现停止调度、真实任务收尾与专属附件清理。任务确认停止后宿主解绑并释放租约；其他插件/功能仍需采集时保持开启。

TTSE 2.0.0 是本机制的业务插件：选项、旧配置兼容、bank 校验、TTSEConfig 和归纳策略均在 ZIP 内。旧 TTSE 1.x 的 coding_runtime 声明不兼容，升级时配套导入新 ZIP 并重启宿主。core 继续提供同步 Rail 工厂、绑定清理和 TTSE 算法/关闭能力，无需为每个新插件改 core。
