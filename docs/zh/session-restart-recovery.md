# 会话恢复的时间、并发与取消边界

Front 从自身卡顿恢复后，按 IPC 解码时间判断收包新鲜度。旧 pong 出队不会刷新接收时间。探测登记前收到的近期请求完成结果，只在同一连接、同一 generation 且匹配实际发出的新请求时，作为一次存活证据。仅保留至多 256 项关联元数据，不保存业务正文。普通心跳超时和业务循环停滞阈值保持不变。

探针发送抛出连接异常，或发送失败时连接已关闭、接收端已有错误，均报告 `connection_closed`；其他发送错误保留 `write_failed`，便于区分断连与写失败。

冷恢复配额之前的历史预检只尝试非阻塞取锁；锁忙时转入有限并发的恢复路径，不占用共享 I/O 线程等锁。恢复并发和等待队列仍有上限。

复用旧 `HISTORY_RESTORE_LIMIT` 结论前，会验证原历史来源。校验中出现普通异常时放弃该缓存结论，交由受配额保护的历史恢复重新判断；取消信号继续传播。

历史中的重复终态回执和自动压缩审计不算后续模型活动。真实迟到的工具结果仍须与原调用保持成组，真实超限调用组仍会拒绝恢复；原始历史不会被重写或截断。

解归档登记阶段取消请求时，已落盘的操作也会记录失败并唤醒恢复。取消会等待已接纳的文件操作结束才释放执行所有权；失败记录只作用于该次 operation_id。

Worker 就绪不等于旧会话已恢复。验收还应确认旧历史进入新推理、新回合落盘、团队成员与任务保留以及进程退出清理。会话可继续使用也不表示崩溃时的外部工具副作用可以自动重放。
