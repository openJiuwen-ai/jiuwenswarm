# JiuwenSwarm 文档编写规范

本文档规定了 JiuwenSwarm 项目文档的编写规范，旨在确保文档风格统一、结构清晰、易于阅读和维护。

---

## 一、文档结构规范

每篇文档应遵循以下统一结构：

### 1.1 文档开头

文档开头必须包含以下元素（按顺序）：

```markdown
# 文档标题

> **目标**：简要说明本文档的目标和预期读者。
>
> **英文版：** [English Version](../en/对应英文文档.md)

---
```

**说明**：
- **标题**：使用一级标题 `#`，简明扼要地概括文档内容
- **目标**：使用引用块 `>` 说明文档目标，帮助读者快速判断是否需要阅读
- **英文版链接**：提供对应英文版本的链接，方便中英文切换
- **分隔线**：使用 `---` 分隔开头与正文

### 1.2 正文结构

正文使用二级标题 `##` 划分主要章节，使用阿拉伯数字编号：

```markdown
## 1. 章节标题

### 1.1 子章节标题

### 1.2 子章节标题

## 2. 章节标题

### 2.1 子章节标题
```

**编号规则**：
- 二级标题使用 `## 1.`、`## 2.` 等格式
- 三级标题使用 `### 1.1`、`### 1.2` 等格式
- 四级标题使用 `#### 1.1.1` 等格式（尽量避免超过四级）

**禁止使用**：
- ❌ 中文数字编号：`一、`、`二、`、`三、`
- ❌ 步骤式编号：`第一步`、`第二步`
- ❌ 无编号的二级标题（除特殊说明外）

### 1.3 文档结尾

文档结尾必须包含返回导航：

```markdown
---

## 返回导航

- [返回文档首页](../README.md)
- [返回项目首页](../../README_CN.md)
```

## 二、格式规范

### 2.1 标题层级

| 层级 | 用途 | 示例 |
|------|------|------|
| `#` | 文档主标题（仅一个） | `# 配置信息` |
| `##` | 主要章节 | `## 1. 模型配置` |
| `###` | 子章节 | `### 1.1 配置项说明` |
| `####` | 细分内容（尽量少用） | `#### 配置示例` |

### 2.2 列表格式

**无序列表**：使用 `-` 符号

```markdown
- 项目一
- 项目二
  - 子项目
```

**有序列表**：使用数字加点

```markdown
1. 第一步
2. 第二步
   1. 子步骤
```

### 2.3 表格格式

表格应包含表头和分隔线：

```markdown
| 列1 | 列2 | 列3 |
|-----|-----|-----|
| 内容1 | 内容2 | 内容3 |
```

### 2.4 代码块

代码块必须指定语言：

````markdown
```yaml
api_base: https://api.example.com
api_key: your-api-key
```
````

### 2.5 提示与警告

使用引用块表示提示信息：

```markdown
> 💡 **提示**：这是提示信息。

> ⚠️ **注意**：这是警告信息。

> ❌ **禁止**：这是禁止事项。
```

## 三、内容规范

### 3.1 语言风格

- 使用简洁、准确的语言
- 避免口语化表达
- 技术术语保持一致
- 使用第二人称"您"称呼读者

### 3.2 链接规范

- 内部链接使用相对路径
- 外部链接使用完整 URL
- 链接文字应描述目标内容，而非"点击这里"

**正确示例**：
```markdown
详细配置请参考：[模型配置](#1-模型配置)
```

**错误示例**：
```markdown
点击[这里](#1-模型配置)查看
```

### 3.3 图片规范

- 图片文件存放在 `docs/assets/images/` 目录
- 使用相对路径引用图片
- 添加图片说明（alt text）

```markdown
![配置面板界面](../assets/images/config-panel.png)
```

## 五、检查清单

在提交文档前，请确认以下事项：

- [ ] 文档包含统一的开头格式（目标 + 英文版链接）
- [ ] 章节使用阿拉伯数字编号（1. 2. 3.）
- [ ] 标题层级正确（#、##、###）
- [ ] 代码块指定了语言
- [ ] 图片路径正确且有说明文字
- [ ] 内部链接使用相对路径
- [ ] 文档底部包含返回导航
- [ ] 语言简洁准确，无口语化表达
- [ ] 技术术语保持一致
