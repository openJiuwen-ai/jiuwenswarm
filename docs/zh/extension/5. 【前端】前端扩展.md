# 5 前端扩展

前端扩展让扩展包把一棵受控的组件树挂到 JiuwenSwarm 已经预留的界面位置，并通过事件与宿主交互。
扩展包负责声明界面项、生成组件树和处理事件；Web Client 负责渲染，Gateway 或 AgentServer 负责校验目标、维护实例并把交互送入事件链。

本文集中回答三个问题：哪些界面位置可以扩展、每个组件可以做什么、组件交互怎样回到扩展处理逻辑。
完整的属性表、事件数据和跨模块映射以仓库中的组件规约与功能文档为准。

## 三层如何分工

| 层 | 负责什么 | 开发者需要关心的边界 |
| --- | --- | --- |
| Web Client | 接收 `webui.render`、维护显示实例、渲染组件树、保存必要的本地交互状态，并通过 `webui.dispatch` 上送交互 | 浏览器只提交当前已显示树中的目标、版本和动作；不能把浏览器上报的数据当成可信状态 |
| AgentServer | 承载会话级槽位，维护会话实例和组件事件规则，触发 `ui.*` 事件并执行扩展 Handler | 会话槽位必须有会话上下文；事件数据、槽位归属和实例版本在业务 Handler 之前校验 |
| Gateway | 承载应用级槽位，维护 Web 连接级实例，并提供素材、请求绑定、本地存储和刷新等浏览器能力 | Gateway 当前只接收应用范围的 `application.entry` 与 `application.sidebar.footer`；浏览器操作只投递到当前包和当前连接 |

这三层共享渲染帧、组件树和交互协议，但不共享槽位登记表：AgentServer 与 Gateway 各自维护自己的槽位和组件校验规则。

## 从 `manifest.json` 声明界面贡献

扩展包在 `manifest.json` 的 `ui` 段声明界面项；宿主读取已激活扩展包的清单，生成界面贡献目录。清单只声明可挂载位置和渲染器，当前会话里的具体组件树仍由 Handler 通过 `ops.ui.render()` 下发。

```json
{
  "ui": {
    "apiVersion": 1,
    "items": [
      {
        "type": "web.slot.contribution",
        "id": "token-weather.turn",
        "slot": "message.assistant.meta",
        "order": 10,
        "panel": {
          "title": "Turn Usage"
        },
        "renderer": {
          "kind": "webui-tree"
        }
      }
    ]
  }
}
```

| 字段 | 作用 | 约束 |
| --- | --- | --- |
| `apiVersion` | 声明界面协议版本 | 当前只接受 `1` |
| `items[].type` | 区分界面贡献项和语言资源项 | 当前支持 `web.slot.contribution`、`web.locale` |
| `items[].id` | 标识包内的界面项 | 同一包内同类型必须唯一 |
| `items[].slot` | 选择宿主槽位 | 界面贡献项必填，必须是宿主已登记的槽位 |
| `items[].order` | 控制同一槽位中的顺序 | 可选，默认值为 `0` |
| `items[].panel.title` | 提供面板或页签标题 | 当前用于 `Panel`、`Iframe` 等宿主容器 |
| `items[].renderer.kind` | 选择渲染器 | 当前只接受 `webui-tree` |
| `items[].localeId`、`resources` | 关联包内语言资源 | 路径不能逃逸扩展包根目录 |

一个扩展包只要有一项界面声明非法，该包的界面项就不会发布；其他扩展包不受影响。
扩展包只能选择槽位，不能在 `manifest.json` 中自定义槽位的范围、展示模式或页面位置。

## 组件树怎样被渲染

扩展 Handler 通过 `ops.ui.render` 下发一棵 `webui-tree`，每个节点包含组件名、受控 props、可选的子节点和可选的 `events` 声明。
宿主先校验整棵树，再把渲染帧发给 Web Client；Web Client 只从受控组件目录中查找渲染器。

组件树不是任意 HTML：

- 节点只能使用当前宿主登记的组件名和 props，未知字段、未知事件和任意 `style` / `className` 会被拒绝。
- `Box`、`Card` 等组合组件可以承载普通子节点；`Panel`、`Iframe` 只能作为允许它们的槽位根节点；`Tabs` 的内容放在 `items[].children`。
- 节点深度最多 8 层，属性深度最多 24 层，单个列表最多 100 项，整棵树最多 512 个节点，单字段文本最多 16 KiB，完整渲染帧最多 256 KiB。
- 同一会话最多同时维护 32 个 WebUI 实例，动作参数序列化后最多 8 KiB。
- `replace`、`clear`、断连、渲染失败或实例释放都会使旧节点绑定失效；旧版本的交互不能作用于新树。

## 组件支持的逻辑

下面按用途整理当前组件目录。表中的“输入”指扩展包声明的关键 props，“输出”指组件可能产生的上行事件；完整字段仍以 S_17 为准。

### 布局与展示组件

| 组件 | 可以做什么 | 关键输入 | 交互输出与限制 |
| --- | --- | --- | --- |
| `Box` | 组织横向或纵向布局，控制间距、对齐、换行和弹性伸缩 | `direction`、`gap`、`align`、`justify`、`wrap`、`flex`；Gateway 另支持 `width`、`height`、`padding`、背景图和 `visibleFrom` | 不产生事件；Gateway 的尺寸值受 0–4096、百分比和 `auto` 规则约束，低于 `visibleFrom` 时隐藏并停用子树交互 |
| `Text` | 显示一段带语义色或排版效果的文字 | `value`、`type`、`size`、`strong`、`italic`、`code`、`mark`、`ellipsis` 等 | 不产生事件；文案使用 `value`，不接受节点子树 |
| `Empty` | 显示无数据或空列表状态 | `image`、`description` | 不产生事件；`image` 只能是内置空态名或合法资源地址 |
| `Image` | 显示扩展包素材、预览图或带失败回退的图片 | `src`、`alt`、`width`、`height`、`fallback`、`preview`；Gateway 另支持 `fit` | 预览由浏览器本地处理，不产生业务事件；Dropdown 触发区中的图片必须显式 `preview: false` |
| `Divider` | 在内容之间显示水平或垂直分隔线，可带标题 | `children` 字符串、`orientation`、`variant`、`titlePlacement`、`plain` | 不产生事件；字符串标题与 `Text` 子节点二选一，垂直分隔线不能带标题 |
| `Card` | 把标题、封面和一组内容组织成卡片 | `title`、`extra`、`cover`、`hoverable`、`size`、`variant` | 不产生业务事件；允许普通子节点，`cover` 必须是合法资源地址 |
| `Tag` | 显示状态、分类或可选链接标签 | 字符串 `children`、`color`、`variant`、`disabled`、`href`、`target` | 不产生业务事件；文案使用 `children`，不能改写成 `value`；只有提供 `href` 时才作为链接 |
| `Avatar` | 显示图片头像或扩展包指定的文字头像 | `src`、字符串 `children`、`alt`、`gap`、`size`、`shape`、受控 `style` | 不产生事件；宿主不从账号名推导首字母、颜色和字号，图片失败后的文字由组件按声明显示 |
| `Icon` | 显示一个受白名单约束的图标 | `name`、`size`、`aria-label` | 不产生事件；当前由 AgentServer 前端目录提供，名称必须来自图标白名单，不接受任意 SVG |

### 输入与交互组件

| 组件 | 可以做什么 | 关键输入 | 交互输出与限制 |
| --- | --- | --- | --- |
| `Button` | 触发动作、显示加载状态或打开链接 | `value`、`type`、`color`、`variant`、`shape`、`loading`、`disabled`、`href`、`target`、`icon`、`aria-label` | `ui.click`；普通按钮的 `data` 为 `{}`，禁用、加载或断连时不发送；纯图标按钮必须有非空 `aria-label` |
| `Input` | 接收单行文本，支持清空、输入法组合和 Enter 提交 | `value`、`defaultValue`、`placeholder`、`maxLength`、`allowClear`、`type`、`readOnly`；Gateway 另支持 `autoComplete` | `ui.click` 为 `{value}`；`ui.change` 为 `{value, isComposing}`；`ui.press_enter` 为 `{value}`；只读输入框只允许 click |
| `Switch` | 提供布尔开关，适合设置项和功能切换 | `checked`、`defaultChecked`、`loading`、`disabled`、`checkedChildren`、`unCheckedChildren` | `ui.change` 与 `ui.click` 都可发送 `{checked}`；初始化和合法 replace 不发送事件，loading 或 disabled 时不可操作 |
| `Select` | 提供单选、多选、标签输入、搜索和清空 | 必填 `options`，以及 `value`、`defaultValue`、`mode`、`maxCount`、`showSearch`、`allowClear` | `ui.select` 为单个 `{value}`；`ui.change` 为整体 `{value}`；`ui.search` 为 `{searchValue}`；`ui.clear` 为 `{}`；选项值必须唯一且类型一致 |
| `TreeSelect` | 提供树形单选、多选或勾选 | 必填 `treeData`，以及 `value`、`multiple`、`treeCheckable`、展开和搜索相关 props | `ui.select` 为单个 `{value}`；`ui.change` 为整体值；`ui.clear` 为 `{}`；树最多 8 层、512 项，禁用节点不能通过交互新增 |
| `Slider` | 提供区间内的数值选择、刻度和 marks | `min`、`max`、`step`、`value`、`defaultValue`、`marks`、`dots`、`orientation` | `ui.change` 为 `{value}`，每次合法变化独立发送，不等待前一请求；数值必须满足区间、步长或 marks 规则 |
| `Tabs` | 在一棵组件树中组织多个页签内容 | 必填 `items`，以及 `activeKey`、`defaultActiveKey`、`type`、`tabPlacement`、`destroyOnHidden` | `ui.change` 为 `{activeKey}`；隐藏内容仍参与整树校验；默认保留隐藏页状态，`destroyOnHidden: true` 时切回重新初始化 |
| `Dropdown` | 提供本地展开的菜单和选项选择 | 必填 `items`，以及 `trigger`、`placement`、`disabled`；AgentServer 可用 `icon` 或展示型子树，Gateway 使用一个展示型子树 | 菜单项选择通过 `ui.select` 发送 `{key}`；打开和关闭不产生业务事件；禁用项、分隔项、重复 key 或空 label 会被拒绝 |

### 文件、面板与页面组件

| 组件 | 可以做什么 | 关键输入 | 交互输出与限制 |
| --- | --- | --- | --- |
| `FileTree` | 展示会话工作区目录，保留展开、选择、滚动和本地宽度状态 | 必填 `treeData`，以及 `selectedKey`、`expandedKeys`、`status`、`truncated`、`readFailed` | `ui.select` 为 `{key}`；`ui.change` 为 `{key, expanded, expandedKeys}`；目录状态不是扩展包自报路径，数据应来自 `ops.session.files` |
| `FilePreview` | 预览文本、图片和受管 PDF，或显示文件缺失、禁止和读取失败状态 | 必填 `file`，可为 `null`；非空文件至少提供 `name`、`path` 和 `content` / `downloadUrl` 之一 | 不产生业务事件；HTML 只按文本显示，PDF 使用受管同源地址，内部 PDF iframe 不等于通用 `Iframe` |
| `Panel` | 创建宿主管理的页签型面板 | 必填 `title`，并提供非空子树 | 不产生事件；只能作为允许该组件的槽位根节点，不能嵌套 `Panel` 或 `Iframe` |
| `Iframe` | 在宿主管理的页面区域加载外部或扩展页面 | 必填 `src`、`title` | 不产生事件；只允许作为专用槽位根节点，宿主固定 sandbox，不包含 `allow-same-origin`；只有激活且连接有效时加载 |

### Gateway 独有的表单逻辑

Gateway 组件目录额外提供 `Form` 和 `Form.Item`，AgentServer 组件规则不启用这两个组件。

| 组件或能力 | 可以做什么 | 输入与输出 | 约束 |
| --- | --- | --- | --- |
| `Form` | 在同一渲染实例中管理一组字符串字段，并在浏览器本地进行失焦和确认校验 | 必填唯一 `name`，可选 `layout`、`disabled`、`ariaLabel`、`requiredMark`；本身不产生事件 | 只能包含 `Form.Item`，不允许嵌套 `Form`；隐藏页签保留字段值，clear、replace、断连或实例结束后重新初始化 |
| `Form.Item` | 把一个 `Input` 绑定到表单字段，并显示字段标签和校验错误 | 必填唯一 `name`，可选 `label`、`rules`；必须恰好包含一个不声明上行事件的 `Input` | `rules` 只支持字符串规则 `required`、`min`、`max`、`pattern`、`message`，不接受函数和自定义 validator |
| `Button.form` | 让按钮提交指定表单并把字段值作为一次点击数据发送 | `form` 引用同一渲染实例中的 `Form.name` | 校验通过后 `ui.click.data` 是以字段名为键的对象；引用无效或校验失败时不发送普通点击事件 |

表单的字段值来自 `Form.Item` 中 `Input` 的 `value`、`defaultValue` 或空字符串。
表单输入框使用本地事件，不在 `Form.Item` 内声明 `ui.change` 或 `ui.press_enter`。

## 组件事件怎样传给扩展

组件是否能够产生上行事件，不由组件名称推断，而由节点的 `events` 声明和当前组件规则共同决定。
扩展应按事件表读取 `payload.data`，不要依赖前端 DOM 事件对象。

| 组件 | 事件 | `payload.data` | 触发时机 |
| --- | --- | --- | --- |
| `Button` | `ui.click` | 普通按钮为 `{}`；Gateway 的 `Button.form` 为字段对象 | 用户点击或键盘确认，且节点已绑定、未禁用、未加载 |
| `Input` | `ui.click` / `ui.change` / `ui.press_enter` | 分别为 `{value}`、`{value, isComposing}`、`{value}` | 点击、有效编辑、非输入法组合期间按 Enter |
| `Switch` | `ui.click` / `ui.change` | `{checked}` | 点击后按声明分别发送；初始化不发送 |
| `Select` | `ui.select` / `ui.change` / `ui.search` / `ui.clear` | 单项值、整体值、搜索文本或 `{}` | 选择、整体值变化、搜索、清空 |
| `TreeSelect` | `ui.select` / `ui.change` / `ui.clear` | 单项值、整体值或 `{}` | 选择、整体值变化、清空 |
| `Slider` | `ui.change` | `{value}` | 每次合法拖动或键盘调整 |
| `Tabs` | `ui.change` | `{activeKey}` | 切换到已存在且未禁用的页签 |
| `Dropdown` | `ui.select` | `{key}` | 选择已存在且未禁用的菜单项 |
| `FileTree` | `ui.select` / `ui.change` | `{key}` 或 `{key, expanded, expandedKeys}` | 选择文件、展开或收起目录 |

初始化、合法的 `replace` 和本地状态恢复通常不发送事件；没有绑定事件时，组件仍可能在浏览器内完成本地交互。
例如没有绑定 `Select.ui.change` 时，用户仍可以选择选项，但不会把选择送入扩展事件链。

## 交互校验与宿主兜底

`webui.dispatch` 是前端交互的唯一上行入口。宿主按以下顺序校验请求：

1. 校验事件名、目标范围、会话或连接归属，以及扩展包是否仍处于激活状态。
2. 校验槽位是否允许该扩展包、实例是否存在、实例 `revision` 是否仍是当前版本。
3. 从当前渲染树按 `node_key` 找到节点，确认事件、`action_id` 和 `args` 与节点声明完全一致。
4. 按组件规则校验 `data`，包括选项合法性、禁用状态、文本长度、表单字段集合和动作参数大小。
5. 通过校验后才触发 `ui.*` 事件链，交给扩展 Handler 继续处理。

失败发生在业务 Handler 之前：

| 情况 | 宿主行为 | 扩展侧应如何处理 |
| --- | --- | --- |
| 没有界面贡献项 | 返回 `no_contribution` 或对应稳定错误码 | 检查 `manifest.json` 是否声明了当前槽位，并等待目录更新 |
| 实例不存在、已清空或版本过期 | 返回 `inactive` / `stale`，错误码通常为 `TARGET_INACTIVE` | 丢弃旧交互，不重试旧 `revision`；需要恢复时重新执行 `ui.ready` 或重新渲染 |
| 节点、事件、动作或 data 不匹配 | 返回 `invalid_action`，错误码通常为 `SCHEMA_ERROR` | 以当前渲染树为准重新生成动作，不在客户端拼接旧 payload |
| Handler 没有接住事件 | 返回 `no_handler` 或 `unhandled` | 检查事件名、槽位目标和 Handler 注册情况 |
| 连接关闭或扩展包失活 | 清理连接级实例，拒绝旧代次的渲染和浏览器操作 | 将连接重建视为新生命周期，重新等待 `ui.ready` |

这层校验是前端扩展的核心兜底逻辑：客户端的禁用态和版本判断只改善交互体验，不能替代宿主的可信校验。

## Gateway 的浏览器能力

Gateway 扩展除了渲染应用槽位，还可以使用当前 Web 连接提供的浏览器能力。
这些能力不通过组件事件声明，而是由当前扩展包、连接和激活代次自动归属。

| 能力 | 扩展侧调用 | 输入与结果 | 使用边界 |
| --- | --- | --- | --- |
| 扩展素材地址 | `ops.ui.asset_url(path)` | 输入扩展包 `assets` 目录内的相对路径，返回带包 ID 和激活代次的 URL | 只能读取当前激活包的素材；包失活后旧 URL 返回 404 |
| 写入本地存储 | `ops.client.local_storage.set(key, value)` | `key` 为非空字符串，`value` 为有限 JSON；返回 `{"accepted": true, "status": "queued"}` | 只投递到发起调用的浏览器；不等待浏览器执行回执，不提供查询或重试 |
| 删除本地存储 | `ops.client.local_storage.delete(key)` | 输入 `key`；返回排队结果 | 存储按 Gateway、扩展包和连接归属，调用者不能指定其他浏览器 |
| 刷新当前页面 | `ops.client.page.reload()` | 无参数，返回排队结果 | 不需要额外声明；是否刷新由扩展显式决定，存储变化不会自动刷新页面 |
| 请求绑定 | `client.requestBindings` | 在包声明中描述哪些主 WebSocket RPC 或 Gateway HTTP 请求携带绑定参数 | 绑定不等于认证；请求仍进入 `gateway.request`，策略由扩展 Handler 决定 |

浏览器操作会通过 `client.operation` 单向投递。
其中 `invocation_id` 只用于关联原请求的结束等待，不代表浏览器执行回执；当前协议没有逐操作回执、去重、重试或 token 有效期语义。

## 开发时如何选择槽位和组件

先按页面位置选择槽位，再按交互复杂度选择组件：

| 需求 | 推荐槽位 | 推荐组件组合 |
| --- | --- | --- |
| 给聊天输入补充提示或开关 | `conversation.input.above` / `conversation.input.below` | `Box` + `Text` / `Switch` / `Button` |
| 给一轮回复增加统计或操作 | `message.assistant.meta` / `conversation.turn.footer.actions` | `Text` / `Tag` / `Button` / `Dropdown` |
| 在回复右侧提供独立工作区 | `conversation.panel.right` | 根 `Panel` 或 `Iframe`，内部使用 `Box`、`Text`、`FileTree` 等 |
| 提供扩展级导航入口 | `application.menu` / `application.menu.main` | 菜单项使用 `Button`、`Icon`、`Avatar`，主页面使用普通组件树 |
| 提供 Gateway 应用入口或登录页 | `application.entry` / `application.sidebar.footer` | Gateway 组件树；需要字段校验时使用 `Form`、`Form.Item`、`Button.form` |
| 显示会话文件 | `conversation.panel.right` 或消息相关槽位 | `FileTree` + `FilePreview`，数据来自会话文件能力 |
| 加载扩展自己的网页 | `conversation.panel.right` 或应用主页面 | `Iframe`，同时接受宿主的沙箱和激活生命周期 |

推荐遵循三个原则：

- 优先选择语义最接近的预定义组件，避免把多个交互塞进 `Dropdown` 的展示区。
- 把服务端状态放在 render props 中，把浏览器临时状态交给组件本地维护；需要业务决策时再绑定事件。
- 对会话级内容使用会话槽位，对包级或连接级内容使用应用槽位，不要通过 `instance_key` 模拟另一种范围。

## 验证前端扩展

前端目录已经提供针对组件目录、协议、运行时、事件和渲染器的定向测试；在 `jiuwenswarm/channels/web/frontend` 目录执行：

```bash
npm run test:webui-contracts
npm run test:webui-components
npm run test:webui-protocol
npm run test:webui-runtime
npm run test:webui-events
npm run test:webui-renderer
```

涉及输入法、文件树、Gateway 表单或浏览器桥接时，还应补跑对应的前端测试和 Gateway 单元测试。
文档层面的检查至少包括：`manifest.json` 中的槽位在目标宿主登记表中、组件名属于目标宿主目录、事件 data 与当前组件规约一致、重连和 clear 后不会复用旧实例。
