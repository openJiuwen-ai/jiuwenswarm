# WeLink 消息可靠性

WeLink 网关和 AgentServer 需要使用同一版本升级。本次修复适用于 `jiuwenmate_0.2.8`，不改变视觉模型配置。

## 入站消息

格式错误、绑定不匹配的消息作为永久拒绝处理，允许推进游标。队列满、调度器关闭、存储或服务暂时不可用时返回 `retryable`，不推进游标；待处理批次先保存到账号凭据目录的 `pending-*.json`，重启后继续处理。服务端仍通过原 `source_ref` 去重。

## 群成员权限

已共享群与未共享群均参与成员复查，默认复查间隔为 60 秒。成功结果的时间写入 `membership.json`，默认有效期为 300 秒。一次失败或 429 不会立即撤销仍有效的共享状态；明确查询到不再共享，或旧结果过期而无法重新确认时，停止读取该群。发送结果核对也遵守此边界。

## 回复关联

历史消息 ID 可以登记为已匹配提及的别名，但不会替换正在执行的 Request 使用的原消息 ID。文本兜底对齐要求同群、同发送者且候选唯一；已有别名的任务不会被另一条历史消息再次认领。回复只按原 ID 或已登记别名选取问答任务；不匹配时发送独立群消息。

提及尚未受理时，轮询消息不会被视为已经处理；如两条路径并发到达，统一消息 ID 后交由服务端去重。

## 发送与核对

每次发送在写 WebSocket 前，先在凭据目录的 `deliveries-*.sqlite3` 保存发送意图、幂等键、群、正文、助手身份、发送前历史位置和协议关联 ID。该文件权限限制为当前用户读写；它包含消息正文，应与其他会话数据一同保护。

`send()` 返回只代表本地写入，不代表群中已收到，投递保持 `unknown`。服务端每 10 秒轮转核对一条未知投递，网关只查询历史：

- 同群、同助手、同正文，且消息 ID 为本次协议 ID，或位于发送前的数字游标之后，才作为候选证据。按正文核对只允许唯一助手身份。
- 候选唯一且未被其他投递使用，确认 `delivered`，保存真实历史消息 ID。
- 收到与本次发送关联的 `tool_error`，且历史未查到成功证据，确认 `failed`。
- 查询失败、历史页没有覆盖结果、候选不唯一、旧版本缺少发送意图时，继续保持 `unknown`。仅凭“没查到”不会判失败。

未知投递不会自动重发；相同正文在同群有未解决投递时，新投递暂缓发送以避免混淆核对证据。重启后也保持这一规则。已确认结果继续走原有归档流程。

当前历史接口每页 20 条，核对只读取最新一页。因此活跃群的旧结果可能一直保持未知，需要人工核实；不能直接把未知行改回待发送。升级不会重写旧版本已经标记为已送达的记录。
