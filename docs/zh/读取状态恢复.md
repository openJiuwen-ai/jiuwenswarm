# 读取状态恢复（Code 模式）

`ReadRestoreRail` 解决的问题：Code 会话在新进程中继续时，`edit_file` / `write_file` 被拒绝并提示「File must be read before editing」。

## 1. 为什么需要

agent-core 只允许编辑已经用 `read_file` 读过的文件，且这一记录保存在进程内存中。会话一旦换到新进程继续，之前的读取记录全部丢失：

* **无头实现驱动**（`jiuwenswarm-process --implement`）每一轮续跑都启动新进程。在 20 题 SWE-bench Pro 评测中，每次运行 `edit_file` 被拒 33–80 次，其中 95% 以上是之前轮次已经读过的文件。每次被拒都要重读并重试（每次运行多出 50–67 次模型调用、370 万–560 万输入 token，占全部输入的 6.5%–9%）。每次运行最多有 19 次在重试前本轮就结束了；最多有 10 次模型放弃 `edit_file`，改用 shell（`sed -i`、Python 写文件）修改文件，而编辑工具、变更追踪和按路径匹配的钩子都看不到这类修改。
* **桌面端和其他渠道**：AgentServer 重启后恢复会话时也会遇到同样的拒绝。

驱动在每轮续跑时已经提示模型先调用 `read_file`，`edit_file` 的工具说明和 Code 提示词里也都有这一要求，但拒绝仍然发生。

## 2. 工作方式

* **记录。** 每次 `read_file`、`edit_file`、`write_file` 成功后，Rail 为当前会话（`session.get_session_id()`）记录该文件的大小、修改时间、SHA-256 和行数；读取还会记录读过的行区间。记录保存在 `<agent 根目录>/read_restore/<会话>.json`（默认 `~/.jiuwenswarm/agent/read_restore/`），从不写入项目目录。每个会话最多保留 400 个文件，最多保留 500 个会话文件，超出时先删除最旧的。
* **恢复。** 对已存在的文件执行 `edit_file` 或 `write_file` 之前，如果 agent-core 在本进程中没有该文件的读取记录，Rail 会查找本会话的记录。只有文件内容与 agent 当时看到的完全一致（大小和哈希相同）时，Rail 才调用 agent 自己已注册的 `read_file` 工具，由 agent-core 自己登记这次读取，然后编辑照常进行。`edit_file` 只读一行（agent-core 对编辑接受任何读取）；`write_file` 则以每次 500 行的窗口读完整个文件，并且只在本会话曾通过 `read_file` 读完整个文件时才恢复：agent-core 只允许 `write_file` 覆盖已完整读取的文件，编辑或写入在 agent-core 中也不算完整读取。
* **不恢复**的情况（agent-core 的拒绝保持不变，模型照常重新读取）：
  * 本会话看到之后文件已被修改（其他进程、用户或 shell 命令）；
  * 本会话从未读取、编辑或写入过该文件（不会使用其他会话的记录）；
  * 当前读取策略拒绝或需要询问：只拒绝的项目策略（`.jiuwenswarm/permissions.yaml`，安装了该功能包时），以及 `permissions.enabled` 为 true 时权限引擎对该路径 `read_file` 的判定（规则与文件守卫）。策略检查出错时同样不恢复；
  * 文件大于 8 MiB，或是 PDF、Notebook、图片；
  * 该调用已被更早的 Rail 拒绝。

Rail 从不把文件内容返回给模型，也不修改 agent-core：恢复就是用 agent 自己的 `SysOperation` 正常调用一次 agent-core 公开的 `read_file` 工具。

## 3. 配置

```yaml
modes:
  code:
    read_restore:
      enabled: true   # false = 不记录也不恢复（即 agent-core 原本行为）
```

每次调用都会重新读取该开关，配置热加载后无需重建 agent 即可生效。

## 4. 如何确认已生效

每次恢复都会输出一条 INFO 日志：

```
[ReadRestore] restored read state of /path/to/file.py for edit_file (session <id> saw it earlier)
```

因文件已变化而跳过时会输出 `[ReadRestore] not restoring … changed since session … saw it`。

## 5. 限制

* agent-core 的读取记录在同一进程内由所有会话共享。在长时间运行的 AgentServer 中，会话 B 本来就能编辑只有会话 A 读过的文件；本 Rail 不改变这一点（这是 agent-core 的行为，已作为上游问题报告）。
* 文件被改动后又改回完全相同的字节，会被视为未变化。
* 恢复按会话进行。新会话（例如在同一项目上新开的桌面对话）与以前一样没有记录。
