# 项目与会话管理（Web 端）

> **实现**：`jiuwenswarm/gateway/channel_manager/web/app_web_handlers.py`（handler 注册）、`jiuwenswarm/gateway/channel_manager/web/git_ws_handler.py`（Git Diff WebSocket）、`jiuwenswarm/server/runtime/session/project_store.py`（项目存储）、`jiuwenswarm/server/runtime/session/session_metadata.py`（会话元数据）、`jiuwenswarm/server/runtime/session/project_git.py`（Git 操作）、`jiuwenswarm/server/runtime/session/git_diff_status.py`（Diff 聚合）、`jiuwenswarm/server/runtime/session/git_diff_watcher.py`（Diff 监控）
> **English**: [../en/Project-Session-Management.md](../en/Project-Session-Management.md)

---

## 1. 概述

Web 端提供项目（Project）维度的会话管理能力。会话通过 `project_id` 绑定到指定项目,也可使用默认空项目。项目与项目之间通过 `project_id` 建立归属关系。

当前实现额外引入 `work_mode` 维度,将普通办公协作与代码工程隔离管理。`code` 模式项目支持 Git 状态、分支、Diff 历史、实时监控与撤销/重做本轮文件修改;`work` 模式保持普通项目/会话能力。

### 核心概念

| 概念 | 说明 |
|------|------|
| **默认项目** | 不入库,由接口动态注入,`project_id="default"`。禁止 rename / remove / pin。会话 `project_id` 为空或不匹配任何可见项目时归入默认项目 |
| **工作模式 `work_mode`** | 项目/会话/定时任务的隔离维度,取值 `work` 或 `code`。Web 默认 `work`,TUI 默认 `code` |
| **代码默认项目** | `project_id="default_code"`,不入库,用于承接未绑定真实 code 项目的会话。与 `default` 分别对应 `code` / `work` 两个默认桶 |
| **Code 项目 Git 能力** | 真实 `code` 项目开放 Git 状态、初始化、分支、Diff、历史变更和撤销/重做接口。默认项目和 `work` 项目不开放 Git 操作 |
| **软删除** | `project.remove` 标记 `hidden:true`,不删记录,可恢复。隐藏期间其下非置顶会话临时归入默认项目 |
| **置顶会话** | 从项目分组中剥离,通过 `project.pinned_sessions` 独立获取,按 `pin_order` 升序排列 |
| **置顶项目** | 与非置顶项目视觉区分,置顶项目在前(按 `pin_order` 升序) |
| **project_id / project_dir / work_mode 不可变** | 会话首次绑定 `project_id`、`project_dir` 和 `work_mode` 后不可修改,不提供跨项目/跨模式迁移接口 |

### 通信约定

- 传输方式：WebSocket JSON 消息
- 请求结构：`{ "id": "<req_id>", "method": "<方法名>", "params": { ... } }`
- 响应信封（所有接口统一）：

| 字段 | 类型 | 必返 | 说明 |
|------|------|------|------|
| `ok` | boolean | 是 | 成败标志 |
| `payload` | object | 成功时 | 响应数据 |
| `error` | string | 失败时 | 错误描述 |
| `code` | string | 失败时 | 错误码 |

### session_id 生成约定

- `session_id` 由**前端生成**,格式：`sess_<16进制毫秒时间戳>_<6位16进制随机>`
- `sess_` 前缀是 Web 端强约定：仅 `sess_` 开头的会话支持 `history.get` 恢复历史
- 后端不校验该格式,但前端必须遵循

## 2. 数据结构

### ProjectInfo

`project.list` 返回此结构。

| 字段 | 类型 | 说明 |
|------|------|------|
| `project_id` | string | 项目唯一标识;默认项目为 `"default"` |
| `name` | string | 展示名 |
| `project_dir` | string | 工作目录绝对路径;默认项目为空串 `""` |
| `pinned` | boolean | 是否置顶 |
| `pin_order` | integer | 置顶顺序,越小越靠前;未置顶为 0 |
| `is_default` | boolean | 是否默认项目 |
| `hidden` | boolean | 是否已软删除;默认项目恒为 false |
| `session_count` | integer | 该项目下**非置顶**会话数 |
| `last_message_at` | number \| null | 该项目下最新消息时间戳(UTC 秒);无会话为 null |
| `last_user_message_at` | number \| null | 该项目下最新用户消息时间戳(UTC 秒);无用户消息时回退到 `created_at` |
| `created_at` | number | 创建时间戳(UTC 秒);默认项目为 0 |
| `updated_at` | number | 更新时间戳(UTC 秒);默认项目为 0 |
| `work_mode` | string | 工作模式,`work` 或 `code` |
| `git` | object | Git 状态快照。`code` 项目由 Git 探测/操作写入;`work` 与默认项目通常为 disabled/空状态 |

### GitStatus

`ProjectInfo.git` 与 Git RPC 响应中的 `repo` 用于展示代码项目的仓库状态。

| 字段 | 类型 | 说明 |
|------|------|------|
| `enabled` | boolean | 项目是否启用 Git 能力(持久化快照字段) |
| `status` | string | 探测状态,如 `ready` / `not_git` / `git_missing` / `transient` / `error` / `disabled` |
| `repo_root` | string \| null | Git 仓库根目录 |
| `branch` | string \| null | 当前分支;detached 时可能为 HEAD 短哈希 |
| `head` | string \| null | HEAD 短哈希 |
| `is_dirty` | boolean | 工作区是否有变更 |
| `error` | object \| null | 结构化 Git 错误,包含 `code`、`message`、`hint` 等 |

### SessionInfo

`project.get_sessions` / `project.pinned_sessions` 返回此结构。从 `metadata.json` 投影,排除 `delivery_context` / `channel_metadata` 等内部字段。

| 字段 | 类型 | 说明 |
|------|------|------|
| `session_id` | string | 会话唯一标识 |
| `title` | string | 会话标题 |
| `created_at` | number | 创建时间戳(UTC 秒) |
| `last_message_at` | number | 最后消息时间戳(UTC 秒) |
| `message_count` | integer | 消息数 |
| `mode` | string | 会话模式 |
| `pinned` | boolean | 是否置顶 |
| `pin_order` | integer | 置顶顺序;未置顶为 0 |
| `project_id` | string | 绑定项目 ID;空串为默认项目 |
| `project_dir` | string | 绑定项目路径;空串为默认项目 |
| `work_mode` | string | 会话工作模式,`work` 或 `code` |
| `last_user_message_at` | number \| null | 最后一次用户消息时间戳(UTC 秒);无用户消息时回退到 `created_at` |
| `model` | string | 当前使用的模型标识;未设置时为空串 |

### mode 有效值

| 值 | 说明 |
|------|------|
| `agent.plan` | Agent 规划模式 |
| `agent.fast` | Agent 快速模式 |
| `code.plan` | Code 规划模式 |
| `code.normal` | Code 普通模式(默认) |
| `code.team` | Code 团队模式 |
| `team` | 团队模式 |

## 3. 排序规则

| 场景 | 排序规则 |
|------|------|
| 置顶会话(`project.pinned_sessions`) | 按 `pin_order` 升序,从项目中剥离独立展示 |
| 项目列表(`project.list`) | 置顶项目在前(按 `pin_order` 升序),其余按 `last_user_message_at` 倒序,末位为默认项目 |
| 项目下会话(`project.get_sessions`) | 仅非置顶会话,按 `last_user_message_at` 倒序 |

> **统计口径**: `session_count` 与 `project.get_sessions` 始终只统计当前项目下的**非置顶**会话。置顶会话由 `project.pinned_sessions` 独立返回,不计入任何项目的 `session_count`。

## 4. 会话接口

### session.list — 获取会话列表

扁平分页获取会话列表,行为不变。

**请求参数:**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `limit` | integer | 否 | 返回上限,默认 20,最大 200 |
| `offset` | integer | 否 | 偏移量,默认 0 |

**响应 payload:**

| 字段 | 类型 | 说明 |
|------|------|------|
| `sessions` | object[] | 会话元数据列表(完整字段,包含 `work_mode`) |
| `total` | integer | 会话总数 |
| `limit` | integer | 实际使用的 limit |
| `offset` | integer | 实际使用的 offset |
| `has_more` | boolean | 是否还有更多会话 |

---

### session.create — 创建会话

追加可选参数 `project_dir`、`project_id` 和 `work_mode`,不传时按通道默认值兼容旧行为。Web 通道默认 `work`,TUI 通道默认 `code`。

**请求参数:**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_id` | string | 是 | 会话 ID,由前端生成(`sess_` 前缀) |
| `title` | string | 否 | 会话标题 |
| `mode` | string | 否 | 模式,默认 `unknown`(首次 `chat.send` 时由请求参数覆盖为真实模式) |
| `project_dir` | string | 否 | 工作目录绝对路径。不可单独传入——必须同时带有效 `project_id`(非空且非 `"default"`),否则 `BAD_REQUEST`。仅传 `project_id` 未传 `project_dir` 时,由项目记录自动补齐 |
| `project_id` | string | 否 | 所属项目 ID,绑定后不可变(首次锁定)。非空且非 `"default"` / `"default_code"` 时必须对应一个存在且可见的项目,否则 `NOT_FOUND`;若同时传了 `project_dir`,必须与项目绑定路径一致(一致性校验),否则 `BAD_REQUEST`。不传或默认项目 ID(且 `project_dir` 为空)表示默认项目 |
| `work_mode` | string | 否 | `work` / `code`。未传按通道推断;显式非法值返回 `BAD_REQUEST`;显式值与项目记录不一致时返回 `BAD_REQUEST` |

> 校验 —— `project_id` / `project_dir` 绑定规则:
> - 两者皆空(或 `project_id="default"` / `"default_code"` 且 `project_dir` 为空)→ 对应模式的默认项目(兼容旧版);
> - 仅传 `project_id`(无 `project_dir`)→ 按项目记录自动补齐 `project_dir`;
> - 同时传 `project_id` + `project_dir` → 一致性校验(须与项目绑定路径一致,容忍尾部分隔符/大小写差异);
> - 仅传 `project_dir` 而无有效 `project_id` → 拒绝(`BAD_REQUEST`)。
>
> 此外,`project_dir` 非空时必须为绝对路径,否则 `BAD_REQUEST`。创建时将 `project_dir`、`project_id` 和 `work_mode` 写入 session metadata,首次绑定后均不可变。

**响应 payload:**

| 字段 | 类型 | 说明 |
|------|------|------|
| `session_id` | string | 创建的会话 ID |
| `project_id` | string | 最终绑定的项目 ID |
| `project_dir` | string | 最终绑定的项目目录 |
| `work_mode` | string | 最终工作模式 |

**错误码:** `BAD_REQUEST`(`project_dir` 非空且非绝对路径;`project_dir` 未搭配有效 `project_id`;`project_dir` 与项目绑定路径不一致)、`ALREADY_EXISTS`(会话已存在)、`NOT_FOUND`(`project_id` 对应的项目不存在或已隐藏)

### session.rename — 重命名会话

支持查询/设置/清除三种语义。

**请求参数:**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_id` | string | 是 | 目标会话 ID |
| `title` | string | 否 | 不传(或 `null`)→查询当前标题、空串/纯空白→清除标题、非空→设置(截断 200 字符) |

**响应 payload:**

| 字段 | 类型 | 说明 |
|------|------|------|
| `session_id` | string | 目标会话 ID |
| `title` | string | 操作后的标题 |

### session.pin — 置顶/取消置顶会话

置顶时会话从项目分组剥离进入全局置顶区;取消置顶时回归原项目。操作后对所有置顶会话紧凑重编号为 1..N。

**请求参数:**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_id` | string | 是 | 会话 ID |
| `pinned` | boolean | 是 | `true`=置顶,`false`=取消 |

**响应 payload:**

| 字段 | 类型 | 说明 |
|------|------|------|
| `pinned` | boolean | 操作后的置顶状态 |
| `pin_order` | integer | 操作后的 `pin_order` |

> **幂等**:对已处于目标状态的会话再次操作视为成功。
> 新置顶的会话 `pin_order` 默认 0,重编号后置于置顶区顶部。

**错误码:** `NOT_FOUND`(会话不存在)

## 5. 项目接口

### project.list — 获取项目列表

返回项目列表(含统计信息),已排序,包含默认项目。

**请求参数:**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `filter` | string | 否 | `"all"`(默认) / `"pinned"` / `"unpinned"` |
| `include_hidden` | boolean | 否 | 是否包含已软删除项目,默认 `false`。仅 `"all"` / `"unpinned"` 时生效 |
| `work_mode` | string | 否 | 按 `work` / `code` 过滤项目。不传返回全部模式 |

**filter 参数语义:**

| 值 | 说明 |
|------|------|
| `"all"` | 置顶项目在前(按 `pin_order` 升序),其余按 `last_user_message_at` 倒序,末位为默认项目。默认项目按 `work_mode` 拆分为 `default` 与 `default_code` |
| `"pinned"` | 仅置顶项目,按 `pin_order` 升序 |
| `"unpinned"` | 仅非置顶项目,按 `last_user_message_at` 倒序,末位为默认项目 |

**响应 payload:**

| 字段 | 类型 | 说明 |
|------|------|------|
| `projects` | ProjectInfo[] | 项目列表,已排序,包含 `work_mode` 与 `git` 字段 |

**错误码:** 无

---

### project.get_sessions — 获取项目下会话列表

按 `project_id` 返回该项目下的**非置顶**会话列表,已排序。会话仅按 `project_id` 匹配归属。传 `"default"` 时返回不属于任何可见项目的非置顶会话(含 `project_id` 为空、命中已隐藏项目的会话)。

**请求参数:**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `project_id` | string | 是 | 项目 ID,传 `"default"` 获取 work 默认项目会话,传 `"default_code"` 获取 code 默认项目会话 |
| `limit` | integer | 否 | 返回上限,默认不限 |
| `offset` | integer | 否 | 偏移量,默认 0 |

**响应 payload:**

| 字段 | 类型 | 说明 |
|------|------|------|
| `sessions` | SessionInfo[] | 已排序的非置顶会话列表(按 `last_user_message_at` 倒序) |
| `total` | integer | 该项目下非置顶会话总数(截断前全量计数) |

**错误码:** `NOT_FOUND`(项目不存在或已软删除/隐藏)

---

### project.create — 创建项目

创建项目,指定工作目录(可选)。若传入的非空 `project_dir` 命中同 `work_mode` 的已隐藏项目,自动恢复该项目。支持创建空路径项目(允许多个,靠 `project_id` + `name` + `work_mode` 区分)。

**请求参数:**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | 是 | 项目展示名(非空,全局唯一含隐藏项目);命中已隐藏项目时用于更新展示名 |
| `project_dir` | string | 否 | 工作目录绝对路径;不传或空串创建空路径项目 |
| `work_mode` | string | 否 | `work` / `code`;未传按通道推断。code 项目创建后自动探测或初始化 Git |

**响应 payload:**

| 字段 | 类型 | 说明 |
|------|------|------|
| `project_id` | string | 项目 ID(新建为 `proj_<8位hex>`,恢复为原 ID) |
| `project_dir` | string | 项目路径(空路径项目为空串) |
| `restored` | boolean | `true`=恢复了已隐藏项目,`false`=新建 |
| `project` | ProjectInfo | 完整项目对象 |
| `work_mode` | string | 项目工作模式 |
| `git` | object | Git 快照。code 项目可能为 `ready` / `not_git` / `git_missing` 等;work 项目为 disabled/空状态 |

> **自动恢复**: 非空 `project_dir` 命中同 `work_mode` 的已隐藏项目时,置 `hidden:false` 并更新展示名,其下会话因 `project_id` 仍匹配自动重新归属。`project_dir` 与同模式已有可见项目重复,或 `name` 与同模式已有项目(含隐藏)重复时返回 `CONFLICT`。
>
> **Code 项目 Git 探测**: 新建 code 项目时,空目录会自动 `git init`;已是 Git 仓库写入 `ready`;非空非 Git 目录写入 `not_git`;系统无 Git 写入 `git_missing`。恢复隐藏项目时只刷新探测快照,不自动重建 `.git`。

**错误码:** `BAD_REQUEST`(`name` 为空、`project_dir` 非空且非绝对路径)、`CONFLICT`(`project_dir` 与已有可见项目重复、`name` 与已有项目重复)

### project.rename — 重命名项目

仅修改展示名,不改动工作目录路径。`name` 与同 `work_mode` 已有项目(含隐藏)重复时返回 `CONFLICT`。

**请求参数:**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `project_id` | string | 是 | 项目 ID |
| `name` | string | 是 | 新名称(非空,全局唯一含隐藏项目) |

**响应 payload:** 空(`{}`)

**错误码:** `BAD_REQUEST`(`name` 为空)、`NOT_FOUND`(项目不存在)、`FORBIDDEN`(默认项目禁止重命名)、`CONFLICT`(`name` 与已有项目重复)

切换项目置顶状态。操作后对所有置顶项目紧凑重编号为 1..N。

**请求参数:**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `project_id` | string | 是 | 项目 ID |
| `pinned` | boolean | 是 | `true`=置顶,`false`=取消 |

**响应 payload:**

| 字段 | 类型 | 说明 |
|------|------|------|
| `pinned` | boolean | 操作后的置顶状态 |
| `pin_order` | integer | 操作后的 `pin_order` |

> **幂等**:对已处于目标状态的项目再次操作视为成功。

### project.remove — 移除项目(软删除)

将项目标记为 `hidden:true`,同时自动取消置顶。其下非置顶会话临时归入默认项目;置顶会话不受影响。

**请求参数:**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `project_id` | string | 是 | 项目 ID |

**响应 payload:**

| 字段 | 类型 | 说明 |
|------|------|------|
| `affected_sessions` | integer | 受影响(临时归入默认项目)的非置顶会话数 |

> **幂等**:对已隐藏的项目再次移除,返回 `affected_sessions: 0`。

**错误码:** `NOT_FOUND`(项目不存在)、`FORBIDDEN`(默认项目禁止移除)

### project.restore — 恢复项目

将已软删除的项目恢复为可见。其下会话因 `project_id` 仍匹配,自动重新归属。恢复后 `name` 与同 `work_mode` 已有项目(含隐藏)重复时返回 `CONFLICT`。

**响应 payload:**

| 字段 | 类型 | 说明 |

| `affected_sessions` | integer | 重新归属到该项目的非置顶会话数 |

**错误码:** `NOT_FOUND`(项目不存在)、`CONFLICT`(项目未处于软删除状态 或 恢复后 `name` 与已有项目重复)、`FORBIDDEN`(默认项目)

### project.pinned_sessions — 获取全部置顶会话

**请求参数:** 无

| 字段 | 类型 | 说明 |

> 项目软删除后,其下置顶会话仍保留在全局置顶列表中,不受项目隐藏影响。

**错误码:** 无

## 6. Git 与 Diff 接口（Code 项目）

以下接口仍走普通 `/ws` WebSocket 请求信封,用于 code 项目的 Git 状态、分支和 Diff 快照查询。仅真实 `work_mode="code"` 项目可用;默认项目、`work` 项目、隐藏项目或空路径项目会被拒绝。

### GitStatusPayload

`project.git.status` / `probe` / `init` 以及分支操作中的 `status` 使用此结构。

| 字段 | 类型 | 说明 |
|------|------|------|
| `project_id` | string | 项目 ID |
| `project_name` | string | 项目名称 |
| `project_dir` | string | 项目工作目录 |
| `work_mode` | string | 恒为 `code` |
| `repo` | object | 仓库信息:`is_git`、`repo_root`、`branch`、`head`、`detached`、`transient`、`upstream` |
| `working_tree` | object | 工作区统计:`is_dirty`、`staged`、`unstaged`、`untracked`、`conflicted` |
| `branches` | object | 分支列表:`current`、`locals`、`remotes` |
| `generated_at` | number | 生成时间戳(UTC 秒) |

> `project.git.status` 是实时读取工作区状态,不写入项目存储;`project.git.probe` 会重新探测并刷新 `ProjectInfo.git` 持久化快照,同时唤醒 `/ws/git` 监控重算。

### DiffSummary / DiffFileEntry / Hunk

Diff 接口中的 `current` 表示当前工作区相对 Git 基线的变更,`last_turn` 表示指定会话上一轮 agent 产生的变更。

| 结构 | 关键字段 | 说明 |
|------|----------|------|
| `DiffSummary` | `stats`、`files` | 汇总统计和文件映射;未请求文件时 `files` 为空对象 |
| `DiffFileEntry` | `file_path`、`status`、`change_type`、`lines_added`、`lines_removed`、`is_binary`、`is_new_file`、`is_deleted_file`、`is_untracked`、`is_large_file`、`is_truncated`、`hunks` | 单文件变更。`include_hunks=false` 时不返回 `hunks` |
| `Hunk` | `old_start`、`old_lines`、`new_start`、`new_lines`、`lines` | 文件 diff 片段。hunk 即一个连续变更块,用于定位旧文件/新文件中的起止行和具体增删上下文 |

> 非 Git 或 Git 不可用时,`diff_status` 可退化返回 `repo.is_git=false`、`current=null`;若有 file_ops 历史,`last_turn` 仍可返回。merge/rebase/cherry-pick 等中间状态下 `repo.transient=true`,当前 Diff 置空,历史详情接口会返回 `GIT_TRANSIENT_STATE`。

### project.git.status — 查询 Git 状态

实时读取项目目录的 Git 状态,用于状态栏、分支选择器和写操作前校验。不刷新 `ProjectInfo.git`,不触发 watcher。

**请求参数:**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `project_id` | string | 是 | code 项目 ID |

**响应 payload:** `GitStatusPayload`。

**错误码:** `BAD_REQUEST`、`PROJECT_NOT_FOUND`、`FORBIDDEN`、`GIT_NOT_FOUND`、`NOT_GIT_REPOSITORY`

---

### project.git.probe — 重新探测并写回 Git 快照

重新探测项目目录是否为 Git 仓库、当前分支、HEAD、工作区脏状态等,并写回项目记录的 `git` 字段。适用于用户手动 `git init`、安装 Git 后刷新、删除 `.git` 后重新识别等场景。成功后唤醒 `/ws/git` 监控。

**请求参数:**

| 参数 | 类型 | 必填 | 说明 |

### project.git.init — 初始化 Git 仓库

### project.git.switch_branch — 切换分支

### project.git.create_branch — 创建分支

## 7. /ws/git 实时监控与撤销/重做接口

`/ws/git` 是 Git Diff 专用 WebSocket。请求/响应信封与普通 `/ws` 一致,但除了响应请求外,还会主动推送事件:

| 事件 | 触发时机 | payload 简述 |
|------|----------|--------------|
| `project.git.diff_changed` | summary 指纹变化 | `project_id`、`session_id`、`repo`、`current`、`last_turn`、`revision` |
| `project.git.diff_files_changed` | 已订阅来源的文件列表变化 | `project_id`、`session_id`、`source`、`revision`、`files`;`last_turn` 来源额外包含轮次元信息 |
| `project.git.diff_detail_changed` | 已订阅文件的 hunk 变化 | `project_id`、`session_id`、`source`、`revision`、`files`;`last_turn` 来源额外包含轮次元信息 |
| `project.git.error` | 监控重算失败 | `project_id`、`session_id`、`code`、`message`、`detail` |

### project.git.diff_watch — 订阅 Diff summary

创建 summary 级 watcher。首次响应只返回统计快照,文件列表固定为空;后续变化通过 `project.git.diff_changed` 推送。

**请求参数:**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `project_id` | string | 是 | code 项目 ID |
| `session_id` | string | 否 | 会话 ID,用于计算 `last_turn` |
| `scope` | string | 否 | 当前仅支持 `summary`,默认 `summary` |
| `include_last_turn` | boolean | 否 | 是否监控上一轮 Diff,默认 `true` |

**响应 payload:**

| 字段 | 类型 | 说明 |
|------|------|------|
| `watch_id` | string | 本次监控 ID,供后续 files/detail/unwatch 使用 |
| `scope` | string | 恒为 `summary` |
| `snapshot` | object | 首次快照,包含 `project_id`、`session_id`、`repo`、`current`、`last_turn`、`revision` |

**错误码:** `BAD_REQUEST`、`NOT_FOUND`、`FORBIDDEN`、Git 领域错误码

---

### project.git.diff_files_watch — 订阅文件列表

在已有 `watch_id` 上订阅或切换某个来源的文件列表。首次响应返回当前文件列表(不含 hunk),后续列表变化通过 `project.git.diff_files_changed` 推送。

**请求参数:**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `project_id` | string | 是 | code 项目 ID |
| `watch_id` | string | 是 | `diff_watch` 返回的监控 ID |
| `source` | string | 是 | `current` 或 `last_turn` |
| `session_id` | string | 否 | 覆盖 watcher 上的 session_id;通常不传 |

**响应 payload:**

| 字段 | 类型 | 说明 |
|------|------|------|
| `watch_id` | string | 监控 ID |
| `files_scope` | object | `{ "source": "current|last_turn" }` |
| `revision` | string | 快照版本 |
| `files` | object | 文件路径到 `DiffFileEntry` 的映射,不含 `hunks` |

**错误码:** `BAD_REQUEST`、`NOT_FOUND`、`FORBIDDEN`、Git 领域错误码

---

### project.git.diff_detail_watch — 订阅文件详情

在已有 `watch_id` 上订阅具体文件的 hunk。每次调用会替换该 watcher 的 detail 订阅范围。只有订阅文件的内容变化时才推送详情事件。

**请求参数:**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `project_id` | string | 是 | code 项目 ID |
| `watch_id` | string | 是 | `diff_watch` 返回的监控 ID |
| `source` | string | 是 | `current` 或 `last_turn` |
| `files` | string[] | 是 | 要订阅详情的文件路径列表 |
| `session_id` | string | 否 | 覆盖 watcher 上的 session_id;通常不传 |

**响应 payload:**

| 字段 | 类型 | 说明 |
|------|------|------|
| `watch_id` | string | 监控 ID |
| `detail_scope` | object | `{ "source": "...", "files": [...] }` |
| `revision` | string | 快照版本 |
| `files` | object | 请求路径到 `DiffFileEntry` 的映射;找不到的文件值为 `null`;包含 `hunks` |

**错误码:** `BAD_REQUEST`、`NOT_FOUND`、`FORBIDDEN`、Git 领域错误码

---

### project.git.diff_unwatch — 取消监控

释放 watcher 资源。`scope="all"` 移除整个 watcher;`files`/`detail` 仅取消对应子订阅并保留 summary。`watch_id` 不存在时幂等成功。

**请求参数:**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `watch_id` | string | 是 | 监控 ID |
| `scope` | string | 否 | `all` / `files` / `detail`,默认 `all` |

**响应 payload:**

| 字段 | 类型 | 说明 |
|------|------|------|
| `watch_id` | string | 监控 ID |
| `cancelled` | boolean | 恒为 `true` |
| `scope` | string | 实际取消范围 |

**错误码:** `BAD_REQUEST`

---

### project.git.discard_turn_changes — 撤销本轮代码修改

撤销当前会话最后一轮 agent 通过文件工具产生的代码修改,将受影响文件恢复到该轮开始前的状态,或删除本轮新建文件。成功后将本轮 session-specific file_ops 条目打上 `discarded_out` 软删除标记(而非物理删除,保留快照供 `redo_turn_changes` 恢复)并唤醒 Diff watcher;若部分文件恢复失败,返回 `ok=false` 且保留 file_ops 以便重试。

**请求参数:**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `project_id` | string | 是 | code 项目 ID |
| `session_id` | string | 是 | 会话 ID,必须绑定到该项目 |

**响应 payload:**

| 字段 | 类型 | 说明 |
|------|------|------|
| `session_id` | string | 会话 ID |
| `turn_index` | integer | 被撤销的最后一轮序号 |
| `change_set_id` | string \| null | 被标记为已撤销的变更集 ID;部分失败时为 null |
| `restored_files` | string[] | 已恢复到旧内容的文件 |
| `deleted_files` | string[] | 已删除的新建文件 |
| `errors` | object[] | 单文件恢复失败信息;为空表示完全成功 |
| `file_ops_truncated` | boolean | 是否已将本轮 session-specific file_ops 条目标记为 `discarded_out`(软删除,保留供 redo) |
| `global_file_ops_truncated` | boolean | 恒为 `false`,全局 file_ops 不按路径清理以避免误伤其他会话 |
| `partial` | boolean | 是否部分失败;为 `true` 时顶层 `ok=false`、`code=PARTIAL_RESTORE_FAILED` |

**错误码:** `BAD_REQUEST`、`NOT_FOUND`、`FORBIDDEN`、`SESSION_NOT_BOUND`、`PROJECT_SESSION_MISMATCH`、`SESSION_BUSY`、`NO_TURN_TO_DISCARD`、`PARTIAL_RESTORE_FAILED`

---

### project.git.redo_turn_changes — 重新应用本轮被撤销的代码修改

与 `discard_turn_changes` 对称:将被 `discard_turn_changes` 撤销的最后一轮文件变更重新应用到工作区,恢复 file_ops 条目的可见性(去掉 `discarded_out` 标记),并清除该轮的 `discarded` 状态(恢复为 `completed`)。成功后唤醒 Diff watcher;若部分文件重新应用失败,返回 `ok=false` 且保留 `discarded` 状态以便重试。

**前置条件:** 最后一轮必须已被 discard(`status == "discarded"`);未撤销时返回 `NOTHING_TO_REDO`。

**请求参数:**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `project_id` | string | 是 | code 项目 ID |
| `session_id` | string | 是 | 会话 ID,必须绑定到该项目 |

**响应 payload:**

| 字段 | 类型 | 说明 |
|------|------|------|
| `session_id` | string | 会话 ID |
| `turn_index` | integer | 重新应用的最后一轮序号 |
| `change_set_id` | string \| null | 恢复为 completed 的变更集 ID;部分失败时为 null |
| `redone_files` | string[] | 已重新写入 agent 修改后内容(new_content)的文件 |
| `deleted_files` | string[] | 被 agent 删除的文件(redo 时重新删除) |
| `errors` | object[] | 单文件重新应用失败信息;为空表示完全成功 |
| `partial` | boolean | 是否部分失败;为 `true` 时顶层 `ok=false`、`code=PARTIAL_REDO_FAILED` |

**错误码:** `BAD_REQUEST`、`NOT_FOUND`、`FORBIDDEN`、`SESSION_NOT_BOUND`、`PROJECT_SESSION_MISMATCH`、`SESSION_BUSY`、`NO_TURN_TO_REDO`、`NOTHING_TO_REDO`、`REDO_HISTORY_MISSING`、`PARTIAL_REDO_FAILED`

> **`REDO_HISTORY_MISSING`:** 最后一轮状态为 `discarded` 但未找到任何可恢复的 file_ops 条目(file_ops 缺失/损坏/无 `discarded_out` 标记)。此时不清除 `discarded` 状态,保留供排查。
>
> **`NOTHING_TO_REDO`:** 最后一轮未被 discard(如 `status=applied` 或 `completed`),无可重做的变更。
