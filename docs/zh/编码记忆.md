# 编码记忆（Coding Memory）

单人 Work 和 Code 模式由随发行版安装的 **Agent Memory** 插件提供记忆。新会话默认启用；可在会话的扩展面板关闭。关闭后保留历史记忆，不再召回或写入，也不回退原有编码记忆。

## 启用与配置

WorkSwarm 个人版的记忆插件只使用内置 HTTP 服务。WorkSwarm 启动时自动启动仅监听本机、需要认证的服务，关闭时停止。插件自动连接，详情页显示服务状态。旧 SDK 模式、自定义服务地址和保存的客户端密钥不再生效。企业版不会启动此单一身份的服务。

`memory.plugin.default_enabled` 控制新会话是否默认启用，已有会话沿用保存的选择。新会话默认开启，不受 `memory.engine: none` 等旧记忆设置影响。此配置不控制监听器启停。`modes.code.memory.enabled` 仍单独控制读取项目说明书的 `ProjectMemoryRail`。`team.work`、`team.code` 在 `memory.builtin.provider=jiuwen` 时走此插件，由会话「扩展 → 记忆插件」开关控制；`team.design` 和未指定 provider 时保留原有行为。

内置 HTTP 服务继续读取 `memory.builtin.jiuwen.sdk` 中的模型配置，`plugins.agent-memory-plugin.sdk` 可覆盖它。这个历史配置键只配置服务端模型，不会启用 SDK 接入。仓库模板使用本地 hashing 向量；基于模型的抽取仍需要真实 LLM。未显式配置 LLM 凭证时，服务复用 Swarm 默认模型。

## 工具与调用

| 路线 | 工具 | 主要参数与用途 |
|---|---|---|
| Jiuwen | `agent_memory_coding_memory_read` | `md_filename`，可选 `offset/limit`；读取 `USER.md`、`MEMORY.md` 或日期文件 |
| Jiuwen | `agent_memory_coding_memory_write` | `content`；抽取并分类保存长期事实，不接受主题文件路径 |
| Jiuwen | `agent_memory_coding_memory_edit` | `md_filename/old_text/new_text`；替换唯一匹配文本，先读后改 |
| Jiuwen | `agent_memory_coding_memory_search` | `query`，可选 `top_k`（默认 5，范围 1–50）；只查当前项目 |

Jiuwen 普通回合先读取用户画像并召回项目记忆；无命中或搜索失败时尝试读取项目 `MEMORY.md`。Code 插件只挂载到主 Agent。用户消息和助手回复均非空时，回合结束会排队执行 `sync_turn`；心跳和定时任务不触发此抽取。工具失败或无新单元不代表记忆已保存。

## 身份与存储

Jiuwen 路线的 Work/Code/Team 统一使用 `memory.builtin.jiuwen.agent_id`，默认 `main_agent`，运行 Agent 名称不覆盖它。Work/Code 使用同一内置库；项目事实按项目键隔离，团队结论按团队键隔离。

默认 `main_agent` 兼容原默认身份数据。已有配置若显式设置其他 `agent_id`，仍以该值为准；需使用原默认身份数据时改为 `main_agent`。旧数据不自动迁移或合并。

Work/Code 采用相同的`项目键`：规范绝对路径的目录名加 12 位摘要，同名不同路径相互隔离；未指定项目时为 `default`。连接同一记忆库、满足身份过滤并选择同一项目路径时，两种模式可共享项目记忆。Code 工具不能覆盖项目键；Work 工具默认使用当前项目，也保留显式指定既有项目坐标的能力。

| 路线 | 位置 |
|---|---|
| 原生及 AutoMemory | `{agent_workspace}/coding_memory/{项目键}/`，主题 Markdown 与 `MEMORY.md` 索引 |
| Jiuwen 画像 | `{root}/USER.md` |
| Jiuwen 项目 | `{root}/memory/{项目键}/MEMORY.md`、`daily_memory/YYYY-MM-DD.md` |
| Jiuwen 影子索引 | `{root}/memory/.shadow/shadow.db` |

`{root}` 是 Swarm 数据目录下的 `agent/memory/managed-http`。已有内置服务数据继续使用；原 SDK 和外部 HTTP 记忆库不会自动迁移或删除。

## 与旧记忆的关系

Work/Code 主 Agent 不再走旧 Rail、AutoMemory 抽取或 Dreaming 启动入口，避免重复写入。内置 HTTP 未运行时，对话继续并保留会话的记忆开关。续接目标时不切换已挂载的插件，记忆可在下一个普通回合重新挂载。其他插件加载错误仍会报告。Team 成员共用插件的接入配置，由各自的 Team Rail 读写记忆；内置服务离线时跳过成员管理，不访问旧记忆库。关闭插件后停止团队记忆的召回和写入，也不会回退到原生 Team 记忆。手动启用的 MCP 连接器独立。
