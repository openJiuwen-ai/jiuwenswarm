# 编码记忆（Coding Memory）

单人 Code 模式可使用原生文件记忆，或显式选择 agent-memory 文档记忆。两者由同一个编码记忆槽位装配，不需要向动态 `rails`、`tools` 列表添加条目。

## 启用与配置

编辑当前生效的 `config.yaml`（模板见 `jiuwenswarm/resources/config.yaml`）。`modes.code.memory.enabled` 控制编码记忆和读取项目说明书的 `ProjectMemoryRail`；默认开启。`memory.builtin.provider` 默认空值，保留原生 `CodingMemoryRail`。

选择 Jiuwen SDK 文档记忆：

```yaml
modes:
  code:
    memory:
      enabled: true
memory:
  mode: local
  engine: builtin
  builtin:
    provider: jiuwen
    jiuwen:
      mode: sdk
      user_id: my-user
      scope_id: my-org
      agent_id: jiuwenswarm  # 无运行 Agent 名称时才使用
      session_id: ""        # 不自动绑定聊天会话 ID
      space: ""
      sdk:
        markdown_store:
          default:
            target: local
            params:
              root: /absolute/path/to/memory  # 可省略，使用共享默认根
```

SDK 在 Swarm 进程内创建 Runtime 和文档看门狗。未显式覆盖的模型凭证从 Swarm `models.defaults` 的默认模型及 `embed.*` 注入；需配置可用的模型服务，无需另设 agent-memory 环境文件。可用 `jiuwen.sdk.globals` 覆盖模型、凭证和维度，完整字段见模板。

使用 HTTP 时将上面的 `jiuwen` 段改为：

```yaml
jiuwen:
  mode: http
  base_url: http://127.0.0.1:8137
  api_key: ""              # 按服务端认证配置填写
  identity_org: local
  identity_user: developer
  user_id: my-user
  scope_id: my-org
  agent_id: jiuwenswarm
  session_id: ""
  space: ""
```

HTTP 需要已启动的 agent-memory 文档记忆服务；Runtime、模型、存储及看门狗均由服务端管理。Swarm 不创建本地记忆 Runtime，不使用 `jiuwen.sdk` 配置，也不自动上传本地记忆文件。`memory.mode` 仍为 `local`：它是 Swarm 的内置路线门禁，与 `jiuwen.mode=http` 的连接方式不同。

两种连接方式都需要包含 Coding 接入功能的 core、JiuwenMemory 配套依赖；仅合并源码不代表已安装的包包含功能。模板的连接方式缺省为 `sdk`；配置与 `JIUWEN_MEMORY_MODE` 环境变量均未指定时，解析器回落到 `http`。

## 工具与调用

| 路线 | 工具 | 主要参数与用途 |
|---|---|---|
| 原生 | `coding_memory_read` | `path`，可选 `offset/limit`；读取主题文件 |
| 原生 | `coding_memory_write` | `path/content`；写入主题文件 |
| 原生 | `coding_memory_edit` | `path/old_text/new_text`；编辑主题文件 |
| Jiuwen | `agent_memory_coding_memory_read` | `md_filename`，可选 `offset/limit`；读取 `USER.md`、`MEMORY.md` 或日期文件 |
| Jiuwen | `agent_memory_coding_memory_write` | `content`；抽取并分类保存长期事实，不接受主题文件路径 |
| Jiuwen | `agent_memory_coding_memory_edit` | `md_filename/old_text/new_text`；替换唯一匹配文本，先读后改 |
| Jiuwen | `agent_memory_coding_memory_search` | `query`，可选 `top_k`（默认 5，范围 1–50）；只查当前项目 |

Jiuwen 普通回合先读取用户画像并召回项目记忆；无命中或搜索失败时尝试读取项目 `MEMORY.md`。主 Agent 和 `code_agent` 共用所选 Rail/Provider。用户消息和助手回复均非空时，回合结束会排队执行 `sync_turn`；心跳和定时任务不触发此抽取。工具失败或无新单元不代表记忆已保存。

## 身份与存储

Work/Code 都优先使用运行 Agent 名称，再以配置 `agent_id` 兜底。SDK 下 org/user/space 相同、Agent 同名时可以共享画像；不同 Agent 仍按 Scope 过滤。`session_id` 原样透传，默认空字符串；文档读取匹配 session，现有影子索引搜索跨 session。HTTP 的身份映射由服务端协议处理，认证身份需与部署匹配。

`项目键` 为规范绝对路径的目录名加 12 位摘要，同名不同路径相互隔离；未指定项目时为 `default`。Code 工具不能覆盖项目键。

| 路线 | 位置 |
|---|---|
| 原生及 AutoMemory | `{agent_workspace}/coding_memory/{项目键}/`，主题 Markdown 与 `MEMORY.md` 索引 |
| Jiuwen 画像 | `{root}/USER.md` |
| Jiuwen 项目 | `{root}/memory/{项目键}/MEMORY.md`、`daily_memory/YYYY-MM-DD.md` |
| Jiuwen 影子索引 | `{root}/memory/.shadow/shadow.db` |

SDK 的 `{root}` 默认是用户数据目录下的 `agent/workspace`，Work/Code 共用，显式 `markdown_store.default.params.root` 优先。共用根目录不取消身份过滤；旧主题文件不会自动迁入新目录。HTTP 中这些文件位于记忆服务端。

## AutoMemory 与失败行为

AutoMemory 保持原设计和旧目录，不因启用 Jiuwen 而跳过：页面等 canonical `agent.code.*` 入口读全局 `auto_memory_enabled`；历史 `code.*` 入口读 `modes.code.memory.auto_coding_memory`。二者默认均为 `false`，且任务还受记忆总开关和原有触发条件控制。

AutoMemory 抽取子任务不继承 Jiuwen 编码 Rail 和工具，继续使用旧 `coding_memory_*` 工具；其模型前缀缓存复用可能减少。Jiuwen `sync_turn` 不受 AutoMemory 开关控制，同时开启会分别抽取、写入各自目录，可能增加模型调用；两套结果不自动合并。

Jiuwen 编码 Rail 创建或重建失败时，编码槽位留空；热更新会卸载并关闭旧实例，不回退原生 Rail。`ProjectMemoryRail` 仍独立读取本地项目说明书。修复配置后可通过重建/重载恢复；运行时请求超时和服务端抽取失败仍按原错误处理。原生 Coding 的失败策略保持不变。
