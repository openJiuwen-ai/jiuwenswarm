# 在 SwarmChat 中使用 AI 同事

创建群聊或打开“群成员 +”时，可在“AI 同事”页签选择已启用的同事。
入群只登记身份；用户、专家或其他同事 @ 它后，由同事原有调度器处理请求，再以自己的名字回复。
SwarmChat 群成员登记不受普通团队人数配额限制；专家团内部执行仍遵守团队配额，AI 同事执行并发由同事调度器管理。

同事每个群有独立连续的上下文，先获取最近背景，再按需调用 search_group_messages 查询。
它可以读取入群前历史，并查询有权访问的 IM 与 SwarmChat 群消息；消息查询免分享审批，成员资格和访问范围仍须有效。
没有配置 IM 群历史时，SwarmChat 群历史仍可查询。IM 搜索优先使用当前执行身份在该群的历史可见范围。
群内公开文件可搜索并导入当前会话；读取副本不会修改原文件。文件与工具操作的权限规则继续生效。

需要确认操作时，群对话框显示审批卡片。最终回复和明确公开的附件进入群历史，执行过程留在同事会话中。
自动接力每群以最近用户消息为范围限制 5 次，发送新消息可继续；停止群会停止相关同事请求。

服务重启后保留成员关系、Session 和待投递回复。群运行时尚未恢复时，回复延迟到群下一次就绪。
开发运行需要包含 HOST_MANAGED 的 agent-core；仅更新 SwarmChat 前端不能启用此能力。

同事可通过只读工具直接查询获授权的飞书群成员名单，无需执行 Shell 或逐次审批。仍需审批的操作会在卡片中显示脱敏摘要，批准只适用于所选调用。

## 自动判断回复

群聊默认开启“自动判断回复”：发送没有 @ 任何成员的消息时，由判断模型决定哪些成员需要回复，被选中的专家、专家团代理或 AI 同事以自己的身份回复。@ 成员的消息不经过判断，始终由被 @ 的成员回复。

在群聊右侧的群设置中可以调整：
- 关闭“自动判断回复”后，没有 @ 的消息只归档。
- “判断模型”默认跟随群会话模型；选用响应快的小模型可以降低开销和等待时间。

用户消息下方会显示判断结果：正在判断、已通知哪些成员、无需成员回复，或未能判断。未能判断时不会有成员回复，可以 @ 成员。
判断模型一次可以通知多位成员，它们各自独立回复。当请求需要多个专家团共同交付一份成果时，判断模型也可以指定其中一个专家团牵头：只有牵头的专家团先被唤醒，由它决定直接回答、向你追问还是发起协作；发起后其他专家团加入，最后只回复一份汇总。消息下方会显示“已请某专家团协调”。想自己指定由谁牵头时，请按顺序 @ 这些专家团，第一个被 @ 的牵头。成员之间的消息不触发自动判断。整群停止时会同时取消尚未开始的自动回复。
