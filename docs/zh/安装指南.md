# JiuwenSwarm 安装指南

> **重要提醒：** 安装完成并不代表直接可用，需要先完成模型配置。请参考[配置信息](https://gitcode.com/openJiuwen/jiuwenswarm/blob/develop/docs/zh/%E9%85%8D%E7%BD%AE%E4%BF%A1%E6%81%AF.md)进行模型配置

## 首次安装

### 方式一：桌面安装包（dmg / exe）

适用于 Windows 和 macOS 用户，希望开箱即用、不想自行配置 Python / Node.js 环境。从 gitcode Release 下载对应平台的安装包即可。从 [Release](https://gitcode.com/openJiuwen/jiuwenswarm/releases) 页面下载。

| 平台 | 下载产物 |
|------|----------|
| Windows | `JiuwenSwarm-setup-<version>.exe` |
| macOS | `JiuwenSwarm-<version>.dmg` |

下载地址：https://gitcode.com/openJiuwen/jiuwenswarm/releases

##### 系统要求

桌面安装包是针对特定平台和架构预编译的，安装前请确认你的机器满足以下条件：

| 平台 | 系统版本 | 架构 | 权限要求 | 最小运行资源（建议） |
|------|----------|------|----------|----------------------|
| Windows | Windows 10 / 11（64 位） | 仅 x64 | **需管理员权限**运行安装程序（`PrivilegesRequired=admin`） | CPU 2 核、内存 4 GB、可用磁盘 2 GB |
| macOS | macOS 11 (Big Sur) 或更高 | 仅 arm64（Apple Silicon） | 首次启动需在 Finder 右键「打开」以放行 GateKeeper | CPU 2 核、内存 4 GB、可用磁盘 2 GB |

> 💡 **资源说明**：上表为单机本地运行（Web 端 + 至少一个模型通道）的经验性建议下限。若同时启用浏览器自动化（Playwright）、向量检索（ChromaDB/FAISS）或挂接多个 IM 通道，建议内存提升至 8 GB 以上。实际开销主要取决于所配置的模型与并发任务数。

##### 架构说明（macOS）

当前 macOS 桌面安装包**仅提供 `arm64`（Apple Silicon）原生版本**，不提供 `x64`（Intel）版本，也不是 Universal 二进制：

- ✅ **Apple Silicon（M 系列）**：原生支持，直接下载 dmg 安装即可。
- ❌ **Intel Mac**：**不支持桌面安装包**。Intel 用户请改用 [方式二：pip 安装](#方式二pip-安装) 或 [方式三/四：源码安装](#方式三源码安装uv-方式)。

如不确定你的 Mac 芯片类型，可在终端执行 `uname -m`：输出 `arm64` 为 Apple Silicon（可使用 dmg），输出 `x86_64` 为 Intel（需改用 pip / 源码安装）。

#### 1. macOS：用 curl 下载 dmg（推荐）

> ⚠️ **重要**：从浏览器下载的 `.dmg` 会被 macOS 打上隔离标签（`com.apple.quarantine`），打开时触发 GateKeeper 检查，可能提示「已损坏，无法打开」或「无法验证开发者」。改用终端 `curl` 下载，文件不会带隔离标签，可正常挂载安装。

```bash
# 把 <version> 替换为目标版本号
curl -L --fail -o JiuwenSwarm-<version>.dmg \
  https://gitcode.com/openJiuwen/jiuwenswarm/releases/download/JiuwenSwarm<version>/JiuwenSwarm-<version>.dmg
```

#### 2. 安装与首次启动

- **macOS**：双击挂载 dmg，将 `JiuwenSwarm.app` 拖入 `Applications`。如果 macOS 阻止首次启动，请在 Finder 中右键选择「打开」。
- **Windows**：双击下载的安装包（`.exe`）按提示安装。安装程序会请求**管理员权限**（UAC 提权弹窗），请在弹窗中点击「是」继续；安装时会自动初始化工作区。如果使用便携式 onedir 版本，需要手动运行一次 `jiuwenswarm.exe init`。
  > ⚠️ 仅支持 Windows 10 / 11 的 **64 位**版本，不支持 32 位系统及更早的 Windows 版本。

首次启动后，系统会创建配置目录 `~/.jiuwenswarm/`，之后请参考 [启动后验证](#3-启动后验证) 完成模型配置。

> 版本号以 Release 页面实际下载链接为准。Windows 与 macOS 桌面端的自动更新方案见 [桌面端自动更新设计](windows自动更新设计.md)。

### 方式二：pip 安装

#### 环境检查

桌面安装包已包含运行所需的 Python 运行时和前端静态资源，无需执行本节检查。本节仅适用于 pip 安装和源码安装；二者均支持 Windows 10/11、macOS 10.15+ 和 Linux。

> 📦 **关于 wheel 包**：PyPI 上分发的 wheel 包不绑定特定系统镜像，但其运行依赖仍受上述系统版本与下表 Python 版本约束。注意桌面 dmg 要求 macOS 11+，而 pip/wheel 仅要求 macOS 10.15+。运行资源建议与桌面安装包一致：CPU 2 核、内存 4 GB、可用磁盘 2 GB（启用浏览器/向量检索/多通道时建议 8 GB+）。

| 依赖项 | 版本要求 | 适用方式 | 说明 |
|--------|----------|----------|------|
| Python | ≥3.11, <3.14 | pip 安装、源码安装 | 推荐使用 Python 3.11 |
| Node.js | 18.x 或更高版本 | 仅源码安装 | 用于构建 Web 前端；pip 包已包含前端静态资源 |
| Node.js | 20.x 或更高版本 | pip/wheel 与源码安装的浏览器运行时 | 用于运行内置 Playwright MCP CLI；普通应用使用不需要 Node |
| Git | 最新版本 | 仅源码安装 | 用于克隆和更新源码 |

在终端中运行以下命令检查对应环境：

```bash
# pip 安装和源码安装：检查 Python 版本
python --version
# 预期输出：Python 3.11.x、3.12.x 或 3.13.x

# 仅源码安装：检查 Node.js 版本
node --version
# 预期输出：v18.x.x 或更高

# 仅源码安装：检查 Git 版本
git --version
# 预期输出：git version 2.x.x
```

#### 1. 安装步骤

```bash
# 创建虚拟环境（推荐）
python -m venv jiuwenswarm-env

# 激活虚拟环境
# Windows:
jiuwenswarm-env\Scripts\activate
# macOS/Linux:
source jiuwenswarm-env/bin/activate

# 安装 JiuwenSwarm
## 方式一：默认安装（稳定版）
pip install jiuwenswarm

## 方式二：使用国内镜像源（推荐）
# 清华源
pip install jiuwenswarm -i https://pypi.tuna.tsinghua.edu.cn/simple

# 阿里源
pip install jiuwenswarm -i https://mirrors.aliyun.com/pypi/simple/

## 方式三：安装预发布版（beta）
# pip 默认只装稳定版，加 --pre 才会考虑预发布版（beta）
pip install --pre jiuwenswarm

# 国内镜像 + 预发布版
pip install --pre jiuwenswarm -i https://pypi.tuna.tsinghua.edu.cn/simple

# 也可指定具体 beta 版本号（版本号以 PyPI 实际发布为准）
pip install jiuwenswarm==0.2.4b3
```

#### 2. 首次启动

```bash
# 初始化 JiuwenSwarm（首次启动）
jiuwenswarm-init
# 启动 JiuwenSwarm
jiuwenswarm-start
```

首次启动后，系统会自动创建配置目录 `~/.jiuwenswarm/`。

#### 3. 启动后验证

启动成功后，请按以下步骤验证安装是否正确：

1. **打开 Web 端**：在浏览器中访问 `http://localhost:5173`
2. **进入配置页面**：点击左侧导航栏「配置信息」
3. **完成模型配置**：参考 [配置信息](配置信息.md) 完成模型 API 配置
4. **验证安装成功**：
   - Web 页面可正常访问
   - 完成模型配置后可进行一次基础对话（根据配置可能会使用工具/MCP）

![Web 端验证安装成功示例](../assets/images/天气.png)

> 💡 **提示**：如果 Web 页面无法访问，请检查日志文件 `~/.jiuwenswarm/logs/` 是否有错误信息。

#### 4. 重新启动服务

如果关闭 JiuwenSwarm 后需要再次使用：

```bash
# 再次启动
jiuwenswarm-start
```

### 方式三：源码安装（uv 方式）

#### 1. 环境准备

请先完成 [环境检查](#环境检查) 中源码安装所需的 Python、Node.js 和 Git 检查。

确保已安装 uv。如未安装，请参考 [uv 官方文档](https://docs.astral.sh/uv/) 自行安装。

```bash
# 检查 uv 是否已安装
uv --version

# 预期输出：uv 0.x.x
```

#### 2. 克隆并安装

```bash
# 克隆代码仓库
git clone https://gitcode.com/openJiuwen/jiuwenswarm.git

# 进入项目目录
cd jiuwenswarm

# 使用 uv 创建虚拟环境并安装依赖
uv venv
uv pip install -e .
```

#### 3. 构建前端

> ⚠️ **重要**：源码安装（editable install）需要手动构建前端，否则启动时会报错 `dist directory not found`。构建产物位于源码目录的 `jiuwenswarm/channels/web/frontend/dist`，运行时会直接读取该目录，无需复制到 `~/.jiuwenswarm/`。以下正斜杠路径可在 Windows PowerShell/CMD 和 macOS/Linux shell 中直接使用。

```bash
# Windows / macOS / Linux：从项目根目录进入前端目录
cd jiuwenswarm/channels/web/frontend

# 安装前端依赖
npm install

# 构建前端
npm run build

# 返回项目根目录
cd ../../../..
```

**说明**：
- `uv pip install -e .` 是 editable install，直接指向源码目录
- 源码中的 `frontend/dist` 被 `.gitignore` 忽略，仓库不包含构建产物
- `jiuwenswarm/channels/web/app_web.py` 会直接读取源码树中的 `frontend/dist`

#### 4. 首次启动

```bash
# 激活虚拟环境
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

# 初始化 JiuwenSwarm（首次启动）
jiuwenswarm-init
# 启动
jiuwenswarm-start
```

#### 5. 启动后验证

验证步骤见 [启动后验证](#3-启动后验证)。

#### 6. 重新启动服务

```bash
# 激活虚拟环境后启动
jiuwenswarm-start
```

## 版本升级

| 当前版本范围 | 升级方式 | 说明 |
|--------------|----------|------|
| 常规版本（如0.1.8 → 0.1.9，不跨0.1.7版本） | [常规版本升级](#常规版本升级) | 直接升级，无需备份 |
| 重大版本（如<0.1.7 → >0.1.7，跨0.1.7版本） | [重大版本升级](#重大版本升级) | 需要先备份数据 |

### 常规版本升级

#### pip 安装升级

```bash
# 激活虚拟环境
# 然后执行升级
pip install --upgrade jiuwenswarm
```

#### 源码安装升级

```bash
# 进入项目目录
cd jiuwenswarm

# 拉取最新代码
git pull

# 重新安装
pip install -e .
```

如果前端有更新，请重新构建。构建产物保留在源码树中，无需复制到用户工作区。以下正斜杠路径可在 Windows PowerShell/CMD 和 macOS/Linux shell 中直接使用。

```bash
# Windows / macOS / Linux
cd jiuwenswarm/channels/web/frontend
npm install
npm run build
cd ../../../..
```

### 重大版本升级

> ⚠️ 跨主版本升级前，请务必备份数据！

#### 1. 数据备份步骤

**Windows 系统：**

```bash
# 备份整个配置和数据目录
xcopy "%USERPROFILE%\.jiuwenswarm" "%USERPROFILE%\.jiuwenswarm_backup" /E /I

# 或使用 PowerShell（推荐）
Copy-Item -Path "$env:USERPROFILE\.jiuwenswarm" -Destination "$env:USERPROFILE\.jiuwenswarm_backup" -Recurse
```

**macOS/Linux 系统：**

```bash
# 备份整个配置和数据目录
cp -r ~/.jiuwenswarm ~/.jiuwenswarm_backup

# 或使用 rsync（推荐，保留权限和属性）
rsync -av ~/.jiuwenswarm ~/.jiuwenswarm_backup
```

**备份内容说明：**

| 目录/文件 | 说明 |
|-----------|------|
| `config/config.yaml` | 主配置文件（模型、API密钥等） |
| `config/.env` | 环境变量配置 |
| `agent/workspace/` | 身份、任务及工作区文件 |
| `agent/workspace/memory/` | 用户记忆数据 |
| `agent/workspace/skills/` | 技能库（自定义技能和配置） |
| `agent/home/` | 定时任务数据（`cron_jobs.json`） |

> `agent/jiuwenclaw_workspace/`、`agent/memory/` 和 `agent/skills/` 均为旧目录；当前版本会将其中的内容迁移至 `agent/workspace/`。

#### 2. 执行升级

根据您的安装方式，选择对应的升级方法：

##### pip 安装升级

按照 [常规版本升级 - pip 安装升级](#pip-安装升级) 中的相同步骤执行：激活虚拟环境，然后运行 `pip install --upgrade jiuwenswarm`。

##### 源码安装升级

按照 [常规版本升级 - 源码安装升级](#源码安装升级) 中的相同步骤执行：拉取代码、重新安装，并在需要时重新构建前端。

#### 3. 数据迁移

升级完成后，需要进行数据迁移以确保配置和数据兼容新版本。

##### 步骤一：检查配置文件变更

```bash
# 查看新版本的配置模板（源码安装）
cat jiuwenswarm/resources/config.yaml

# 或查看配置变更日志
# https://gitcode.com/openJiuwen/jiuwenswarm/blob/develop/docs/CHANGELOG.md
```

##### 步骤二：配置文件迁移

1. **对比新旧配置文件结构**

   新版本可能引入新的配置项或废弃旧配置项。请检查：
   - `config.yaml` 中是否有新增必填项
   - `.env` 中是否有新的环境变量
   - 旧配置项是否被废弃或重命名

2. **手动迁移配置**

   ```bash
   # 备份新版本的默认配置
   cp ~/.jiuwenswarm/config/config.yaml ~/.jiuwenswarm/config/config.yaml.new

   # 从备份恢复旧配置（谨慎操作）
   # 建议使用文本编辑器对比合并，而非直接覆盖
   ```

3. **常见配置迁移场景**

   | 场景 | 处理方式 |
   |------|----------|
   | 新增模型支持 | 在 `config.yaml` 中添加新的模型配置项 |
   | API 端点变更 | 更新 `.env` 中的 API 地址 |
   | 配置项重命名 | 按更新日志映射旧项到新项 |
   | 废弃配置项 | 删除不再使用的配置项 |

##### 步骤三：记忆数据迁移

记忆数据通常向后兼容，但建议检查：

```bash
# 检查记忆目录结构
ls ~/.jiuwenswarm/agent/workspace/memory/

# 如有异常，可从备份恢复
cp -r ~/.jiuwenswarm_backup/agent/workspace/memory/* ~/.jiuwenswarm/agent/workspace/memory/
```

##### 步骤四：验证迁移结果

```bash
# 启动服务
jiuwenswarm-start

# 检查日志是否有配置错误
# 日志位置：~/.jiuwenswarm/logs/
```

**迁移检查清单：**

- [ ] 服务能正常启动
- [ ] 模型配置生效（能正常对话）
- [ ] 历史记忆数据可访问
- [ ] 自定义配置已迁移
- [ ] 无报错或警告信息

## 常见问题

### Q: 启动时报错 "Python version not supported"

JiuwenSwarm 要求 Python 版本范围为 **3.11、3.12、3.13**（即 ≥3.11 且 <3.14）。`3.10` 及更早版本、`3.14` 及更新版本均不可用。其中 3.11、3.12 兼容性最佳。Python 版本检查详见：[环境检查](#环境检查)

> ℹ️ 如果在某些页面看到类似 `Python >=3.11 ❤️ 3.14` 或 `Python 3.11 3.14` 这类残缺写法，是 `<=` 尖括号在渲染时被识别为 HTML 标签或触发了 emoji 替换所致，其完整含义即 `≥3.11, <3.14`。

### Q: Windows 安装时弹出"是否允许此应用对你的设备进行更改"？

这是正常现象。Windows 安装程序（`.exe`）以管理员权限运行（`PrivilegesRequired=admin`），需要写入系统目录并注册卸载项。点击「是」继续即可。

### Q: macOS 上下载的 dmg 无法启动，或提示"已损坏"

见上方 [macOS：用 curl 下载 dmg（推荐）](#1-macos用-curl-下载-dmg推荐)。浏览器下载的 dmg 带隔离标签，推荐用终端 `curl` 下载。另外请确认你的 Mac 是 Apple Silicon（M 系列）——桌面安装包仅提供 arm64 版本，不支持 Intel Mac，Intel 用户请改用 [pip 安装](#方式二pip-安装)，详见 [架构说明（macOS）](#架构说明macos)。

### Q: 源码安装时提示 "Node.js not found" 或找不到 `npm`

重新构建前端需要 Node.js 18.x 或更高版本；pip/wheel 与源码安装如需使用浏览器运行时，则需要 Node.js 20 或更高版本来运行内置 Playwright MCP CLI。桌面安装包已内置 Node 22.11.0。普通安装、启动和非浏览器 Agent 不需要 Node.js。版本检查详见：[环境检查](#环境检查)

### Q: 怎么安装 beta 预发布版？

JiuwenSwarm 的预发布版采用 PEP 440 预发布格式，如 `0.2.4b3`（`b3` 表示第 3 个 beta，注意不是 `0.2.4.beta3`）。pip 默认只装稳定版，安装 beta 有两种方式：

加 `--pre` 标志，让 pip 自动取最新预发布版：

```bash
pip install --pre jiuwenswarm
```

或直接指定 beta 版本号（以 PyPI 实际发布为准）：

```bash
pip install jiuwenswarm==0.2.4b3
```

国内用户可加镜像源加速：`pip install --pre jiuwenswarm -i https://pypi.tuna.tsinghua.edu.cn/simple`。

> ℹ️ `pip index versions jiuwenswarm` 默认只列出稳定版，不显示 beta 版本。查看可用 beta 版本请到 [PyPI 项目页](https://pypi.org/project/jiuwenswarm/#history) 的 Release history，或 Release 发布页。

### Q: 如何查看当前版本？

```bash
pip show jiuwenswarm
```

### Q: 如何卸载？

```bash
pip uninstall jiuwenswarm
```
