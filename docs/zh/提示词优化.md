# 提示词优化（RLAF-P）

JiuwenSwarm 的运行时提示词优化器：通过 RL 风格的反馈闭环，为可重复的任务持续改进**系统提示词**——
**不训练任何模型权重**。策略（Policy，基于 LLM）生成候选提示词，环境（Environment）执行它们，
奖励模型（Reward）打分，漂移裁判（DriftJudge）确保不偏离原始目标，压缩后的优化历史再引导下一轮生成。
它与 Symphony 的 `experience` 子系统并列，因为二者是同一种反馈闭环，只是把对象从“技能选择”换成了“提示词”。

- 代码包：[`jiuwenswarm/symphony/optimization/`](../../jiuwenswarm/symphony/optimization/)
- 扩展：[`jiuwenswarm/extensions/optimization/`](../../jiuwenswarm/extensions/optimization/)
- 工具：`optimize_prompt`　·　护栏：`PromptOptimizerPromptRail`
- 配置：`config.yaml` 中的 `symphony.optimization`

完整说明（架构图、扩展点、防奖励作弊、最佳实践）见英文文档
[PromptOptimization.md](../en/PromptOptimization.md)。

## 核心组件

| 组件 | 接口 | 默认实现 | 复用的既有能力 |
|---|---|---|---|
| 策略 Policy | `PromptPolicy` | `LLMPromptPolicy` | `symphony.llm` 客户端 |
| 环境 Environment | `PromptEnvironment` | `LLMEnvironment`（另有 `WorkflowEnvironment`、`CallableEnvironment`） | `symphony.llm`、token 统计 |
| 奖励 Reward | `RewardModel`/`RewardComponent` | `CompositeReward` + 内置指标 | `TraceEvaluator` 的 LLM 裁判范式 |
| 漂移 Drift | `DriftJudge` | `LLMDriftJudge` | LLM-as-judge |
| 记忆 Memory | `PromptMemory` | `JsonlPromptMemory`/`ExperienceBankPromptMemory` | `ExperienceBank` + `EmbeddingClient` |

每个组件都是**可替换的抽象基类**，由 `OptimizerRuntimeFactory` 依据配置构建，
主循环结构与 `SymphonyScoreBuilder.build` 一致，并输出 JSONL 运行日志。

## 快速上手

```python
import asyncio
from jiuwenswarm.symphony.optimization import optimize_prompt, TaskSpec, TaskCase

task = TaskSpec(
    objective="把客服工单总结成最多 3 条行动项。",
    constraints=["输出 markdown 无序列表", "最多 3 条"],
    cases=[
        TaskCase(input="发票金额错误，且登录时 App 崩溃。",
                 expected="- 修复发票\n- 排查登录崩溃"),
        TaskCase(input="收不到重置密码邮件；深色模式异常。", hidden=True),
    ],
)

result = asyncio.run(optimize_prompt(task))
print(result.best_score, result.best_prompt)
```

## 配置（`symphony.optimization`）

```yaml
symphony:
  optimization:
    enabled: false
    candidate_prompts: 5          # 每轮生成的候选提示词数量
    max_iterations: 6
    parallel_execution: true      # 并发执行候选
    convergence_threshold: 0.01   # 视为“有提升”的最小奖励增量
    convergence_window: 3         # 连续 K 轮无提升则停止
    drift_penalty: 0.5            # 语义漂移的惩罚权重
    min_correctness: 0.5          # 硬门槛，防止奖励作弊
    memory_enabled: true
    reward_weights:
      correctness: 1.0
      completeness: 0.3
      latency: 0.1
      token_usage: 0.1
    models:
      policy_model: ""            # 留空则使用 JiuwenSwarm 默认模型
      environment_model: ""
      judge_model: ""
```

启用后，团队 leader 会获得 `optimize_prompt` 工具与对应护栏；
可运行的离线示例见 [`examples/optimize_summarizer.py`](../en/examples/optimize_summarizer.py)。
