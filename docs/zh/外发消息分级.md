# 外发消息分级

JiuwenSwarm 向飞书、钉钉等外部聊天平台推送运行事件时，可按需控制外发内容量，避免执行过程信息淹没最终回复。

## 配置方式

编辑 `~/.jiuwenswarm/config/config.yaml`，在顶层加入 `output.external` 段：

```yaml
output:
  external:
    verbosity: final
    channels: [feishu, dingtalk, welink]
```

- `verbosity`：外发级别，三档取值：
  - `final`（默认）：仅外发最终回复、失败上报，以及需要你确认的交互（ask_user、权限审批、目标确认等）；执行过程信息（流式输出、工具调用、子代理动态、状态快照）只记入会话历史与日志，不投外部渠道。
  - `progress`：在 `final` 基础上放行执行过程事件，适合需要盯进度的场景。
  - `verbose`：全量外发，供调试使用。
- `channels`：受本策略约束的渠道名单。**名单外渠道不受影响**：web / 桌面端等交互界面照常渲染全部事件，`__cron__` 等内部渠道的通知行为保持不变。
- 环境变量 `JIUWENSWARM_OUTPUT_VERBOSITY`（取值同上）可运行期临时覆盖配置文件，用于不重启的紧急止血；取值非法时忽略并沿用配置。

## 行为说明

- 该策略作用于运行事件外发的收敛门：被丢弃的过程消息仍完整保留在会话历史与 `agent_server.log` 中，日志会记录每次丢弃的请求、渠道与事件类型，可事后追溯。
- 任何级别下，最终回复（chat.final）、错误（chat.error）、需要你操作的交互（ask_user / 审批 / 确认）与文件交付必定送达外部渠道，不会被收敛门拦截。
- 无法确定来源渠道的系统推送（定时任务投递、卡片回调等）不受收敛门影响，宁多投不漏投。
- 修改配置后需重启 JiuwenSwarm 生效；紧急情况下可先用环境变量覆盖。
