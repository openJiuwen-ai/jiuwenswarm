# 自定义 Model Client

JiuwenSwarm 可以在启动时加载指定的 Python model client 文件，无需修改 `agent-core`。未被指定的文件不会加载。

## 放置源码

将文件放在扩展根目录的 `model_clients/` 下，例如：

```text
jiuwenswarm/extensions/model_clients/u_openai_model_client.py
```

Model Client 类通过 `__client_name__` 声明其模型提供商名。OpenAI 兼容接口可参考仓库中的 [`u_openai_model_client.py`](../../examples/u_openai_model_client.py)。

`jiuwenswarm/extensions` 是默认搜索目录。也可以通过进程环境变量 `EXTENSION_DIRS` 指定其他扩展根目录；多个目录用分号分隔。加载器会在每个根目录下查找 `model_clients/<文件名>.py`。

Gateway 和 AgentServer 是独立 Pod，不共享容器文件系统。企业部署时：

- `MODE=dev` 且设置了 `CLAW_CODE_PATH`：部署脚本将该宿主机代码目录分别挂载到两个 Pod，放在其中的 `jiuwenswarm/extensions/model_clients/` 文件可被两边读取。
- `MODE=product`：不挂载宿主机代码目录，所选文件需包含在 Gateway 和 AgentServer 使用的镜像中。

两种模式下，文件依赖的 Python 包都需在两个 Pod 中可用。`.env.custom` 只指定加载哪些文件，不会把源码分发到 Pod。

## 选择要加载的文件

设置 `AGENT_EXTRA_MODEL_CLIENTS`，填写文件名，不带 `.py`：

```dotenv
AGENT_EXTRA_MODEL_CLIENTS=u_openai_model_client
```

多个文件名用逗号分隔，例如 `u_openai_model_client,company_b_model_client`（文件均需存在）。企业部署可在 `deploy/enterprise/.env.custom` 中设置该变量。留空则不加载额外 model client；修改源码或名单后需要重启相关进程。

## 选择模型提供商

文件名用于**加载模块**，模型提供商名用于**选择模块注册的 model client**，两者不必相同。例如，示例类声明了 `__client_name__ = ["UOpenAI"]`：

```text
AGENT_EXTRA_MODEL_CLIENTS=u_openai_model_client  → 加载文件
client_provider: UOpenAI                   → 使用其中注册的 model client
```

在本地环境变量中，对应设置 `MODEL_PROVIDER=UOpenAI`；在 Manager 的模型配置中，对应填写 `model_provider: UOpenAI`。模型名称、API 地址和密钥仍按原有方式配置。

## 确认加载

启动后查看 Gateway 和 AgentServer 日志。成功加载时会出现 `[ModelClientExtensions] Loaded <文件名>`；找不到文件或导入失败时会记录错误。若已加载但模型不可用，检查模型配置中的提供商名是否与 model client 的 `__client_name__` 一致。

该示例还展示了如何把模型响应中指定的额外业务字段放入 `provider_metadata`，供上层按需读取。
