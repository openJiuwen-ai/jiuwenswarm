# 智能审批

智能审批用于减少单 Agent 工作过程中重复的工具确认。它不仅执行预设规则，还会在规则约束下判断工具调用是否符合当前任务。针对**当前这一次工具调用**，它会选择：

- 允许本次调用；
- 拒绝本次调用；
- 转交给你人工确认。

智能审批不会永久放开某个工具，也不会覆盖明确的拒绝规则。

## 生效范围

| 场景 | 是否支持智能审批 | 说明 |
| --- | --- | --- |
| Web 单 Agent 工作模式 | 支持 | 当前主要使用入口。 |
| Code Agent、Code plan | 不支持 | Code 模式智能审批待后续补齐。 |
| Team、集群和分布式 Team | 不支持 | 与现有工具权限审批一致；Team 智能审批待工具权限支持后补齐。 |

表中的“不支持”仅表示当前不提供智能审批保证，不表示相应模式无法使用。

一个智能审批会话只绑定一个主要项目/workspace。需要切换到不同目录时，请新建会话。

## 与其他权限模式的区别

Web 输入框的权限选择器提供以下档位：

| 档位 | 行为 |
| --- | --- |
| **默认权限** | 按现有工具和路径规则直接执行、询问或拒绝；需要确认时显示 Permission 卡。 |
| **智能审批** | 结合当前任务和权限规则，处理每次工具审批；不确定时仍会询问你。 |
| **完全访问权限** | 关闭工具权限边界，不再请求批准。该模式风险显著更高，并不等同于智能审批。 |

权限档位切换从**下一轮对话**开始生效。

## 使用方法

### 在 WebUI 中启用

1. 打开一个单 Agent 工作会话。
2. 点击输入框附近的权限选择器。
3. 选择“智能审批”。
4. 从下一轮对话开始正常提出任务。

遇到需要人工判断的调用时，系统仍会显示 Permission 卡。你可以允许一次、拒绝，或使用现有的“会话内记住”等选项。

### 通过配置启用

配置文件通常位于 `~/.jiuwenswarm/config/config.yaml`。如设置了 `JIUWENSWARM_CONFIG_DIR`，则使用该目录下的 `config.yaml`。

最小配置：

```yaml
permissions:
  enabled: true
  mode: auto
```

切回默认权限：

```yaml
permissions:
  enabled: true
  mode: manual
```

`permissions.mode` 用于选择 `manual` 或 `auto`，不要与后文的 `permissions.permission_mode` 混淆。

## 哪些现有配置会影响智能审批

智能审批建立在现有工具权限之上。以下配置会直接影响最终结果。

### 工具和参数规则

```yaml
permissions:
  schema: tiered_policy
  permission_mode: normal
  defaults:
    "*": ask
  tools:
    bash: ask
    write_file: allow
  rules:
    - id: deny-dangerous-command
      tools: [bash]
      pattern: "rm *"
      action: deny
```

- `permissions.tools`：设置工具级 `allow`、`ask` 或 `deny`。
- `permissions.rules`：按命令、路径或参数设置更具体的规则。
- `permissions.defaults`：没有其它匹配时的默认动作。
- `permissions.permission_mode`：`normal` 或 `strict`，影响没有显式 `action` 的风险等级映射。
- `permissions.package_builtin_rules`：控制是否加载 agent-core 包内安全规则，默认开启，仅 Global/宿主配置可设置，User/Session 不能覆盖。

显式 `deny` 始终优先，智能审批不能覆盖。智能审批也不会把宽泛的默认 `allow` 当作无限制授权；高风险或高灵活度工具仍可能转入自动判断或人工确认。

### 路径和 workspace 规则

```yaml
permissions:
  file_guard:
    enabled: true
    defaults:
      read: ask
      write: ask
      exec: ask
    workspace:
      read: allow
      write: allow
      exec: ask
    paths:
      - path: "/data/shared"
        read: allow
        write: ask
        exec: deny
```

- `file_guard` 控制 workspace、可信目录和外部路径的读、写、执行权限。
- 更具体的路径 `ask` 或 `deny` 会继续限制智能审批。
- `external_directory` 是旧版兼容配置；新配置建议使用 `file_guard`。
- `/add-dir` 添加的可信目录仍按现有路径规则生效。

### 已记住的授权和频道规则

- `permissions.approval_overrides` 和“会话内记住”可能按既有范围减少后续确认，但不能覆盖显式拒绝。
- `permissions.owner_scopes` 继续控制指定频道和用户的工具权限，但不会让 Team 或其它未支持模式获得智能审批。

### AutoReviewer 选项

这些选项通常无需修改：

```yaml
permissions:
  auto:
    reviewer_timeout_ms: 60000
    reviewer_min_confidence: 0.7
    persistent_audit_enabled: false
    bounded_write_max_files: 3
    bounded_write_excluded_paths: []
```

| 配置 | 作用 |
| --- | --- |
| `reviewer_timeout_ms` | 自动判断的超时时间；超时会转人工，不会自动允许。 |
| `reviewer_min_confidence` | 最低置信度；低于阈值时转人工。 |
| `persistent_audit_enabled` | 是否记录持久审计信息。 |
| `bounded_write_max_files` | 有界写入快速路径允许涉及的最大文件数。 |
| `bounded_write_excluded_paths` | 额外排除的敏感路径；会与内置保护路径合并。 |

AutoReviewer 使用当前配置的模型服务进行判断，因此可能增加一次模型请求和少量等待时间。模型不可用、超时或返回无效结果时，系统会转人工或拒绝，不会静默放行。

## 你会看到什么

- 自动允许：工具直接继续，并显示智能审批标记或原因。
- 转人工：显示普通 Permission 卡，由你决定。
- 拒绝：工具不执行，并显示拒绝原因。
- 多个待确认调用：按顺序逐张处理，不提供“全部允许”。

## 已知显示限制

在包含多个 subagent 的任务中，WebUI todo 面板可能显示一个任务“进行中”、其余任务“等待中”，即使多个 subagent 实际已并行运行。这是现有 todo 状态投影问题，不是智能审批导致的串行执行，也不代表 child 获得了智能审批能力。

## 安全建议

- 优先使用“智能审批”，不要为减少确认而长期启用“完全访问权限”。
- 对 shell、外部路径和敏感文件保留 `ask` 或 `deny`。
- 使用 `file_guard` 明确 workspace 和外部目录边界。
- 调整规则后用新一轮对话验证；切换 workspace 时新建会话。
- 定期检查已记住的授权和 `approval_overrides`。

更多配置说明参见[工具权限与安全防护](工具权限与安全防护.md)和[配置信息](配置信息.md)。
