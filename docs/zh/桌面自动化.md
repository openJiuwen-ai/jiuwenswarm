# 桌面自动化（cua_agent）

`cua_agent` 是 JiuwenSwarm 的桌面自动化子代理（computer-use）：它通过界面观察和**窗口截图**了解本机状态，
再用**真实的鼠标和键盘输入**操作原生应用窗口，例如记事本、Office、IDE、聊天客户端、系统对话框和设置面板。

子代理及传统单步工具位于 agent-core（`openjiuwen.harness.subagents.cua_agent` 与
`openjiuwen.harness.tools.cua`）；Windows/macOS 桌面安装包还通过 JiuwenSwarm 的 `CuaExtensionRail`
接入 Computer Use SDK 的持久 Python REPL。实际能力以所安装版本和打包的驱动为准。

> **重要：** 它的输入是真实的。运行期间它会移动你的鼠标，并向当前拥有键盘焦点的窗口输入文字。
> 任务执行时请不要使用这台电脑；支持输入检测的平台还可开启 `pause_on_user_input`（见第 5 节）。

## 1. 适用场景

| 目标位置 | 使用 |
|---|---|
| 网页（URL、网站、Web 应用、登录某个站点） | `browser_agent`，见 [浏览器工具](浏览器.md) |
| 本机原生窗口（已安装的应用、系统对话框、桌面本身） | `cua_agent` |
| Discord、Slack、VS Code、Spotify 等 Electron 桌面应用 | `cua_agent`（它们是原生窗口，浏览器代理无法访问） |
| 不需要图形界面的文件 / 命令行工作 | 主 Agent 自己的工具 |

任务同时跨越网页和桌面时（例如把网页上的数值填进桌面应用），主 Agent 会先用 `browser_agent`
完成网页部分，再用 `cua_agent` 完成桌面部分。

## 2. 前置条件

- **操作系统和安装方式**：Windows、使用 X11 的 Linux（`DISPLAY` 指向 X11 服务器），
  或 macOS 14 及以上。macOS 需使用带原生驱动的桌面安装包，官方 macOS 包
  [仅支持 Apple Silicon（ARM64）](../../README_CN.md)，不支持 Intel。Linux 不支持 Wayland。
- **交互式桌面会话**：必须有真实的显示器/桌面会话；无桌面的服务、锁屏或 SSH 会话无法使用。
- **Windows/Linux 源码或 wheel 安装的 `cua` 可选依赖（默认不安装）**：桌面相关依赖（`pyautogui`、`psutil`，Windows 上的
  `pygetwindow`，Linux 上的 `python-xlib`）作为可选依赖提供，需安装到 JiuwenSwarm 所用的环境中：

  ```bash
  pip install "workswarm[cua]"
  # 或（源码/开发环境）
  uv sync --extra cua
  ```

  在源码仓库中直接执行 `uv sync` 会再次移除这些依赖，请始终带上 `--extra cua`。
  此安装方式不会启用 macOS 的原生 REPL；macOS 桌面安装包需包含 Computer Use SDK 和驱动，
  并在系统提示时取得辅助功能、录屏等所需权限。

- **具备视觉能力（多模态）的模型**：桌面任务需要理解截图，不能只依赖纯文本模型。
  JiuwenSwarm 启动时会向 `models.defaults` 中的每个模型发送一张测试小图。若确认当前模型
  不支持图片输入，则不会挂载 `cua_agent`，主 Agent 会提示你换用支持图片输入的模型；若测试
  结果不确定，则照常挂载。如需跳过测试，可在该模型条目中声明
  `model_client_config.supports_vision: true`（或 `false`）。

## 3. 启用

后端具备运行所需的安装条件时，可在 **设置 → 实验功能 → 电脑操控** 中切换；
不支持的平台、缺少可选依赖或桌面安装包中的驱动文件时隐藏该分组，不改写已保存的选择。
检测不会启动驱动或请求系统权限；可见不代表已经取得系统授权。配置文件中的
`react.subagents.cua_agent.enabled` 默认为 `null`，表示跟随版本默认值（当前关闭）。
只有手动切换开关时才写入 `true` 或 `false`；读取设置及版本升级会保留 `null` 和已有的明确选择。

先满足对应平台的安装和权限条件（见第 2 节），再编辑 `~/.jiuwenswarm/config/config.yaml`（模板见 `jiuwenswarm/resources/config.yaml`）：

```yaml
react:
  subagents:
    cua_agent:
      enabled: true              # 明确开启；null 跟随版本默认值（当前关闭）
      # max_iterations: 100      # 子代理轮次上限，默认 100
      # snapshot_keep_last_k: 3  # 上下文中完整保留的截图数量，默认 3
      pause_on_user_input: false # 用户使用鼠标/键盘时暂停操作，空闲后继续
```

同一个 `enabled` 开关同时作用于单 Agent（deep）模式、代码模式以及团队（swarm）成员
（provider `swarm.cua_agent`），与运行模式无关。修改后重启 JiuwenSwarm 生效。

## 4. 使用

直接在对话中描述要在桌面上完成的结果，不需要说“使用子代理”。启用后，主 Agent 会：

- 用同步的 `task_tool`（`subagent_type` 为 `"cua_agent"`）委派桌面任务，并在 `task_description`
  中保留完整目标，而不是缩减为步骤说明；
- 每次委派前弹出“操作确认: cua_agent”卡片，列出任务内容并提示子代理可能启动应用（`launch_app`）和输入文字（`type_text`）。
  可选“本次允许”“会话内记住”“永久记住”“拒绝”；“永久记住”会把 `require_approval` 写为 `false`，所有会话不再询问（见第 5 节）；
- 在发送消息、删除文件、提交表单、支付等不可逆操作执行前，先请你确认；
- 不通过 Bash、PowerShell、pyautogui、AutoHotkey 等脚本自行驱动图形界面；`cua_agent` 不可用时会直接说明。

### 4.1 示例

- “打开记事本，输入 hello，保存到桌面，文件名为 hello.txt。”
- “看看现在打开了哪些窗口。”
- “在计算器里算 1234 × 5678，把结果告诉我。”
- “打开设置，切换到深色模式。”
- “在 VS Code 里打开命令面板，执行 Format Document。”

### 4.2 工作方式

Windows/Linux 的传统单步工具先用 `list_windows` / `list_apps` 找到目标窗口，调用 `get_window_state` 把该窗口置于前台并截图，
再按截图中的像素坐标点击、输入或滚动；每次输入后会重新截图核对效果，只有屏幕上有证据时才声明完成。

传统单步工具（macOS 不提供此后端）：

| 类别 | 工具 |
|---|---|
| 观察（只读） | `list_windows`、`list_apps`、`get_window_state`、`zoom`、`get_screen_size`、`get_cursor_position` |
| 输入 | `click`、`double_click`、`right_click`、`move_cursor`、`drag`、`scroll`、`type_text`、`press_key`、`hotkey` |
| 应用 | `launch_app`、`bring_to_front` |

强制结束进程的 `kill_app` 不在默认工具集中。

Windows/macOS 桌面安装包另有 `cua_repl`：通过 Computer Use SDK 执行支持顶层 `await` 的 Python，
预置 `computer`、`print` 和 `print_image`，同一委派内保留变量。macOS 的桌面操作使用此入口；
Windows 可在单步工具和 REPL 之间选择，但两者的引用和截图坐标不能混用。
代理应依次等待每个操作完成，读取界面核验结果；需要查看截图时使用 `print_image`。
工具成功返回仅说明该次调用的结果，不代替文件名、文件数量等任务后置条件的核验。

### 4.3 REPL 会话失效后的恢复

当原生会话已退休（`Native session is retired`）或 SDK 要求重置会话时，代理可调用
`cua_repl_reset`，参数为 `{}`。这是独立的恢复工具，不接收或执行任务代码。

- 重置成功表示旧执行会话已清理，Python 变量和旧界面引用均被清空。随后重新创建应用变量、
  读取当前界面，再决定下一步；之前的点击或输入可能已经生效，重置不会撤销或自动重放它们。
- 普通 Python 错误（例如 `NameError`）无需清空会话；修正代码即可继续使用已有变量。
- 清理无法确认时，后续 REPL 执行被阻止；只能由持有该会话的恢复入口显式重试清理，
  不能通过另一个会话解除阻塞。重置不会跳过任务授权或 macOS 系统权限。
- 重置只适用于活动中的委派。取消或关闭后的运行时不会被重置重新打开；再次执行需要新委派，
  仍须先确认旧资源已清理。

会话重置解决的是运行时恢复，不保证任务已经完成，也不保证反复操作无进展或模型等待问题已解决。

## 5. 配置项

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `react.subagents.cua_agent.enabled` | boolean / null | `null`（当前关闭） | 是否挂载 `cua_agent`；`null` 跟随版本默认值，明确的 `true` / `false` 在升级后保持不变。 |
| `react.subagents.cua_agent.max_iterations` | int | `100` | 子代理轮次上限。“截图-操作-核对”循环较耗轮次，不建议调得过低。 |
| `react.subagents.cua_agent.snapshot_keep_last_k` | int ≥ 1 | `3` | 上下文中完整保留的最近截图数量。默认 3 可兼顾两个窗口之间切换的任务；只操作单个窗口的任务设为 `1` 可大幅缩减上下文。非法值会被忽略并记录警告，沿用默认值。 |
| `react.subagents.cua_agent.pause_on_user_input` | boolean | `false` | 检测到你在使用鼠标/键盘时暂停桌面操作，空闲约 5 秒后自动继续；持续使用超过约 60 秒时，子代理会结束本次任务并汇报已完成的部分。仅 Windows 和 Linux X11 支持检测，其他环境下该选项不起作用。 |
| `react.subagents.cua_agent.require_approval` | boolean | `true` | 主 Agent 每次把任务交给 `cua_agent` 前弹出确认卡片（完全访问权限下同样询问）。在卡片上选择“永久记住”会写入 `false`，此后所有会话不再询问；改回 `true` 可恢复询问。 |

环境变量：

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `OPENJIUWEN_SUBAGENT_TASK_TIMEOUT_S` | `720` | 单次 `task_tool` 委派的超时（秒）。长时间桌面任务可调大；非正数会被忽略。`cua_agent` 会在超时前约 20 秒主动收尾，返回可继续的结果。 |

## 6. 安全建议

- 运行期间不要操作鼠标键盘，否则你的输入和子代理的输入会相互干扰；支持输入检测的平台可开启 `pause_on_user_input`。
- **停止任务**：使用客户端的停止操作。传统 pyautogui 单步后端还可通过把鼠标移到屏幕角落触发 fail-safe；
  原生 `cua_repl` 不使用这项机制，不能把屏幕角落当作它的停止开关。
- 执行前关闭或最小化与任务无关、含敏感信息的窗口；截图会发送给模型。
- 子代理可以通过 `launch_app` 启动本机程序、通过 `type_text` 向任意聚焦窗口输入文字，请只在可信任务和可信模型下启用。
- 涉及发送、删除、支付等不可逆操作时，在主 Agent 请求确认时仔细核对。
- 委派确认卡片是子代理接管桌面前的最后一道确认。选择“永久记住”后所有会话都不再询问；需要恢复时把 `react.subagents.cua_agent.require_approval` 改回 `true`。

## 7. 常见问题排查

| 问题现象 | 可能原因 | 解决方法 |
|---|---|---|
| 主 Agent 不调用 `cua_agent`，或说“不可用” | 未启用 | 确认 `react.subagents.cua_agent.enabled: true` 并重启 |
| 主 Agent 说桌面能力不可用，因为模型无法理解图片 | 当前模型未通过启动时的图片测试，因此未挂载 `cua_agent` | 换用支持图片输入的模型；若测试结果有误，可在模型条目中设置 `supports_vision: true` |
| `No module named 'pyautogui'` / `cua desktop preflight failed` | 未安装 `cua` 可选依赖，或被直接执行的 `uv sync` 移除 | 执行 `pip install "workswarm[cua]"`，源码仓库中执行 `uv sync --extra cua`，然后重启 |
| `no backend for platform 'darwin'` | macOS 调用了传统单步后端，或当前安装未提供原生 REPL | 使用带驱动的 macOS 桌面安装包，通过 `cua_repl` 操作；安装 `cua` extra 不会补齐 macOS 后端 |
| `Native session is retired` / SDK 要求 `computer_use_reset` | 原生调用的准入或清理状态无法确认 | 在 WorkSwarm 中调用 `cua_repl_reset`；成功后重新观察，勿直接重放先前动作（见 4.3） |
| 重置后提示清理未确认 | 旧 worker 或原生资源尚未确认退出 | 保持 REPL 执行阻塞，由同一会话显式重试恢复；持续失败时停止任务并检查运行日志 |
| `DISPLAY is not set` | Linux 无 X11 显示，或使用 Wayland | 在 X11 桌面会话中运行，并确保 `DISPLAY` 已设置 |
| 提示窗口已最小化 | 目标窗口被最小化（坐标约为 -32000） | 子代理会先调用 `bring_to_front`；如仍失败，手动还原窗口后重试 |
| `could not bring window ... to the foreground` | 系统拒绝切换前台窗口（如有全屏程序或系统弹窗） | 关闭遮挡的全屏程序/弹窗后重试 |
| 子代理点不准、反复操作无效 | 模型视觉能力不足，或目标过小 | 换用视觉能力更强的模型；在任务描述中说明目标位置 |
| 子代理看不到界面，委派很快以 “Max iterations reached” 结束 | 模型不支持图片输入，但启动测试结果不确定，`cua_agent` 仍被挂载 | 换用多模态模型 |
| 委派结果中 `cua_result.status` 为 `"partial"`，恢复提示提到迭代上限 | 任务未完成前就达到了 `max_iterations` | 续跑该任务；长任务可调大 `max_iterations` |
| 任务中途因超时结束 | 超过 720 秒委派上限 | 设置 `OPENJIUWEN_SUBAGENT_TASK_TIMEOUT_S`，或拆分任务 |

## 8. 已知限制

- 平台和安装方式受第 2 节限制；macOS 的源码/wheel 安装不提供原生 REPL，官方 macOS 包不支持 Intel。
- 同一时间只有一个前台窗口和一套鼠标键盘，桌面任务无法与用户操作或其他桌面任务并行。
- 停止或取消不能撤销已经发送的输入。REPL 在取消时清理执行会话；清理未确认时阻止后续 REPL 执行。
  恢复任务前仍需核对界面和已完成的业务步骤。
