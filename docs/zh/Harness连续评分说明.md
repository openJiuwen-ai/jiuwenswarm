# Harness 连续评分与基线对照

当前规范：[Harness 两项修改说明](Harness两项修改说明.md)。新任务使用
`continuous_two_stage_v2`，替代先前的额外全量确认方案。

## 两个评估阶段

1. 目标预检：每道目标题独立满足 `候选分 > 本题基线 + 0.05`。
2. 全量评估：重新运行所有题，包括目标题，同时要求：
   - 每道目标题严格高于自己的冻结基线。
   - 每道其他题不低于自己的基线减 0.05，边界允许。
   - 全量连续均分严格高于修改前均分，不要求再提高 0.05。

多目标不能用平均值掩盖某题没改善。评估异常或缺测不放行。全量之后没有第三次
确认；相同包、同基线、同协议不能靠换目录重复抽分。原有工程和行为证据检查保留。

本次两阶段都使用修改前同一份逐题基线。晋级后，以这次全量评估的逐题成绩和均分
作为下一次修改的基线，不再使用目标预检高分或历史峰值。未晋级则继续使用父版本。

LLM Judge 输出的连续 rubric 总分直接作为单题分；候选、全量和 Best 都使用连续分。
前端保留三位小数，判定使用未舍入分数；`passed` 只是达标标记。

## Judge 基线对照

候选两阶段评分都提供同题修改前的回答、真实产物、连续分、逐项分和理由。
大文件在隔离只读 `baseline/` 中按需读取；评分明细直接放入请求。
全量阶段不告诉 Judge 候选目标题首评得过多少分。这些对照资料不进入 Solver 输入。
历史评分疑点可以报告，不能改写冻结基线。已记录的基线产物丢失或变化时停止比较。

## 配置与产物

默认 `promotion.min_improvement=0.05`，`promotion.non_target_max_regression=0.05`。
已移除 `confirmation_runs`。旧 continuous_margin_v1 任务不自动迁移为新规则。

每个 attempt 的 `target/` 保存目标题首评，`full/` 保存独立全量评估。
`single_harness_state.yaml` 和 `single_harness_report.yaml` 保存连续分、目标提升凭证、
逐题分差及全量三个条件的判断。Judge 的 `baseline_context.json` 标明基线来源。
只有完整通过两阶段及工程验收的包可以发布和安装。

代码已调整，尚未进行运行验证，也未构建前端或重启服务。
