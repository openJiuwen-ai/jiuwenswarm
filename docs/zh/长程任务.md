# 长程任务

长程任务（Long Horizon Task）用于跨日期、多阶段的目标跟踪：Agent 先规划草稿，用户确认后创建 Gateway Cron；到点只弹 Toast，不自动开工。会话内 `todo_*` 仍负责当前回合拆解，二者不互相替代。

与 [任务规划](任务规划.md)（会话内 todo）和 [定时任务](定时任务.md)（通用 Cron）的区别：长程任务绑定固定执行会话 `longhorizon_{task_id}`，每个阶段对应 Gateway 侧闹钟键 `lh-{task_id}-{stage_id}`；到点只走长程投递，不落入普通定时 LLM wake。

## 工具名与可用模式

| 项 | 说明 |
| :--- | :--- |
| Agent 工具 | `long_horizon_task`（单工具、多 `action`） |
| Python 包 | `jiuwenswarm.agents.harness.common.long_horizon` |
| 模式 | **仅普通 Agent**；Team / Code 模式不装配、不可见 |

### Action 一览

| action | 作用 |
| :--- | :--- |
| `draft` | 校验并保存草稿，**不**创建 Cron |
| `confirm` | 锁定 brief 与阶段计划，创建执行会话与每阶段 Cron |
| `update` | 整表重写 stages（保留 `task.id` / `exec_session_id`） |
| `list` | 列出已有长程任务 |
| `inbox` | 查询已到期、待处理的阶段 |
| `delete` | 删除任务并取消关联 Cron |
| `stage_action` | `start` / `done` / `skip` / `snooze` / `defer` / `mute_year` |

## 审批与规划规则

- 至少一个用户明确给出的阶段；每个阶段必须有非空 `plan`（做什么、怎么做）。
- **禁止**默认 T-30 / T-7 / T-1 等阶段模板；缺阶段、日期或背景时先追问用户。
- `draft` 后必须等用户确认；`confirm` 必须提供非空 `brief`（目标、约束、交付物、关键背景）。
- `confirm` 成功的当前回合不得直接执行阶段劳动或把阶段标为完成。
- `draft` 不调度；只有 `confirm` 后才创建 Cron。

常见错误码：`brief_required`、`stage_plan_required`、`task_not_found`、`stage_not_found`。

## 调度与执行会话

- 执行会话：`longhorizon_{task_id}`（一任务一会话，对话列表可见）。
- Cron job：`lh-{task_id}-{stage_id}`（一阶段一 job；**不**绑 `session_id`，避免被当成普通 Cron 会话）。
- 到点先标记阶段为 `due` 并推送 `long_horizon.stage_due`，**不**自动开工、**不**走普通 Cron LLM wake。
- `start`：用户（Toast/立即执行）可开任意未结束阶段；Agent 只能开下一未完成阶段。
- `snooze` 默认按任务时区（Asia/Shanghai）延后 2 小时并重建 Cron；`defer` 默认顺延 7 天。
- 阶段 `done` / `skip` 或任务删除时，只取消对应未完成 Cron。

## 存储

| 文件 | 位置 |
| :--- | :--- |
| 任务 | `{agent_workspace}/long_horizon_tasks.json` |
| 审计事件 | `{agent_workspace}/long_horizon_events.jsonl`（append-only） |


## Web Toast

- 展示任务标题、阶段标题与到期时间。
- 操作：**现在做** / **稍后** / **跳过**。
  - 现在做 → `stage_action=start`，切换到执行会话并注入 kick prompt。
  - 稍后 → 默认 snooze 两小时并刷新 Cron。
  - 跳过 → `stage_action=skip`，取消该阶段 Cron。
- 浏览器 WebSocket 方法：`long_horizon_list`、`long_horizon_inbox`、`long_horizon_stage_action`（Gateway 转发到 AgentServer，**不是** gRPC）。
- 启动/重连时调一次 `inbox`，恢复未处理的到点提醒；调用失败时 Toast 保留以便重试。
