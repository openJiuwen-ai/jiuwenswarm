# 实验完整性与工件血缘

`ExperimentIntegrityRail` 记录实验的实际执行过程，并将报告指标反向链接到生成它的
命令、运行环境、输出工件和工件哈希。该能力默认关闭、仅观测且 fail-safe：即使溯源
记录失败，也只记录告警，不会改变 Agent 的执行结果。

## 启用 Rail

在 `config.yaml` 中显式启用：

```yaml
research_integrity:
  enabled: true
  # 留空时使用 <project_root>/.jiuwen/research_integrity
  manifest_dir: ""
  # 空列表使用内置默认值
  tracked_tools: []
  tracked_stages: []
```

相对 `manifest_dir` 会以 `project_root` 为基准解析；绝对路径保持不变。

默认记录 `bash`、`code`、`python` 和 `run_research_experiment` 工具。设置非空
`tracked_stages` 后，只记录指定工作流阶段。

## 运行可验证实验

独立 API 会执行事先声明的命令、哈希输出、确定性提取指标，并验证完整血缘：

```python
from jiuwenswarm.research_integrity import (
    ExperimentSpec,
    MetricSpec,
    run_research_experiment,
)

spec = ExperimentSpec(
    experiment_id="evaluation_seed42",
    name="evaluation",
    command="python evaluate.py --seed 42 --output results.json",
    cwd=".",
    seed=42,
    expected_artifacts=["results.json"],
    metric_specs=[
        MetricSpec(
            name="accuracy",
            source="results.json",
            locator="$.accuracy",
        )
    ],
)

outcome = run_research_experiment(spec, project_root=".")
if not outcome.passed:
    raise RuntimeError(outcome.report.model_dump_json(indent=2))
print(outcome.run.run_id)
```

支持的指标定位器：

- JSON：`$.accuracy` 或 `$.results[0].score`
- CSV：`row=method_a,column=accuracy`
- JSONL：`jsonl[line=14].score`

指标始终从工件中确定性解析，不从模型生成文本中推断。进程失败、输出缺失、工件哈希改变、
非有限数指标或 seed 关系不合法，都会导致验证失败。

## 存储结构

默认 manifest 根目录：

```text
<project_root>/.jiuwen/research_integrity/
  specs/
  runs/
  artifacts/
  metrics/
  reports/
  fingerprints/
  sessions/
```

每个工件都记录 SHA-256。环境指纹包含 Python 与平台信息、依赖/配置/数据集/代码哈希，以及可选
Git 状态。环境变量只有在显式加入白名单时才会被记录。

## 安全与运行边界

- 功能默认关闭，只向配置的本地 manifest 目录写入数据。
- 工具载荷写入前，会脱敏常见密钥字段、Bearer 值、环境变量赋值和 CLI secret 参数。
- 脱敏属于纵深防御，不是密钥传输机制；不要把密钥直接写入命令行或实验工件。
- 不记录模型响应正文，只保留模型标识和 token 用量元数据。
- Rail 只负责观测；强制完整性规则的是确定性实验工具与 validator。
