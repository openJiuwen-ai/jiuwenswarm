# 专家图谱与专家团

小艺 Work 的专家图谱把已安装的单专家归一化为带版本的能力节点，通过显式产物契约建立可执行边，再从连通 DAG 中发现 2～4 人专家团候选。候选可一键物化为 beta3 原生 `agent_group`，无需修改 `agent-core`。

## 完整链路

```text
专家来源
  → ExpertInventory（校验、去重、冲突隔离）
  → ExpertGraph（硬契约边 + 发现型语义边）
  → 子图挖掘（2～4 个单专家、连通、无环、无冲突）
  → beta3 AgentGroup renderer
  → 专家广场加载并运行
```

已有专家团会作为参考节点进入图谱，但不会再次成为新专家团成员，避免 beta3 不支持的 team-of-teams。历史 `package_type=agent_template` 单专家会显示为 `needs_conversion`，转换为 beta3 `packageType=agent_template` 并通过真实包校验后才可参与组团。

## 协作契约

协作字段位于单专家 `manifest.json` 的 `metadata.collaboration`，未知字段不会影响专家独立安装和使用：

```json
{
  "contractVersion": "xiaoyi.expert-collaboration.v1",
  "reusable": true,
  "inputs": [
    {
      "id": "insight.json",
      "mediaType": "application/json",
      "schema": "xiaoyi.insight.v1",
      "visibility": "internal"
    }
  ],
  "outputs": [
    {
      "id": "campaign.html",
      "mediaType": "text/html",
      "schema": "xiaoyi.rendered-html.v1",
      "primary": true,
      "visibility": "public"
    }
  ]
}
```

只有 `mediaType` 与 `schema` 都精确匹配，图谱才建立 `can_feed` 可执行交接边。格式相同但 schema 缺失或不一致时只产生 `needs_adapter`；标签、Skill 或显式关系得到的 `complements`、`overlaps`、`conflicts` 只用于发现和解释，不能冒充可运行链路。

专家团运行时，中间 JSON 写入共享工作区 `.expert-handoffs/`，最终成员只把 `public + primary` 成品交给用户。每个成员保留自己专家包中原始 Skill 名称和 Skill ownership，顶层专家团不会把所有 Skills 无差别注入所有成员。

## RPC

WebChannel 将下列方法原样转发给 AgentServer：

- `experts.inventory.refresh`：重新读取真实专家来源。
- `experts.graph.build`：生成或返回当前进程图谱；`force=true` 强制重建。
- `experts.graph.get`：只读取进程内快照；没有快照时返回 `graph: null`。
- `experts.teams.mine`：按当前 `graph_id` 挖掘候选，拒绝过期图谱。
- `experts.teams.materialize`：仅允许物化服务端刚挖掘出的候选，重新 fetch 成员并再次拒绝 nested team。

物化采用 staging + 原子提交，绝不覆盖已有同名包。若成员版本变化或图谱过期，调用方必须重新构图和挖掘，不能提交自定义成员路径绕过校验。

## 本地验证

源码验证环境需要显式启用本地专家来源：

```bash
export JIUWEN_EXPERT_LOCAL_DIRS=1
```

`scripts/prepare_expert_graph_demo.py` 可把多个现有单专家目录统一转换到 beta3 schema，并从独立 JSON 注入协作契约。脚本不覆盖已有包，也不会改动原始专家；`examples/xiaoyi_expert_graph_demo/collaboration_contracts.json` 仅是示例数据，不进入生产图谱逻辑。

附件中的现有专家团可作为子图结构参考，但不会被直接嵌套。含明文凭据或未满足外部依赖的包必须先隔离、移除凭据并完成依赖检查，不能因为结构校验通过就进入可执行候选。

## 后续扩展边界

本期入口是已安装专家。后续 Skill 图谱发现 Skill-Pack 时，只需复用统一归一化入口把 Skill-Pack 转为带 `metadata.collaboration` 的 beta3 单专家；ExpertGraph、子图挖掘、物化和 UI 协议无需改写。动态 discovery/evaluation 不在本期运行主链路中。
