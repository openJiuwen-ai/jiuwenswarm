# 安全策略 (Security Policy)

感谢您帮助提升 AgentSSAS 的安全性。本文档说明如何报告安全漏洞以及漏洞的处理流程。

## 支持版本

| 版本 | 支持状态 |
| ---- | -------- |
| 0.1.x | ✅ 支持 |

仅最新次版本线（minor line）接受安全修复；已过时的版本不再维护，建议升级到最新版本。

## 报告漏洞

请**勿在公开 Issue、讨论区或代码评论中提交未披露的漏洞细节**（包括可利用代码、PoC）。

按敏感程度选择报告渠道：

| 渠道 | 适用场景 | 入口 |
| ---- | -------- | ---- |
| 私密渠道（推荐） | 可被利用的漏洞、敏感安全问题 | 通过 AtomGit 平台**私信**联系仓库维护者（[yieux1](https://atomgit.com/yieux1)），标题注明 `[security] AgentSSAS` |
| Issue | 非敏感的安全加固建议、依赖组件风险讨论 | <https://atomgit.com/yieux1/AgentSecurity/issues> |

### 报告内容要求

为便于快速定位与复现，私密报告请尽量包含：

1. **影响范围**：涉及的模块 / 文件 / 版本号（`agent-ssas` 版本或仓库分支）
2. **漏洞类型**：如命令注入、路径穿越、信息泄露、反序列化等
3. **复现步骤**：最小可复现的环境、配置与操作序列
4. **影响评估**：可能的攻击面与后果（机密性 / 完整性 / 可用性）
5. **修复建议**（可选）

## 响应时限

| 阶段 | 目标时限 |
| ---- | -------- |
| 确认收到报告 | 3 个工作日内 |
| 初步评估（是否为漏洞、严重等级） | 7 个工作日内 |
| 修复方案与计划 | 评估完成后 5 个工作日内 |

时限为尽力而为的目标，节假日可能顺延；超时未响应可通过 Issue 催办（不含漏洞细节）。

## 处理流程

1. **确认与评估**：维护者确认报告，评定风险等级（safe / low / medium / high / critical）
2. **修复开发**：在私有分支完成修复与回归测试
3. **发布**：随下一个 PATCH / MINOR 版本发布安全修复；critical 级别漏洞可发布紧急版本
4. **披露**：版本发布后，在 [CHANGELOG.md](CHANGELOG.md) 与 [发布页](https://atomgit.com/yieux1/AgentSecurity/releases) 公开致谢（报告者同意的前提下）

## 披露政策

我们遵循**协调披露**原则：

- 修复发布前，请勿公开漏洞细节
- 若报告后 90 天内未发布修复，报告者可自行决定是否公开披露（请提前 14 天告知维护者）

## 安全设计说明

AgentSSAS 自身遵循 fail-open 设计：分析引擎故障时不会阻断被保护 Agent 的业务执行。相关机制参见 [design/](design/) 目录下的设计文档。
