# HTTP API Reference

In HTTP service mode (`mode: http`), AgentSSASCore runs as a standalone FastAPI service, and AgentSSASSecurityRail forwards events to `POST /api/v1/events` via `AgentSSASRemoteBackend` to obtain risk assessment results. This document explains how to start the service, the API schema, and the authentication mechanism.

Related documentation:

- [Configuration Reference](./configuration.md): the `http_*` configuration fields
- [Event Format Reference](./event-format.md): the three-layer `raw_event` structure
- [Run Tests](../how-to/run-tests.md): dependencies of the HTTP-related tests

## Starting the Service

### Option 1: Module Entry Point (Default Configuration)

```bash
python -m agent_ssas.core.modes.http.server
```

Uses the `AgentSSASConfig()` defaults and listens on `0.0.0.0:8443`. The listen address, port, and storage root can be overridden via environment variables:

```bash
SSAS_HTTP_HOST=0.0.0.0
SSAS_HTTP_PORT=8443
SSAS_HOME=<storage root>
```

Starting via this entry point requires the `http` extra dependencies (fastapi, uvicorn, httpx).

### Option 2: Example Script (Loopback Only)

```bash
cd AgentSecurity/AgentSSAS
uv run --extra http python examples/http_server_demo/start_server.py
```

The demo script listens on `http://127.0.0.1:8443` (local access only); environment variables can still override it. The companion client example `examples/http_server_demo/client.py` demonstrates the complete flow of health checks and event reporting.

### Server Information

- Application title: `AgentSSAS HTTP Server` (FastAPI, version 0.1.0).
- Interactive documentation: once started, available at `http://<host>:<port>/docs` (OpenAPI docs auto-generated by FastAPI).

## POST /api/v1/events

Reports one raw_event and returns the risk assessment result. This is the HTTP mapping of `AgentSSASBackendProtocol.report_event`; the event type is distinguished by the `raw_event.common.event_type` and `event_class` fields.

### Request

```text
POST /api/v1/events
Content-Type: application/json
```

Request body (`EventRequest`):

| Field | Type | Description |
|-------|------|-------------|
| `raw_event` | dict | The raw event with the three-layer structure (common / payload / metadata); see the [Event Format Reference](./event-format.md) |

### Response

Response body (`AssessmentResponse`):

| Field | Type | Description |
|-------|------|-------------|
| `assessment` | dict | Serialized `RiskAssessment` |

`assessment` contains the 9 fields of `RiskAssessment`:

| Field | Type | Description |
|-------|------|-------------|
| `has_risk` | bool | Whether a risk was detected |
| `risk_level` | str | Risk level: safe / low / medium / high / critical |
| `risk_type` | str | Risk type |
| `risk_score` | float | Risk score |
| `confidence` | float | Confidence |
| `detected_threats` | list[str] | List of detected threats |
| `recommended_actions` | list[str] | List of recommended actions (default `["log"]`) |
| `details` | dict | Details |
| `evidence` | dict | Evidence |

### curl Example

```bash
curl -X POST http://localhost:8443/api/v1/events \
  -H "Content-Type: application/json" \
  -d '{
    "raw_event": {
      "common": {
        "source": "AgentSSASSecurityRail",
        "event_type": "invoke_start",
        "event_class": "lifecycle",
        "timestamp": 1767196800.0,
        "interaction_seq": 0,
        "session_id": "demo-session",
        "conversation_id": "demo-session",
        "agent_id": "demo-agent",
        "trace_id": "demo-trace",
        "context_id": "demo-ctx",
        "llm_call_seq": -1,
        "tool_call_seq": -1,
        "subsession_id": "",
        "tool_call_id": ""
      },
      "payload": {
        "content": { "query": "帮我列出当前目录下的文件" }
      },
      "metadata": {}
    }
  }'
```

Response example:

```json
{
  "assessment": {
    "has_risk": false,
    "risk_level": "safe",
    "risk_type": "",
    "risk_score": 0.0,
    "confidence": 0.0,
    "detected_threats": [],
    "recommended_actions": ["log"],
    "details": {},
    "evidence": {}
  }
}
```

With authentication enabled, include the token:

```bash
curl -X POST http://localhost:8443/api/v1/events \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{"raw_event": {...}}'
```

## GET /health

Health check endpoint, **no authentication required**:

```bash
curl http://localhost:8443/health
```

Response:

```json
{"status": "ok"}
```

## Bearer Token Authentication

When `AgentSSASConfig.http_token` is not `None`, the server enables the Bearer token authentication middleware (`TokenAuthMiddleware`):

- All requests except `/health` must carry an `Authorization: Bearer <token>` header, and the token must exactly match the configured value.
- A missing, malformed, or mismatched token returns:

```text
HTTP/1.1 401 Unauthorized

{"detail": "Unauthorized"}
```

Configuration (config.yaml or the `SSAS_HTTP_TOKEN` environment variable):

```yaml
ssas:
  mode: http
  http_token: "my-secret-token"
```

When `http_token` is left at the default `None` (empty in YAML), authentication is disabled and all requests pass through.

## Lazy Initialization Behavior

The service does not create the analysis backend at startup. Only when the first request reaches `POST /api/v1/events` does the server create and initialize the in-process `AgentSSASBackend` (including detection module scanning/loading and storage initialization); subsequent requests reuse that instance. Therefore:

- The first request responds noticeably slower than subsequent ones (it includes the backend initialization overhead).
- Changes to the detection module enable/disable configuration take effect any time before the first request arrives; once initialization completes, the service must be restarted to change the module set.
- To initialize at startup instead of lazily, call `initialize_app(app, config)` (provided by `http_server.py`) when building your own service.

## Client Configuration

When AgentSSASSecurityRail runs in HTTP mode, it connects to the server with the following configuration (see the [Configuration Reference](./configuration.md)):

| Configuration | Default | Description |
|---------------|---------|-------------|
| `ssas.mode` | `inprocess` | Set to `http` to enable client mode |
| `ssas.http_endpoint` | `http://localhost:8443` | Server address |
| `ssas.http_timeout` | `5.0` | Client timeout in seconds |
| `ssas.http_token` | `None` | Bearer token, must match the server |
