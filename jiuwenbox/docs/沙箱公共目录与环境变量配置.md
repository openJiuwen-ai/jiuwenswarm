# 沙箱公共目录与环境变量配置

JiuwenBox 接受宿主显式声明，不依赖特定桌面客户端、技能目录布局或产品环境变量。JiuwenSwarm 可以独立提交、部署；其受管 Windows runner 可为 Python、Node 和标准 Git for Windows 生成工具声明，见下文。独立组件没有收到声明时不增加公共目录权限或工具变量继承，也不自动安装依赖、选择技能解释器。

## 宿主接口

| 接口 | 输入与默认值 | 作用 |
| --- | --- | --- |
| JiuwenSwarm `sandbox.path_allowlist` | 绝对目录字符串列表，默认 `[]` | 声明服务共享的可读写目录。 |
| JiuwenSwarm `sandbox.env_allowlist` | 明确的环境变量名列表，默认 `[]` | 从 AgentServer 环境复制对应值，不在 YAML 保存值；保留空字符串。 |
| JiuwenBox `JIUWENBOX_PATH_ALLOWLIST` | JSON 数组，默认 `[]` | 独立组件的公共可读写目录接口；由 JiuwenSwarm 根据 YAML 设置。 |
| JiuwenBox `JIUWENBOX_ENV_ALLOWLIST` | JSON 数组，默认 `[]` | 独立组件的变量继承接口；由 JiuwenSwarm 根据 YAML 设置。 |
| Windows `JIUWENBOX_TOOL_PATHS` | JSON 对象，默认 `{}` | 声明只读工具根 `read_roots` 和命令 PATH 前缀 `executable_dirs`。 |
| Windows `JIUWENBOX_SERVICE_READ_ROOTS` | 绝对目录 JSON 数组，默认 `[]` | 宿主声明服务代码、公共资源的共享只读根，不加入命令 PATH。 |

```yaml
sandbox:
  path_allowlist:
    - 'C:/shared/dependencies'
  env_allowlist:
    - HOST_TOOL_TOKEN
    - HOST_PYTHON_EXE
```

路径支持 `~` 和宿主环境变量，按宿主文件系统规范化、去重；相对路径、通配符、空条目和规范化后的文件系统根目录无效。宿主需要为配置选择合适的权限范围；这是跨会话共享授权，不是单会话临时目录。

变量按明确名称继承，不支持通配符。不存在的键不注入；系统必需变量由组件维护。宿主加载器过滤、Windows profile/TEMP 和强制代理覆盖仍生效。把 `PYTHONPATH` / `NODE_OPTIONS` 等加入白名单不会让服务加载器配置自动进入工具命令。

Windows 工具声明示例：

```json
{"read_roots":["C:/tools/python","C:/tools/node"],"executable_dirs":["C:/tools/python","C:/tools/node"]}
```

两个字段都是绝对非根目录列表，`executable_dirs` 必须由 `read_roots` 覆盖。工具根默认只读；位于显式公共可写根内的工具目录保留可写权限。宿主负责解析 venv 基础解释器、选择实际存在的可执行文件，以及提供技能所需的预装依赖；组件不解析产品变量来发现它们。

Git/Bash 运行时同样需要工具声明，例如 `read_roots: ["C:/tools/git-win"]`，以及该根下实际存在的 `cmd`、`bin`、`usr/bin` 可执行目录。声明完整 Git 根可覆盖 Bash、Git 的已有文件和依赖 DLL。

Windows 内部启动时，若服务环境完全未提供 `JIUWENBOX_TOOL_PATHS`，JiuwenSwarm runner 在 `--ensure` 和 box-server 启动之前生成统一工具声明，两者接收同一环境：

- Python：优先将 `JIUWENBOX_VENV_DIR/Scripts` 放入声明的可执行目录，避免裸 `python` 先命中 runner Python；缺少受管 venv 时才查服务 PATH。`pyvenv.cfg` 中的 `base-executable`、`executable`、`home` 仅用于解析和校验，不能独立产生 ACL 授权。最终文件名必须为 `python.exe` 或 `pythonw.exe`，且受管 venv 的基础解释器必须与宿主钉扎记录一致；验证后才声明完整 venv 和基础运行时目录，不将 `Scripts` 误认为基础运行时。runner Python 与工具 Python 可不同。
- Node：从服务 PATH 查找 `node.exe`，要求同目录存在 `npm.cmd`，只声明该 Node 目录，不推导其父级 runtime 或用户数据目录。其他布局由宿主显式声明。
- Git/Bash：从服务 PATH 查找 `git.exe`，仅接受 `cmd/git.exe`、`bin/git.exe`、`mingw64/bin/git.exe`、`mingw32/bin/git.exe` 的标准布局，且同根 `usr/bin/bash.exe` 必须存在；声明完整 Git 根及实际存在的可执行目录。

自动发现只使用服务 PATH 中的绝对目录，不搜索当前目录或相对 PATH。已有声明（包括显式空字符串或空对象）保持原样，显式声明的技能解释器选择不会被覆盖；非法显式声明仍交给组件拒绝。受管 venv 缺失解释器、无法解析或与钉扎不一致时拒绝启动，不发布 `JIUWENBOX_BUNDLED_PYTHON`，也不生成自动声明。PATH、BUNDLED、RUNNER 等可选 Python 来源解析失败时仅告警并跳过，保留其他有效声明；可选 venv 没有宿主钉扎时也跳过。Linux 和外部启动模式不进行此自动声明。只读工具根沿用组件语义；显式 `JIUWENBOX_VENV_DIR` 仍是可写根。

Swarm 在宿主用户的 `HKCU\Software\JiuwenSwarm\SandboxRuntimePins\<venv路径哈希>` 保存基础解释器和 venv 目录身份。注册表键使用禁止继承的 DACL，仅宿主账号、SYSTEM 和 Administrators 可访问，记录不位于沙箱可写目录。创建 venv 后、执行其 Python/pip 前验证并保存记录；后续启动及进程内复用均重新比对可写配置。已有 venv 缺少记录时，必须先与宿主独立选出的基础解释器匹配，不能直接根据旧 `pyvenv.cfg` 建立信任。宿主可信，显式 `JIUWENCLAW_BASE_PYTHON` 优先于已有记录；选择新解释器或原解释器已删除时重新准备 venv，验证后替换钉扎。宿主删除或重建 venv 后，只要实际基础解释器与宿主独立选择一致，也可更新记录，无需手工清理注册表。正常重启保持已有有效记录，工具 Python 可以与 runner Python 不同；无法匹配宿主选择的元数据变化仍拒绝启动。

普通 venv 供给失败时不声明不可用的 venv，但仍注入宿主选出的基础 Python 目录和解释器；信任校验失败继续中止。Linux 已有 venv 基础解释器解析失败时尝试后续宿主候选，`home` 目录仅有 `python3` 也支持；Linux 不执行上述 Windows ACL 自动声明。

源码启动时，Swarm 还在初始化前通过 `JIUWENBOX_SERVICE_READ_ROOTS` 声明已定位的 `jiuwenbox/src`，使 `jbx-sandbox` 可导入 runner；只设置 `PYTHONPATH` 不能授予磁盘访问权限。它独立于显式 `JIUWENBOX_TOOL_PATHS`，不改变用户选择的工具解释器，也不把任意 `PYTHONPATH` 项、技能目录、整个仓库或 agent workspace 自动授权。冻结包不声明源码根，独立 JiuwenBox 仅解析宿主声明，不推断产品目录。

只有声明的源码根使用服务共享只读 ACL。技能目录保持既有会话读写、授权和撤权行为，不自动设为只读；本次源码导入修复不解决技能依赖的重复扫描耗时。配置的拒绝仍优先，普通用户工作目录保持会话 ACL 行为。

旧源码启动可能在 `__pycache__` 中留下沙箱账号所有、宿主无权修改 DACL 的 `.pyc`。迁移属于 JiuwenBox：每个声明的只读根在首次准备或缓存失效时，共用原有 ACL 遍历；仅当某个对象修改 ACL 返回拒绝访问，才检查它是否属于当前沙箱账号、文件名符合 CPython 缓存格式且有树内对应 `.py`。满足条件才删除派生缓存，不跟随重解析点，不删除源文件或宿主缓存，不接管所有权。逻辑不依赖 JiuwenBox 源码布局，独立组件和第三方宿主同样生效；暖缓存命中时不另行遍历。目录、日志、构建产物、孤儿 SID 等不在自动迁移范围内；显式读拒绝不触发迁移，任何仍存在的必需对象 ACL 失败继续中止初始化并记录路径。

Windows 启动器为沙箱首跳 runner 和受控子进程设置 `PYTHONPYCACHEPREFIX=<沙箱临时目录>/python-cache`。这里的 runner 是以沙箱账号运行的 `jiuwenbox.supervisor.win_exec`：`ProcessRuntime._create_windows` 在调用 `two_hop_spawn_and_authorize` 前设置其环境；`win_exec._create_process_as_user` 再为第二跳命令设置环境。Swarm 的 `JiuwenBoxRunner.ensure_running` 启动的是宿主 box-server，不是这个沙箱首跳，不为它套用沙箱缓存前缀。默认使用沙箱 profile 的 Temp，第二跳无法获取 profile 时沿用 workspace/.tmp 回退。宿主缓存前缀不会通过环境白名单进入命令；请求里的缓存前缀也由启动器重新生成。Python 默认在独立目录保留字节码收益，不向声明源码树生成新缓存。显式 Python 启动参数或程序内部清空环境不属于该默认注入的保证范围，源码只读 ACL 仍保持。

两套只读根取并集：先工具 `read_roots`，再服务根，规范化后去重；`executable_dirs` 始终仅来自工具声明，服务根不加入命令 PATH。显式公共可写根/受管 venv 继续按原语义处理，其包含的子根不再重复准备；共享默认授权不覆盖策略拒绝。Swarm 只自动声明已定位的源码根，不将技能目录或任意 `PYTHONPATH` 项加入该并集。

这层适配位于 Swarm，不需要桌面端生成产品目录权限。它不读取模型命令的 env/PATH，也不推导整个 runtime 或用户数据目录的读写权限。更新 Swarm 后重启托管沙箱服务生效；外部服务由启动方提供声明。共享 ACL 仍由组件准备、缓存并排除于会话撤权，原策略的显式拒绝优先。`CreateProcessAsUserW` 返回 `WinError 5` 且程序存在但不可读时，应检查声明与 ACL；任务目录祖先的显式拒绝仍是独立问题。

各 JSON 环境接口在未设置、空字符串或仅含空白时使用表内默认值。非空的非法 JSON、错误类型和非法路径仍拒绝，不以空配置吞掉错误。工具变量的实际值为空字符串时仍按白名单原样传递，与声明本身为空是两种情况。

## 旧宿主迁移

旧版本内置的产品工具变量名已移除，宿主必须将实际需要的名称写入 `sandbox.env_allowlist`，并提供相应环境值；已经显式保存的用户列表继续在模板升级时保留。空白名单仍是合法配置，不额外放行任何凭据。

当 `sandbox.enabled=true` 且白名单为空时，内部 runner 在每次实际启动服务前输出警告，明确说明没有额外工具变量继承，并提示 `sandbox.env_allowlist` 和 `JIUWENBOX_TOOL_PATHS` 接口。复用同一服务不重复警告；禁用沙箱时不输出该迁移警告。日志不打印变量值。

本仓负责声明的解析、透传和执行，不为特定产品发现目录。可信宿主可通过服务环境或内部 `ensure_running(extra_env=...)` 接口显式注入 `JIUWENBOX_TOOL_PATHS`；未声明时，Windows 内部 runner 生成上述常见运行时的兼容声明。普通工具命令的 env 不能提供授权。外部服务由它的启动方自行配置。

## 启动与配置更新

1. 宿主合并用户 YAML 的两个列表，并在启动 AgentServer 前设置工具声明和所需变量值。只保存变量名，避免凭据落盘；普通命令请求不能修改宿主声明。
2. JiuwenSwarm 内部启动模式解析 YAML，将两个列表分别编码为 `JIUWENBOX_PATH_ALLOWLIST` / `JIUWENBOX_ENV_ALLOWLIST`；可信服务环境中的 `JIUWENBOX_TOOL_PATHS` 继续传给组件，未声明时 Windows runner 尝试生成常见运行时的工具声明。
3. Windows `--ensure` 在 box-server 拉起前准备公共目录 ACL；服务 lifespan 再校验，然后接受会话。直接启动组件时由 lifespan 准备。
4. 创建和停止会话时跳过服务公共根，包括从祖先目录递归授权或撤权的情况。

两个 YAML 列表在配置模板升级时原样保留，包括显式 `[]`。已加载列表变化会使内部 runner 放弃复用旧服务；更新配置后应按部署方式重新加载配置并重启沙箱服务。工具声明或变量值变化时重启 AgentServer，让子进程收到新环境。

Windows lifespan 必须先成功加载根策略，再准备环境或修改 ACL。根策略缺失或无效时直接保留原始异常退出，不再继续使用默认安装参数并在后续掩盖为未定义变量错误。

外部启动模式仅检查现有 box-server 健康状态，**不会**向外部服务下发 YAML 或进程环境。外部服务的启动方需要自行设置所需的 `JIUWENBOX_*` 接口。独立 JiuwenBox 不读取 JiuwenSwarm YAML。

## 权限与缓存边界

- Windows 首次或缓存失效时修复已有对象 ACL，新对象继承公共根权限。`shared-tools-acl.json` 位于 `JIUWENBOX_HOME`，只有准备成功才更新。
- 缓存检查账号 SID、策略、目录身份、运行时关键元数据和根 DACL。条件未变化时不扫描公共目录树；变化时重做失效根。缓存不监控每个子文件的任意外部 ACL 改写。
- Swarm 的自动声明不改变上述组件缓存：普通文件新增可能使目录元数据变化而触发重扫；嵌套文件被外部安装器替换并关闭继承时，现有指纹可能漏检。运行时升级后的定向修复和更精确的缓存失效需要组件另行支持，不能据此承诺任意安装器升级都能自动修复。
- 移除配置根时回收旧公共授权，并保护仍声明的嵌套根。自动根授权不覆盖原策略有效拒绝；只读父根先于可写子根处理。
- 通用 `JIUWENBOX_BUNDLED_PYTHON` / `JIUWENBOX_VENV_DIR` 保留原运行时语义；后者是显式可写根。本能力不重定向技能解释器，不创建额外 venv 或 `.pth`。
- Linux 公共路径转换为 `filesystem_policy.read_write` 和同路径 rw bind，保留既有显式挂载和只读规则。工具 PATH 声明的新增接线针对 Windows。
- 命令请求 env 不是 ACL 声明入口。Windows 执行环境大小写无关地剥离 `JIUWENBOX_SERVICE_READ_ROOTS`、`JIUWENBOX_TOOL_PATHS`、`JIUWENBOX_PATH_ALLOWLIST` 和 `JIUWENBOX_ENV_ALLOWLIST`；即使宿主继承白名单或 `JIUWENBOX_INJECT_ENV` 提供这些键，也不转发给最终命令。服务自身的声明保持不变。其他执行协议键及宿主软删除注入沿用既有行为，不做全部 `JIUWENBOX_*` 键的一刀切过滤。环境白名单也不等于路径授权：凭据、文件权限、服务端命名管道 ACL 各自管理。
- 此缓存仅处理声明的公共根。普通工作空间的全量 ACL 扫描仍存在；不要把任意大工程配置为公共可写根来替代会话隔离。
- 首次新增运行时/源码声明仍有一次 ACL 修复开销；不要把隔离测试中的暖启动时间视为整个客户端或对话的端到端耗时。

## ACL 失败诊断与宿主修复

Windows 逐对象 ACL 加固失败时，日志记录 `root`（正在准备的根）、`path`（失败对象）、`operation`（`read_dacl` / `build_dacl` / `write_dacl` 等阶段）、`owner_sid`、`winerror`、`migration` 和 `required`。必需目录枚举、共享根元数据检查和根 DACL 保护失败也使用同样的诊断，分别标识 `list_directory`、`stat_runtime_metadata`、`read_root_dacl` 或 `protect_root_dacl` 等阶段。属主读取仅在失败时执行，不解析账号名称；无法读取时记录 `owner_sid=unknown` 和 `owner_error`，仍保留原来的 ACL 异常。`required=True` 的失败继续中止初始化，`required=False` 沿用原有 Allow-only 告警处理。

主错误的 `object_type` 区分 `directory`、`file`、`reparse_point` 和 `unknown`；即使目录叫 `__pycache__` 且为空，也不会自动删除。`migration=not_configured` 表示当前调用未配置迁移，`not_attempted` 表示未满足只读根且拒绝访问的触发条件；`blocked_by_read_deny` 表示策略读拒绝阻止迁移；`failed_or_ineligible` 需结合相同 `root/path` 的缓存迁移日志判断：`eligible=false reason=directory_not_cache` 表示阻塞对象是目录，`not_backed_cpython_cache` 表示不属于可安全删除的缓存，`owner_mismatch` 表示非当前沙箱账号所有。这些候选排除细节使用 DEBUG 级别，不重复输出 warning；必需对象失败的主错误仍使用 ERROR。`eligible=unknown` 表示检查未完成，`eligible=true reason=delete_failed` 表示满足缓存条件但删除仍被拒绝，两者继续告警。目录、Node/Git 产物和孤儿 SID 不会因此被自动删除或接管所有权。

遇到无法自动处理的必需对象时：

1. 停止对应服务和沙箱，按日志核对声明根、失败路径和策略。不要通过扩大到用户主目录、取消必要拒绝或跳过对象来绕过错误。
2. 由宿主管理者检查该对象的所有者和 DACL。需要保留的项目文件先备份；运行时安装文件优先通过宿主安装器重新安装或重建到范围明确的目录。
3. 确需人工 ACL 修复时，只处理确认的对象/运行时根，并保留原策略和宿主权限；本组件不自动提权、不执行通用接管或递归重置。完成后使用相同配置重新初始化验证。

共享根正常准备日志包含 `cache=miss elapsed=...`，缓存命中包含 `cache=hit elapsed=...`，后者只统计固定元数据检查，不额外遍历。结合已有 `[ACL] tree ... elapsed=...` 和会话初始化日志定位慢点；这些时间不是整个客户端或新对话的端到端耗时，本次不改变缓存失效规则或目录剪枝。

## 独立验收

无需桌面客户端即可运行 `tests/unit/test_shared_paths_config.py`、`tests/unit/test_shared_tool_paths.py` 与 `tests/integration/test_shared_tool_acl_lifecycle.py`，验证空配置、通用声明、请求隔离、策略拒绝及缓存生命周期。

`tests/unit/test_bytecode_migration.py` 不依赖沙箱账号，覆盖缓存命名、源文件背书、当前/宿主/孤儿 SID、链接拒绝及缓存重定向；`tests/integration/test_shared_bytecode_migration.py` 使用真实 Windows 沙箱账号，覆盖多个独立声明根、仅失败对象迁移、暖缓存无遍历，以及日志对象和显式读拒绝仍中止初始化。

`tests/unit/test_win_acl_bounded.py` 和 `tests/unit/test_shared_acl_diagnostics.py` 覆盖跨运行时路径的失败阶段/属主诊断、属主查询失败保留原异常、正常路径不查询属主，以及初始化失败不写成功缓存。

Swarm 启动适配回归为 `tests/unit_tests/agentserver/test_sandbox_runtime_tools.py`、`test_python_base_pin.py`、`test_jiuwenbox_git_tools.py` 和 `test_jiuwenbox_runner_env.py`，覆盖受管 venv 配置篡改、首次钉扎的宿主匹配、缓存复用时重查、注册表保护 DACL 与真实沙箱账号拒写、可选解析失败隔离、跨解释器的裸 Python 解析、Node/Git 标准布局、显式声明优先和配置重载。NTFS 生命周期测试包含已有 Bash/DLL（含受保护 DACL）取得 RX、相邻用户数据不变和显式拒绝保留。

真实 Windows 账号测试为 `tests/integration/test_shared_tool_runtime.py`，按模块说明显式设置测试工具路径后启用；测试通过普通 pip 安装本地 wheel，再由新进程直接 import，且校验只读工具和会话撤权边界。该测试需要已安装沙箱账号、宿主提供的可写 venv 和预装依赖，不是云服务端到端验收。Linux 内核行为需另行部署验收。
