# config.set 特性设计

## 1. 范围、状态与依据

`config.set` 是原生配置保存前的扩展点，用户可改候选值或显式拒绝；CORE 执行受控原保存 continuation。
不新增 `ops.config.set`，不把已有同名 RPC 当成 EventBus 事件本身。主责规约：[S_21](../specs/jiuwenswarm/extensions_v2/S_21_config-extensions.md)。
沿用固定 Claude config.set 的 key/value/previous/provider/origin 及 value-or-deny 分工，增加写入 scope。

## 2. 能力说明与 Claude 对照

例如插件禁止在生产工作台开启 RSI：订阅 key=rsi.enabled，在 value 为 True 时返回 deny，
则本次配置请求不落盘、不热更新；放行时 next 进入默认 CORE，复用原文件保存和运行配置更新。
首期只对公开目录内的已有写入口触发，不支持任意 YAML 路径或插件自建配置字段注册。
Claude 单行语义映射到本项目行事件；本项目原生批量请求还需要共享一次提交的汇合规则。

## 3. 事件契约

### 触发点与完整调用链

```text
用户通过原设置入口 / 既有 E2A 配置请求提交
 → ConfigAdapter.handle：识别 config.set、config.save_all 或 locale.set_conf
 → 从当前宿主读 previous，规范化原面板 true/false；有会话时绑定 SessionContext，全局入口为 None
 → 为本次公开字段创建私有调用帧，bus.trigger(Event("config.set", input), context)
 → USER 改 value / 返回 deny → 可选 BUILTIN → config_set_core
 → 核对固定事实和字段合法值，进入原生保存 continuation
 → 所有相关字段到达 CORE 后，只调用一次原 ConfigAdapter._handle_native
 → 原 config_set_handler / config_save_all_handler / 语言 writer 保存、原热更新
 → 实际回执逐层返回，原 AgentResponse 的 payload/metadata 保留
```

批量请求中，各字段在继承相同宿主 ContextVars 的独立事件任务里处理。这样同一个 USER Handler
可以检查每一项，不会因 Core 的“活动 Handler 防重入”而漏过后续字段。字段顺序不作为公共保证；
插件共享可变资源需自己同步。任一项在 CORE 前拒绝或伪造成功，整批不进入原保存。
取消会取消并等待所属字段任务。该门闩只保证扩展策略的前置拒绝，不为原多文件保存新增事务回滚。

### 输入字段

| 字段 | 类型 / 谁填写 | 代表什么、填写例子与作用 | 可否改写 |
| --- | --- | --- | --- |
| `key` | `str`；平台 | 稳定标识，如 `rsi.enabled`；原面板 rsi_enabled 已由平台映射 | 固定 |
| `value` | `bool` / `str`；平台候选 | 新值，例如 True 或 `" EN "`；面板布尔字符串进入事件前已规范化为 bool | 唯一可改业务值；必须保持类型，并通过最终选项校验 |
| `previous` | 与字段值同类型；平台 | 触发前有效值快照，例如 False；不是客户端自报旧值，也不是 CAS 版本 | 固定 |
| `provider` | `{plugin,tier}`；平台 | 字段归属，首批 engine/core；与发起者不同 | 固定 |
| `origin` | `{kind:"bridge"}`；平台 | 当前 E2A Web/TUI/协议保存入口，用户不能通过 params 自报 composer/plugin | 固定 |
| `scope` | `"user"`；平台 | 保存到当前宿主配置层；effective 只是读取视图，不能作为写入层 | 固定 |

### 输出与提交事实

| 输出字段 | 类型 / 何时使用 | 含义与如何消费 |
| --- | --- | --- |
| `value` | `bool` / `str`；CORE 保存成功后返回 | 这项实际交给成功原保存的新值，如 `{value:True}`；不能与 deny 同时出现 |
| `deny` | 非空 `str`，最多 512 字符 | 在继续 CORE 前明确拒绝，如 `{deny:"生产环境禁止开启"}`，没有本次写入 |

USER 未调用 CORE 就返回 value，不算保存成功，平台拒绝。CORE 已完成原保存后，USER 再返回 deny、
伪造 value 或抛异常，不能改变已保存事实：平台保留私有真实 AgentResponse，不声称回滚。
不要用抛异常表示拒绝，Core 的既有 USER 故障隔离可能继续默认处理；明确拒绝必须返回 deny。
原 writer 返回失败时沿用原错误响应，不能由 Hook 假装成功。

```python
def register(self, registrar):
    registrar.register_event_handler("config.set", self.before_save, {"key": "rsi.enabled"})

async def before_save(self, event, ops, next_handler):
    if event.event_input["value"] is True:
        return {"deny": "当前环境禁止开启 RSI"}
    return await next_handler(event)
```

若要规范化语言，在 preferred_language 的 Handler 内用 `Event(event.event_type,
{**event.event_input, "value": event.event_input["value"].strip().lower()})` 继续。
输入不是要改写的原生请求 params，不能把 key 换成另一 YAML 路径。

## 4. 方法契约

本次没有配置写 Ops。用户仍从既有设置保存入口提交，由平台适配触发事件。
读取旧值可使用 [value](F_20261127_1041_ops-config-value.md) / [snapshot](F_20261127_1041_ops-config-snapshot.md)，但 event.previous 已提供本次受信快照。
三个读取 Ops 不会自行触发 config.set。

## 5. 接入与兼容方案

| 稳定配置 key | 返回类型 / 缺省值 | 原生写入口与参数 | 含义与边界 |
| --- | --- | --- | --- |
| `preferred_language` | `str`，`"zh"` | `locale.set_conf`，`preferred_language` | 宿主语言，`zh` 中文、`en` 英文；企业版语言归 Gateway/用户偏好服务，不发布为宿主 YAML 项 |
| `react.context_engine_config.enabled` | `bool`，`False` | `config.set` / `config.save_all` 的 `context_engine_enabled` | 原上下文引擎开关，非本扩展自动执行压缩 |
| `rsi.enabled` | `bool`，`False` | 同上，`rsi_enabled` | 原 RSI 入口开关 |
| `rea.enabled` | `bool`，`False` | 同上，`rea_enabled` | 原 REA 入口开关 |

字段由 `config_extension/catalog.py` 显式发布。未登记字段，包括模型密钥、令牌、任意 YAML 路径，
不因名称看起来普通就自动开放。首批不包含通用插件 `userConfig` 字段注册，也不新增项目/会话配置存储。


语言走已有 locale.set_conf；不把原本不支持的 preferred_language 配置面板别名偷偷变成新 RPC。
ConfigAdapter 只加薄包装，原 _handle_native 保留检验、权限、多模态限制、热更新、响应契约。
扩展宿主不可用时沿原路径；没有 USER 时默认 CORE 放行。未公开字段和其它独立配置业务保持原路径，
本事件不是所有同步配置文件写入的全局拦截。Gateway/Front、Core、前端和依赖锁均不修改。
私有帧归本次任务所有，保护会话、来源、字段归属与存储 continuation，直接手工 trigger 不能借 CORE 写盘。

## 6. 验收与未决问题

定向验收入口：`tests/unit_tests/extensions_v2/test_config_extensions.py`。
测试通过真实 assembly/Registry 安装 USER 包，使用隔离的真实 YAML 文件，调用公开 Ops、原生命令和
`ConfigAdapter.handle()`；写后独立用 YAML 解析器读取文件，并检查原热更新回调次数。
并发批量、取消、伪造结果、隐藏与只读投影、无会话读取和卸载均有覆盖。
最终实际命令、数量与结果见本文末尾“验证记录”；未记录为通过的场景不能据此声称已验收。
本次不涉及模型调用、浏览器绘制或完整 Gateway/Worker OS 进程验收。


| 场景 | 验证点 |
| --- | --- |
| 默认放行 / 改候选 | 原 writer 写入最终值，独立读 YAML；热更新回调一次 |
| 显式拒绝 | 字节级比较配置文件不变，回调未执行 |
| 批量通用策略 | 同一无 matcher Handler 检查每一项，第二项拒绝时第一项也未写入 |
| 原响应与实际回执 | post-next 拒绝/改值不能伪造回滚；原成功 payload/metadata 保留 |
| 假成功 / 重复 next | 不经 CORE 不写；重复 next 不重复提交 |
| 非法字段 / 取消 | 不能换写入目标；提交前取消不留字段任务或写入 |
| 卸载 | 移除 USER 后原保存恢复默认放行 |
