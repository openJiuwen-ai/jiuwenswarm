# Hub 应用分发与本地安装实施

## 关联依据

- 设计：`D:\lsq\jiuwen设计\app-hub方案设计.md`、`app-hub实施方案.md`（外部交接文档，未进入 designs 索引）。
- spec：[S_03_app-hub-distribution](../../specs/jiuwenswarm/extensions/app_market/S_03_app-hub-distribution.md)。
- 日期：2026-11-19。
- 实际实施范围：Swarm 侧 Hub `app` 类型接入、下载/解压/安装事务、`install.json`、运行授权、项目绑定与编辑、更新/卸载、市场 RPC 与面板入口。Hub 侧同分支 `feat/app-hub` 完成类型注册、校验、发布、下载与前端/CLI 接入，细节见 Hub 仓 CHANGELOG 与设计文档。

## 决策归属与关系

本期为新增能力，无既有实施记录可续写。原方案中的未决项按实施方案默认值落地：同一资产同一所有者一份安装、首次运行授权、原地更新保留数据与 Git、同机 Web/Electron 验收范围。部署策略（共享远程部署是否允许启动 Hub 包）未在本期实现，保留为部署侧配置项。

## 上下文与跨边界影响

- 产生方：Hub 发布 `app` 资产，返回版本详情与 artifact（原包、SHA-256、`file_size`）。
- 载体：Swarm `HubClient`/`HubPackageDownloader`；安装后目录、`app_market` 清单与 `install.json`。
- 权威状态：包身份以 Hub artifact 为准；本地注册以 `manifest.json` 为准，安装来源以 `install.json` 为准，运行授权以 `run_consents.json` 为准。
- 消费者：`SkillAdapter`/`MarketService` 生成启停脚本；Web 面板、编辑会话与运行期应用。
- 失败与终态：提交前失败清理 staging；注册或凭据失败删除目标目录；更新失败回滚旧目录；启动恢复按操作日志与安装记录处理半安装。

## 实际实现与开发决策

- Hub 类型：`HubAssetKind` 增加 `app`；类型适配器固定 `app ↔ app`；`HubAssetQuery.version` 允许固定版本；详情透传应用能力字段。
- 下载：`HubPackageDownloader` 支持每实例限制与可选 CRC 校验；app 使用 600 MiB 下载、512 MiB 解包、64 MiB 单文件，下载前后校验 SHA-256。
- 安装：新增 `extensions/app_market/hub_install.py`，复用 `install_hub_asset_package` 的 staging/原子提交，新增包根定位器定位 `<outer>/<name>/index.html`，注册复用 `MarketService.publish_app`，`install.json` 紧随清单写入。安装/更新在 `<数据根>/app_market/install_ops/` 写操作日志，检视修复后，启动恢复按事务发布标记校验目录归属，按版本和摘要决定提交或回滚，失败时保留事务记录。
- 生命周期：`app_market.list` 返回 `work_dir_missing`；前端对缺失目录禁用启动/编辑并提供“重新安装”；删除 Hub 应用时单独询问是否清理程序文件。
- 授权：新增 `RunConsentStore`，按 `owner+app+artifact_sha256` 持久化；首次启动缺授权时抛 `RunConsentRequired`，经 WS `app_run_consent_required` 返回摘要，客户端确认后重试。
- 项目：清单新增来源/绑定字段；启动注入 `WORKSWARM_APP_PROJECT_ID/PROJECT_DIR/WORK_MODE`；编辑项目解析改为“已有绑定 → 来源会话 → 应用目录创建/复用”，并恢复隐藏项目。
- 编辑 Git：先探测项目 Git；未初始化时写最小 `.gitignore` 并调用 `project.git.init`（`main`），失败不阻塞编辑；不自动提交。
- 更新/卸载：更新在 staging 完成后停止实例并原子切换，复制 `data/`、`.git`，续用项目字段并完整备份旧工作树。更新、启动、编辑入口和卸载按应用互斥。卸载默认保留文件，显式清理以发布标记确认目录归属。
- 前端：市场页签新增“市场”，支持详情确认、安装目录输入、阶段轮询（解析/下载/校验/解压/注册）、取消、更新按钮、首次运行授权确认与缺失目录重装；编辑入口提示 Git 版本管理建议。
- 本地发布：本地应用卡片复用已有发布抽屉、OAuth 和 Hub 上传接口。后端按注册清单确认所有者、构建 Hub app 包，并继承应用权限。打包排除本地运行数据和市场生成文件，发布人确认文件清单后提交。旧 HTML 入口在快照内适配为 `index.html`，应用声明的版本与发布版本须对齐。

- 应用二次开发通过原地转换解除 Hub 安装关联，在同一目录沿用现有本地编辑与发布流程。本地登记时提前校验显式版本与入口声明。Hub 续发、覆盖及公开版本选择沿用其他资产的共同逻辑。

## 与设计的偏差

- 目录选择使用 `window.prompt` 输入服务端路径，未接入桌面目录选择器；本地单用户下路径即本机路径，与设计“目录选择作用于运行 Gateway 的机器”一致。
- `data_dir` 与环境变量 `WORKSWARM_APP_DATA_DIR` 未实现；按约定应用自行使用 `work_dir/data/`，更新时保留。
- Hub 侧内容扫描只覆盖 `scripts/` 有界前缀，未对大前端 bundle 做硬阻断；与设计一致，但扫描预算为固定 64 KiB。

## 验证结论

- 已证明范围：Hub `app` 包在 Swarm 侧可解析、下载、校验、安装、注册、更新与卸载；首次运行授权与项目字段生效；本地真实 Hub + S3 模拟 + Swarm 服务的安装/启动/页面/更新链路通过；既有本地应用与既有 Hub 资产调用未回归。
- 未覆盖或未通过的承诺：真实 OBS/Nginx 部署、Electron 与前端点击交互、跨盘复制与磁盘不足、大包资源峰值未在本机验证。
- 可支持的交付判断：本地单用户场景的安装、启动前授权、编辑项目绑定、更新、卸载与崩溃恢复已具备实现与定向测试；上线前仍需在真实环境完成网络、进程与容量验收。
