# Multica 本地 ACP 运行时接入

Multica 的自定义 Profile 使用 `kimi` 协议族和本机启动器绝对路径。daemon 探测版本后，以 `acp` 子命令启动适配脚本。脚本将其余参数原样传给当前 checkout 的 `jiuwenswarm-acp`，由它连接已经运行的 Gateway。ACP 和模型配置沿用现有入口。

2026-11-20 在 macOS 验证了启动器版本探测、ACP 初始化、建会话和流式文本回复。两组现有 ACP 测试共 9 项通过。Multica daemon 0.11.1 注册 JiuwenSwarm 0.2.9b5 为在线运行时，冒烟事项 DEV-4 的运行进入 completed，事项收到了 `JIUWEN_ACP_OK`。

首版支持 Linux 和 macOS 启动脚本，在 macOS 上完成实际验证。首版 JiuwenSwarm ACP 声明 `loadSession: false`，跨运行恢复、MCP 配置转发和 Windows 启动未纳入首版验收。此后原生 provider 在 AgentServer 支持持久会话时声明 `loadSession: true`，MCP 配置转发见下节；Windows 启动仍未验证。

## DEV-10 原生 ACP 思考档位与远程 MCP

ACP 桥接进程在新建或加载会话时连接 HTTP、SSE 和 stdio MCP，沿用同一套工具声明、反向调用和会话关闭逻辑。远程请求头由桥接进程直接发送，Gateway 接收工具声明和调用结果。

AgentServer 用当前模型的 core 能力生成 `configOptions`。桥接进程验证并保存客户端所选档位，AgentServer 为该轮构建独立模型配置。选择默认值时沿用原模型配置。切换模型或重新连接后根据当前模型重新协商档位。

macOS 本地 Multica 开发 daemon 的 DEV-15 验收运行使用 DeepSeek V4 Pro 调用了 Streamable HTTP 工具，工具返回标记出现在运行结果中。隔离 AgentServer 与 Gateway 验证了 `max` 和 `off` 到模型 HTTP 请求的映射。自动化测试覆盖选项协商、设置与重置、远程传输和请求头。Multica 界面点选需在主 AgentServer 加载新版代码后验证。
