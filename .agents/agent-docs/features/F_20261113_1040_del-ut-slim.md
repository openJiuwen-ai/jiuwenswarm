# develop 测试库瘦身第一批实施归档

## 关联依据

- 设计：无独立 D（design_note 见 frontmatter）。本批为全量扫描结论中"高置信直接删除"子集，批次划分与执行边界由用户确认。
- spec：不涉及（纯测试删除，未触碰生产契约）。
- 日期：2026-11-13。
- 实际实施范围：`fix/del-ut` 分支（基于 develop@e1e731742）删除 78 个测试文件（约 20,300 行）与 11 个文件内的死代码区间（619 行），同步修订 TESTING.md 目录表。批次 2（gateway 同名分叉 25 文件/场景对照 25 文件）、批次 3（参数化/文件合并）、批次 4（重复 helper 提取）、批次 5（结构归位）均未在本批实施。

## 决策归属与关系

新决定，无旧记录可续写。上游 agent-gateway 仓（pyproject 钉于 `@54e5330d`）的测试归属权由其自身 CI 承担；本仓删除其逐字节镜像测试后，pin rev 的回归守护依赖上游门禁与发版流程 re-pin 检查。

## 实际实现与开发决策

- **71 个上游逐字节镜像测试删除**：对全库 263 个 import `agent_gateway` 的测试文件做 AST 分类——122 个文件为"零 jiuwenswarm import 的纯 gateway SUT"（38,321 行）；其中 72 个与上游仓文件 md5 逐字节相同，属 mirror 同步残留。删除这批不损失任何上游未拥有的覆盖。141 个"monkeypatch gateway 测 jiuwenswarm 行为"的集成契约文件全部保留。
- **why-not（test_cron_etcd_store.py 留下）**：72 个镜像中有 1 个（`tests/unit_tests/gateway/test_cron_etcd_store.py`，10 个用例）被存活的分叉文件 `test_cron_scheduler.py` import（`FakeEtcdJsonClient`），随其消费者推迟到批次 2 一并处置，避免制造新的收集错误。
- **7 个死文件删除**：`agentserver/memory/` 4 个"镜像测试"（文件内自带旧版实现，真实实现已迁至 openjiuwen core 仓或 `agents/harness/common/memory/config.py`，测试永不失败、零回归保护）、`test_skill_manager_rebuild_followup.py`（被 files_rebuild.py 超集覆盖）、`test_envelope_placeholder.py`（被 tool_context_repair.py 超集覆盖）、`integration/test_acp_cli_stdio_integration.py`（与 system_tests 侧逐行等价）。
- **11 个文件的区间删除**：2 处同名重复定义（pytest 只收集后定义者，前份死代码：test_config.py、test_runtime_service.py）、1 处被遮蔽死 helper（test_mcp_dynamic_token_patch.py `_make_provider`）、1 处被测场景已随 A2g 删除的永久 skip 用例、1 处跨文件复制的 owner-stop 用例（保留 write_options 原版）、5 处 11-05 大 merge 复活的死副本（team_model_selection、runtime_worker_phase2、team_helpers、skill_sync、system_tests/project_memory）、test_chat.py 内 6 个与模块文件（test_events/test_render/test_gateway_client）逐行重复且已滞后的陈旧副本类（45 个用例每次全量跑执行两遍）。
- **TESTING.md**：目录表同步真实文件数（unit_tests 约 1180、unit 7、integration 8），移除已删除的 `tests/auth/` 条目。

## 与设计的偏差

无独立设计。执行中两处修正：(1) `test_cron_etcd_store.py` 因交叉引用退出本批（见上）；(2) test_chat.py 删除 6 个类后首次裁剪 import 时误删仍在使用的 `import json`（grep 用量统计漏报），定向 UT 出现 10 个 TestInteractiveLoop NameError 失败，随即以 python 精确计数恢复该 import（`import io` 确认 0 使用、不恢复），修复后 test_chat.py 61 用例全绿。

### 可见行为、副作用与证据有效范围

- 收集数对账（958 = 899 + 59）为最硬证据：删除未引起任何未解释的收集损失；同一批命令下 6 个环境性错误文件名前后完全一致。
- 未运行被删测试（已不存在）；11 个涉改文件的定向套件与基线逐用例对比通过。
- Windows 下的 conftest teardown 偶发 `WinError 32`（日志句柄占用）为基线即有的环境噪音，不影响结果判定。
- 若 venv 升级 agent_gateway 至 develop 期望版本后，6 个收集错误应消失；该重验属环境维护，不属本批范围。

## 验证结论

- 已证明范围：78 文件删除与 11 文件区间删除零覆盖损失——收集差值精确闭合、无新增收集错误、11 文件定向 UT 与基线逐用例一致（除被删项）。
- 未覆盖或未通过的承诺：全量 pytest 执行未跑（遵循只跑相关 UT 约束）；批次 2-5 未实施。
- 可支持的交付判断：本批可独立交付；后续 re-pin agent_gateway 时上游 CI 承担镜像层回归守护。
