# Computer Use 设置修正移植到 develop

## 元信息

| 项 | 值 |
| --- | --- |
| 日期 | 2026-10-26 |
| 范围 | 电脑操控设置、分组顺序回归与安装包资源合并 |

## 现象与根因

#8885 已同步新增电脑操控分组的顺序断言，develop 上对应断言仍缺少该项。
两分支的实验分组不同，不能将 0.2.8 的完整列表复制到 develop。
Windows 可用性评审建议仅凭原生文件返回可用，但安装包中的原单步工具仍由
Core 的 WindowsBackend / PyAutoGuiBackend 执行，初始化依赖 PyAutoGUI，
截图依赖 Pillow；原生驱动用于 cua_repl，不能替代这条路径的依赖。

## 决策

- 移植 #8885 的修正并保留原 commit 信息，按 develop 的现有分组补入末尾的 computer-control。
- 保留依赖检查，仅补充机制说明；不改变输入、权限或运行时生命周期。
- 以 develop 的配置字段和包元数据为准解决相邻冲突，同时保留 CUA 包资源。
- 公共配置重载方法、根依赖声明及锁文件与目标分支一致。

## 拒绝的方案

不整体合入 0.2.8 分支，以免引入发布分支特有改动；不添加其 tool-optimize 分组；
不通过删除 Windows 必需依赖检查规避评审，也不恢复上游已删除的旧轨迹开关。

## 验证与限制

Python 3.11，Core 0ab5913b、Protocol 10a03dd2：173 项后端及打包相关检查通过。
多模型协作设置 24 项通过；前端构建通过；设置回归 62 项通过，
另外两项失败已在 develop 的 6e5e933f7 基线上独立复现。
Windows 依赖缺失采用受控模拟验证，未执行真实 Windows 桌面操作或重建完整安装包。
本次核对范围为移植修正和合并冲突，不代表对 #8873 全部既有代码重新完成检视。
