日志显示同一批任务连续播报排队承诺，停止结果也重复确认。仅凭日志不能将每次重复都归因于状态切换。原提示词要求自然确认，但没有要求与之前已播报事实比较。

在会话、操作回执、取消确认与最终结果提示中共用状态播报规则。区分已接收、排队、执行、等待回答、正在停止与已停止；答案提交不等于生效或恢复。只有实际回执才能证明状态变化；没有新事实时不重复承诺。用户主动查询仍须刷新真实状态。

验证：test:qwen-barge-in 回归通过。该修改是模型指令，不是确定性去重；尚未验证真实 Qwen 音频播报。没有改变通知投递和工具执行。


## 后续决策：成功后台流程静默

按用户进一步要求，成功接收、普通操作、答案提交、停止确认及成功任务结果仅更新上下文，不触发额外 response.create。保留用户语音响应、主动查询结果、失败/拒绝/不完整回执和需要用户输入的卡片提醒。工具回执照常回传；排队与连接互斥沿用现有调度，不提前写入未就绪连接。

队列管理的引导查询不单独触发播报：有写操作时按写操作结果判断异常；纯查询仍回答用户。该决策替代此前“成功状态变化可主动播报”的提示建议。成功结果仍在页面可见且进入模型上下文。

验证：test:qwen-barge-in 共 145 项通过。成功静默、异常生成、用户查询、队列引导查询和重复取消均有协议发送断言；原响应互斥回归改用仍需要回应的查询或失败回执。未进行真实 Qwen 音频实测。
