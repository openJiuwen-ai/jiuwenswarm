# Worker 退出确认超时后恢复自动重试

关联 [Issue #6709](https://gitcode.com/openJiuwen/jiuwenswarm/issues/6709)。本记录仅覆盖退出观察超时导致的恢复断链。

## 现象与影响

不健康 Worker 退休时，即使已经发送终止信号，操作系统也可能在本次观察预算内尚未报告退出。
原实现抛出普通 RuntimeError，在监督循环内设置 FAILED 后直接退出，没有安排自动恢复。
旧进程稍后退出或资源恢复，也不会触发新 Worker 启动，需要操作员重新加载或重启服务。
front_loopback 启动失败后的退休清理分支具有相同断链。

## 关联设计与当前契约

supervisor 尚无独立集中 spec；依据现有 Readiness 状态、进程身份校验及恢复入口的生命周期约束修复。
`_terminate_failed_worker()` 必须成功确认退休，`recover_from_failed()` 才能清除 FAILED 并重新启动监督循环。
IPC 协议、依赖版本和对外 API 均保持原契约。

## 根因与修复决策

- 以内部 RuntimeError 子类 `WorkerExitUnconfirmed` 标识强制终止后的退出观察超时，保留原错误文本与异常基类兼容性。
- 健康故障退休和 front_loopback 启动清理遇到此类超时，复用 `_mark_restart_exhausted()` 与现有唯一后台恢复任务。
  使用已有 30 秒起始、300 秒上限的指数退避，并继续尊重崩溃窗口和禁用重启设置。
- 重试仍经 `recover_from_failed()` → `_terminate_failed_worker()` → `_shutdown_owned_worker()`，
  保留旧 PID、创建时间与进程句柄，重新检查身份并确认退出后才允许选举或启动替代 Worker。
  持续未确认退出时保持 FAILED，不重新连接不健康 Worker，不提前清除退出屏障。
- 身份错误、普通退休异常和权限拒绝不因本次改动变成自动重试；启动时的 WorkerIdentityError 也不能被清理超时覆盖为可重试错误。
- 不采用跳过退出确认或扩大单次等待预算的方式；这些方式分别可能产生重复 Worker，或继续在下一次超时后永久停止恢复。

## 回归证据与适用范围

比较基线：develop `dee1a566ec143c1e6550a63e5bca0964a873a94e`；releases/0.2.9 `547ffa1b56657943cd15421e0c63460e1887503e`。
环境为 Windows、Python 3.12、uv frozen 依赖及各自独立工作区；Core 使用各分支锁定版本，未替换本地开发源码。

- 原代码对照：同一组实际 reaper 超时用例，在 resident 健康退休、front_loopback 健康退休及启动清理三条路径均失败；原因均为没有后台自动恢复任务。
- 新增用例验证多次退出未确认时不启动替代 Worker，保留原身份，观察恢复后自动回到 AGENT_READY，并尊重 max_restarts=0。
- 真实进程用例使用生产启动、IPC、选举与退出检查，分别覆盖 resident 自建 Worker、重连已有 resident Worker、front_loopback Worker。
  仅注入第一次退出观察超时并缩短退避时间，随后检查原 PID 已退出、新 PID 就绪及 SESSION_CREATE 请求收发。
- 8 个相关测试文件完整回归：develop **264 passed, 2 skipped**；releases/0.2.9 **268 passed, 2 skipped**。新增用例每条分支均 9 项通过。
- 两项跳过分别要求原生 POSIX Unix socket 和 SIGTERM/SIGKILL 退出语义，Windows 未执行；运行数据保留在本地任务证据目录 `issue6709-retirement-retry-20261116/`。

复验命令：`uv run --frozen --no-sync pytest -o addopts= --asyncio-mode=auto -o log_cli=false -q -rs`，追加 `tests/unit_tests/agentserver/` 下以下文件：

## 防错模式与资料同步

退休失败必须区分“退出尚未确认”和“身份或权限不允许清理”。前者可退避重试，所有恢复入口仍必须先确认旧进程退出。
本次通过异常类型与行为测试约束这一边界，并更新 bugfix 及自动索引，不新增并行恢复实现。

English summary: retry unconfirmed Worker retirement through the existing bounded recovery loop.
Keep the old identity fenced until exit is confirmed; identity and permission failures remain non-retryable.
