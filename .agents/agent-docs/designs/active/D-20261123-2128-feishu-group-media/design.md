# 飞书群聊 AI 同事图片理解与问答首发方案

## 用户体验与发布边界

用户在飞书群里发一张截图并问“红框里的按钮做什么”，AI 同事应结合问题和截图，先指出按钮的文字、位置或图标，再解释画面能支持的判断。涉及插件是否自动注册等后台行为时，应说明仅凭截图能确认到哪一步。

首发处理触发本次任务的飞书群消息，覆盖独立图片、图文混排和同一帖子里的多张图。沿用同事已有的群响应策略。纯图消息若已触发任务但没有明确问题，可先简述图中内容并询问用户关注点。历史消息追图、私聊和视频处理另行规划。

## 最小改动

当前网关记录了附件引用，[执行入口](../../../../../jiuwenswarm/server/jiuwenmate/execution_driver.py)会在任务开始时刷新触发消息，但图片引用不能直接用于识图。AI 同事已有[图片问答与 OCR 工具](../../../../../jiuwenswarm/server/jiuwenmate/media/vision_runtime.py)，且在[执行时挂载](../../../../../jiuwenswarm/server/jiuwenmate/bash_runtime.py)。首发补齐从飞书引用到视觉工具可读输入的环节，沿用现有模型回复和飞书回帖流程。

1. **解析原消息。** 在刷新触发消息、确认可读后，使用当前同事绑定的飞书机器人身份，按应用、群和消息 ID 获取原消息。仅接受独立图片或富文本图片节点的 image key，并与已登记附件匹配。按帖子顺序编号，同一 key 只下载一次。可参考[现有飞书资源下载与来源校验](../../../../../jiuwenswarm/server/jiuwenmate/cli_group_sharing.py)。
2. **准备图片。** 在下载时限制字节数和耗时，校验实际图片格式及解码像素数。文件写入本次执行专属的临时目录，以系统生成的名称原子落盘。视觉调用前复核消息仍可读，将工具可访问的入站图片限制到本次执行；当前工具以整个办公空间为路径边界，仅新建子目录不足以隔离其他群的图片。任务结束、失败或取消时清理文件，异常退出后的残留按期限回收。
3. **理解并回答。** 将原问题和对应图片路径交给已有的 visual_question_answering。提取界面文字时可使用 image_ocr。多图逐张带编号提问，再按原顺序综合结果。工具成功读取后才能描述画面；局部模糊时指出看不清的位置，一张图读取失败时仍可回答其他图，并标明缺失的图号。
4. **失败与恢复。** 区分机器人无读取权限、图片超限或损坏、视觉模型未配置、视觉服务超时。向用户给出与原因匹配的提示，例如无权限时提示检查机器人资源权限。任务重试时重新核对来源及撤回状态，复用已有回复去重机制。

## 通用执行范围与停止

渠道负责核对原消息和下载附件；通用媒体模块只负责把本次输入引用、当前会话输出映射到工具可读文件，不引用 Issue 修复业务。渠道下载保存在普通办公空间以外的私有缓存，来源记录只包含版本和附件 key，不复制群聊正文。

视觉工具允许当前已授权入站图片及当前会话 output 图片，拒绝其他会话文件和任意网络地址。当前会话输出在权限暂停或服务重启后仍可使用，不通过额外持久化授权表追踪每次执行的文件时间。现有 WeLink 已接收媒体仅开放当前消息对应目录；后续渠道通过适配器提供引用解析与资源关闭接口。

下载阶段作为既有执行控制句柄持有的子任务，停止或取消时等待其清理，再终止本次请求。沿用页面发送按钮切换出的停止按钮，不增加飞书停止命令。远端已经接受的模型请求无法保证追撤。

## 配置、排期与风险

部署前在现有多模态模型页面保存支持图片的模型，并在智能体工具中开启图片处理。AI 同事使用同一配置；只有尚无统一目录的旧部署兼容 VISION 环境变量。先在一个已授权测试群验证机器人自身能下载独立图片和富文本内嵌图，再开展接线。

| 工作项 | 估算 | 完成标志 |
| --- | ---: | --- |
| 身份与资源读取验证 | 0.5–1 人日 | 用绑定机器人身份取回两类消息中的原图 |
| 下载、隔离和视觉问答接线 | 1–1.5 人日 | 图文任务能按原问题调用视觉工具，失败有明确反馈 |
| 定向回归与真实群验收 | 1–1.5 人日 | 通过下列场景，确认回复回到原群 |
| **合计** | **2.5–4 人日** | 含一次真实租户联调 |

估算按一名熟悉项目的开发者、已有可用视觉模型及测试租户计算，租户审批等待时间另计。若 AgentServer 无法以正确的机器人身份下载，改由 agent-gateway 获取资源并通过受控接口交付，预计额外增加 1.5–3 人日。

## 上线验收

| 真实或模拟场景 | 通过条件 |
| --- | --- |
| 真实群内发送截图，在红框内放入正文没有的随机文字 | 回复能读出文字，并说明它位于哪个控件 |
| 图片中放置不同形状或颜色，提问两者的位置关系 | 回复正确描述相对位置，证明能理解画面而非只做 OCR |
| 富文本消息含两张不同截图，要求比较变化 | 按图一、图二指出实际差异，原问题与图片顺序匹配 |
| 消息撤回或尝试读取其他群的图片 | 权限校验阻止读取，视觉请求不包含该图 |
| 无权限、模型未配置、图片损坏或超限 | 给出对应原因，不编造图片内容；临时文件得到清理 |
| 普通文字消息、未触发的群图片、执行重试 | 文字回复正常，未触发时不下载，重试不重复回帖 |

建议先在测试群通过截图识字和非文字画面理解两项，再向已配置视觉能力的同事开放。若联调失败，关闭新增的飞书入站图片处理入口，保留原有群文字回复和其他渠道的视觉能力。本文为首发设计草案，验收结果在实施后记录。
