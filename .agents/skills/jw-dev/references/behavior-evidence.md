# 行为验证与证据适用范围

按实际差异选择能暴露回归的最小充分证据；不要求每次改动执行所有测试层级，也不为低影响修改机械新增测试。
本参考供开发、检视和转测使用，不新增执行外部服务、真实模型、提交或静态检查的权限。

## 证据对应实际行为

| 变更面 | 应观察的证据 | 不能单独证明什么 |
|---|---|---|
| prompt、工具 schema/描述、结果或诊断 | 模型实际收到的消息、工具声明和渲染结果；稳定内容可对比，动态状态按语义核对 | 源码字符串或日志中的中间变量不证明最终请求内容。 |
| 公共 API、协议、模式或渠道 | 实际消费入口的请求/响应、事件顺序、状态与错误；涉及旧消费者时覆盖兼容路径 | 直接调用内部 helper 不证明注册、装配和真实入口可用。 |
| 文件、数据库、进程、工具副作用 | 独立读取最终文件/记录、等待进程结束、检查权限/清理与残留状态 | 模型声称完成、工具返回 success 或收到 ACK 不证明外部效果。 |
| 生命周期与不变量 | 所属组件可观察的事件/可变状态关系；相关非法状态通过真实检查入口触发预期失败 | 方法存在、对象已保存或固定正常示例不证明约束会生效。 |
| 发布资源、插件/provider、可选依赖 | 改动影响到的实际加载/安装包/子进程路径及缺依赖行为 | 源码环境中的手工挂载不证明发布入口正确。 |

观察范围由变更决定：不要求无关模式、渠道、平台或 provider 全部重测。
不变量需要负向证据时，非法用例应在预期边界因预期原因失败，不能以缺依赖、初始化错误等偶然失败代替。
单次故障不自动证明所有类似实现都有同一问题。

## 回放与快照

已有录制会话、协议 fixtures 或快照适用时优先复用；不能自动生成预期再据此宣称行为正确。
没有现成回放设施时，先用真实组装入口的行为测试、可控模型替身或授权的最小复现取得证据，
明确未覆盖的模型/外部环境，不为每次改动搭建全仓回放系统。

- 场景从受影响的实际入口进入，不新增仅供测试绕过注册、装配、权限或生命周期的隐藏入口。
- 会话输入、记录和预期输出有明确维护位置；共享 fixtures 的读者一并核对，避免一方刷新破坏另一方语义。
- 归一化只消除已确认的时间、临时路径和随机 ID，保留身份关联、顺序及真实错误；不吞掉用户/模型/工具正文中的差异。
- 副作用预期必须独立于被测输出；刷新会话快照不能顺带把实际工件复制成“预期正确工件”。
- 逐项检视预期 diff，区分有意变化与回归；报告模拟模型回放、真实服务测试各自证明的范围。
- 记录中涉及凭证、环境或真实用户数据先脱敏；证据中不收集不必要的敏感原文。

## 上下文与覆盖口径

资料新鲜度、事实/推断、跨边界状态权威和覆盖层级按 [因果流程与资料可信度](context-and-flows.md) 核对。
源文件或符号指纹未变化只能证明相应片段未变，不能证明调用方、配置、协议、依赖或环境未变。
已盘点、已理解、已检视与已验证分开报告；不要把文档覆盖率当成行为正确率。

## 版本、有效范围与重验

在已有 feature/bugfix/转测记录中记录证据，不另造台账：

- 对应的候选版本或可复现工作区差异、比较基线、实际入口、命令/步骤和记录路径。
- 环境、依赖及配置；需要时区分锁定依赖与本地 editable、源码与安装包、模拟与真实服务。
- 可观察预期、实际结果、覆盖范围及未执行/跳过/失败/阻塞项。
- 哪些后续变化会影响结论，例如候选差异、依赖版本、装配配置、协议/fixture 或执行环境改变。

证据所依赖的代码、配置和环境未变时可继续引用，不因 commit/push 本身重复已经通过的验证。
候选或基线更新后先判断影响，再重验被改变的前提与消费者；rebase 后即使 diff 类似也不能未经核对沿用旧结果。
没有核实新版本适用性时记为待重验，不能写成当前版本通过。失败在修复后重跑受影响范围。
CI 的候选 SHA 与本地证据分开记录；定向测试不能覆盖已有更高层失败，全量/平台结论来自实际对应结果。
