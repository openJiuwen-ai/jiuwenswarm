# 上下文可信度、因果流程与局部同步

本参考供设计、开发、检视和转测按需读取，吸收项目维护资料的导航与影响分析方法。
复用已有 AGENTS、spec/协议、design、feature、bugfix 与模块文档；不要求建立全仓知识库、逐符号卡片或审计台账。

## 选择上下文并核实新鲜度

1. 从本次路径和用户目标选择所属模块、实际入口、相关协议、已有决策、调用方和消费者。
   模块用于理解职责，目录用于定位证据，跨边界流程用于解释因果，关键符号用于核对执行细节；不逐文件机械建档。
2. 若存在项目地图、manifest 或历史分析资料，只读取关联部分作为导航，核对来源版本、维护日期与当前路径/符号。
   不把整个知识库标记为 current 或 partial 的状态直接套到本次任务，也不要求先补齐无关覆盖。
3. 与候选/基线差异、当前调用者、协议/配置和依赖对照；资料日期较新或符号指纹未变都不证明其仍适用。
   同一函数未变时，上游输入、下游消费者、环境或装配可能已改变，仍须核对受影响关系。
4. 找不到资料或关联内容已过时时，从实际源码、类型、注册/装配、测试和运行证据继续定位。
   明确依据缺口，不把初始化知识库或全仓分析作为普通修复的前置条件。

历史资料帮助发现入口和问题，不自动成为本次预期行为的权威来源；确认设计、当前规约和实现证据各自说明职责。
资料显示的旧风险、统计和健康分数均需核实后才能用于当前结论。

## 区分事实、推断与缺口

在现有依据清单或正文中，用短句标出关键结论的可信程度，不要求给所有文档加新字段：

- **已证实**：给出对应版本、路径/条款、代码或运行证据，并限定它真正证明的范围。
  读取实现可证实某个分支存在，不能据此宣称测试已运行或跨端实际生效。
- **推断**：说明推断依据、缺少的环节和什么证据可确认它；不能仅凭目录名、注释或文档引用升级为事实。
- **待核实**：指出未追通的边界、缺少的源码/环境或冲突资料，说明对方案或结论的影响。

同一段路径可以已定位而行为仍待核实；模拟验证、源码核对与真实环境结果不能用一个“已确认”混在一起。
发现冲突先区分既存文档漂移、当前实现缺陷与有意契约变化；不盲从旧资料，也不以候选实现自证正确。

## 追踪跨边界因果流程

涉及模块、运行时、进程、协议、持久化或 UI 边界，并影响用户输出、长期状态或外部副作用时，
围绕一个具体结果追踪下列关系。小改动可用简短链路或条目；复杂变化在已有设计/spec/feature 的归属位置补流程图或表，不另存重复全貌。

- **结果与起点**：最终用户/模型/系统依赖什么结果？谁产生输入、事件、状态或工件？
- **边界与载体**：哪些组件/进程/协议参与？参数、消息、事件、文件格式和身份如何传递？
- **状态权威**：谁拥有可写状态及生命周期？区分权威存储、缓存、派生投影、遥测/调试记录、测试 fixture 和临时状态；不能因同一事实出现多次就认为都是事实源。
- **消费与重建**：谁读取状态并生成最终输出？何时提交/发布？恢复、重放、分页、hydration 或缓存刷新如何重建它？只追踪与本次变化有关的机制。
- **失败与终态**：错误、取消、重试、排序、去重、幂等和清理由谁负责？迟到事件、部分成功及结果未知怎样影响外部可见结果？
- **证据与断点**：关键入口、符号、协议条款和现有验证是什么？哪一段尚未追通，会影响什么判断？

仅发现 producer 和 renderer 不等于已理解中间持久化或恢复路径；不能用函数调用列表代替状态与副作用的因果解释。
不要求逐 helper 展开；按本次风险核对必要关系，不扩成无关子系统审计。

## 覆盖层级与未完成范围

在已有交接或验证结论中分别报告以下维度，彼此不替代，也不作为必须逐级建档的状态机：

| 维度 | 它说明什么 | 需要保留的限制 |
|---|---|---|
| 已盘点 | 已定位相关路径、模块、符号和消费者 | 被列出不代表实现已读或理解完整。 |
| 已理解 | 已读通相关行为、契约与因果关系 | 读通一段不代表全部模式、失败路径或消费者已覆盖。 |
| 已检视 | 已对明确候选相对基线的差异提出并核对判断 | 结论只覆盖实际审查范围，不是全仓健康审计。 |
| 已验证 | 执行了匹配版本和环境的测试/复现，取得可观察结果 | 仅证明实际场景；未运行、跳过和环境受限单列。 |

按本次范围说明已覆盖、待核实/待重验、明确排除项及理由。简单任务可一句话说明，不制造完整性百分比或全仓健康分数。
对关键未覆盖项给出精确下一步：入口/模块/关系、所缺证据及其影响；列出了所有缺口仍不表示已完成覆盖。

## 验证后局部同步

开发中记录本次证实过时的资料；实现和验证后，核对相关路径、接口、状态、消费者、恢复及验证入口是否需要同步。

- 当前规则与契约更新所属 AGENTS/spec/协议；实施与证据更新 feature，故障因果留在 bugfix。
- 已有项目地图、模块/流程资料实际涉及本次变化时，更新其关联部分和必要入链；不全库重建，不为一次文档同步新增 CHG/ADR。
- 历史设计、当时失败与测试结果保持其历史语义，后续修订写明原因与当前维护位置，遵循 [决策关系](../../jw-design/references/decision-records.md)。
- 不存在知识库时不创建它；文档整理不扩展代码或 Git 授权，检视阶段仍只报告同步缺口，交给开发处理。
- 本次应同步的关联资料未能更新时，分别报告代码/验证状态与资料缺口、影响范围和后续入口，不将整仓标成最新，也不把无关历史欠账变成本次阻塞。

资料同步不替代重新验证，更新文档不会让原失效证据自动变成有效；证据适用范围遵循 [行为证据](behavior-evidence.md)。
