实施范围与行为变化

阶段二：执行和事件记录归 Worker；传输断开仅解除连接订阅，原任务继续。新增独立 dispatch_id、授权范围内 request_id 去重、带序号事件与状态快照、有界流式保留、待答交互恢复、warming 排队取消。Front 真正向 Gateway 发送关键响应后才回传交付确认，发送失败或确认超时走原有 abort。Session metadata 使用现有资源锁及生命周期栅栏读取最新字段并合并，避免 Worker 的旧缓存覆盖 Front 修改。实际数据根目录及 profile 决定 Worker，user_id 只作授权/路由。普通重启 detach；最终退出通过显式控制权在统一 30 秒预算内排空和保存。

阶段三：新增 ResourceKernel / ResourceLease，复用模型连接、不可变 Rail 配方与工具定义、Skill 快照、MCP 连接和项目 LSP。共享键包含可信数据归属、项目、模式、Agent 定义、能力、配置、模型或路由及不透明凭据引用。正在使用的资源在配置变化后延迟释放；新的执行获取新资源。Rail 实例、可变工具、ModelGroup 路由状态保留具体 Agent 所有权。现有 RuntimeSessionCoordinator 及 execution handle 继续负责历史、checkpoint、取消和活动执行；RunContext 隔离 max_turns、预算、权限、host tools 和本次认证上下文，避免复用 adapter 时泄漏。warm pool 的 claim / pin 和 Session 资源租约保留。

阶段四：延后 Agent/工具 barrel 导入，缩短 Front 日志配置读取；迁移、模型身份和路由按依赖顺序准备。PersonalContext、Proactive、图像探测、Zen、Sandbox 等可选能力后台或首次调用准备；对应调用等待自身能力。Worker 复用项目 LSP 和 MCP，Worker 生命周期管理 KVCache。修复 Windows named pipe 存活判断、源程序/冻结程序的 Worker 参数转发，以及 Python / Electron 桌面版普通重启与最终退出的区别。Web 自动查询并恢复原执行游标与交互，过期游标走历史和快照，不重发输入。

最后一项性能修复只调整现有 Windows metadata 资源锁的等待方式：用 5 ms 的非阻塞重试保留原 10 秒上限，消除 CRT 锁重试带来的约 1 秒台阶。修复前已有 Worker P95 超过 2 秒；最终完整样本复测已恢复到 160 ms 内。

未引入多 Worker 调度或 WarmSpare。Process CLI 保持本地子进程 Runtime；远程 TUI 保持 Gateway /tui → TUI Channel → AgentServer。未修改 uv.lock、pyproject.toml 或 agent-core；未修复本次范围之外的 Windows 既有失败。全部改动文件及范围分类可逐项审查。

生命周期与故障结论

Front/Gateway 重启、待答交互接回、离线完成、排队、steer、取消、跨会话消息、Worker 崩溃、最终退出均运行于实际子进程。崩溃后的新实例返回 interrupted，未自动重放输入或不确定工具。AgentOS 两个不同数据目录使用相同 session/request/user ID，Worker PID/实例不同、工具分别仅执行一次；这验证数据目录/profile 隔离，完整 AgentOS 部署认证链另由现有回归覆盖。

创建事务故障测试拦截一次 Front 的实际业务发送，记录 Worker 调用真实 AgentRuntime.abort_session_provision，结果 aborted 且无 commit。按既有 create_token 重试契约保留 prepared Session metadata；这里不声称已经删除全部目录。归档、删除、切换及资源栅栏由 Session 广泛回归验证，本次没有对这些操作全部进行故障注入的原生进程矩阵。

正常最终退出用显式 shutdown helper 验证，保存并释放后实际 Worker PID 消失。warming 中关闭约 6.6 秒，其余已记录场景均在 30 秒预算内。无法完成的步骤会记录，超时可强制退出；硬件卡死和不可中断底层调用并未作穷尽验证。
